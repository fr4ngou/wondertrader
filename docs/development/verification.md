# 验证与证据规范

正在运行或已绑定摘要的安装目录由运行owner独占维护。审查与临时验证使用独立安装；只读导入也使用`-I -B`或独立缓存根，避免默认字节码缓存改变被核安装。目录差异须核清新增文件与原源码身份，保留实际失败及证据，安装校验保持原规则。

数据/策略主路径验证覆盖实际消费者的必需字段、逐角色非空覆盖、知晓时间和信号/不交易原因。合法空值及正常返回仍核业务影响；其他角色有成交或报告可生成时，也核依赖不同的分支。运行故障检查持久日志、失败状态及源请求，确认实际落盘与首错可定位后再判断无异常。

类型：长期规范。适用范围：开发验证、评审、运行资格和发布验收。

## 按影响选择验证

| 变化 | 必要验证 |
|---|---|
| 文档或注释 | 链接/索引、术语、源码依据、行为说明与任务范围 |
| 纯计算与数据转换 | 可人工核算样本、精度/单位、边界值、异常输入 |
| 公共接口与接入 | 生产者/消费者契约、版本、错误、线程与生命周期 |
| 状态、持久化、交易副作用 | 重复/乱序、重启、持久化前后失败窗口、未知结果和恢复 |
| 并发与容量 | 竞争、背压、满额、取消、超时、退出与资源释放 |
| 回测与策略 | 冻结输入、时钟、预热、未来数据、交易规则及模型限制 |
| 用户入口与部署 | 正常、空、异常、恢复、核心数据、关键操作和实际部署身份 |

修复的回归验证重现原根因条件，并核对受影响链路。可复现缺陷验证修复前失败、修复后通过；已失去原环境或输入时，记录替代复现的依据与证明限制。测试断言可观察业务结果，不依赖对实现步骤的机械复制。低影响可逆修改按实际风险检查，避免无收益的测试膨胀。

测试分层、原生入口及系统 E2E 场景见[测试手册](../runbooks/testing.md)。测试代码存在、测试框架名称和模拟组件存在分别记录，实际通过结论由对应运行及断言证明。

日常合入使用[本地CI](../runbooks/local-ci.md)，将适用检查、日志、源码内容及master基线关联到同次结果。CI成功证明已登记阶段在对应输入上通过；完整策略、真实柜台、浏览器及发布后验真按各自实际链路登记。测试源码存在、阶段执行和线上业务生效保持分别可核实。

## 性能与增长验证

适用于交易、策略调度、行情消费、回报、恢复及会周期性累积读写的路径。按改动影响选择下面的对照，用已有业务截止或目标验收，性能样本沿[证据模板](../evidence/TEMPLATE.md)留档。

| 对照 | 输入怎样固定 | 看什么 |
|---|---|---|
| 历史增长 | 固定新回报批次和活跃订单数，只增加累计历史。另单独提高同日回报量，再叠加两者 | 各环节读取/扫描行数、SQL 计划、写入次数和字节、批次时延、启动与重放耗时 |
| 重复和变化 | 同一业务事实换查询编号反复送入，再分别加入真实状态变化、后到费用或归属、冲突和重启重放 | 重复时检查收件、证据和账本的增长。真实变化及时入账，冲突及未决责任有证据 |
| 存储和竞争 | 同一代码、输入和数据库副本对照实际部署卷及候选卷。按影响加入并发查询、checkpoint、慢盘、磁盘写入失败或空间不足 | 端到端和排队、锁、校验、提交、后台合并各段耗时，记录 p50/p95/p99、最大值和样本量。核对重试后的连续性及资源回收 |

分账类改动已有 1 千、1 万、10 万条及叠加场景作为比较档位。其他路径按实际增长速度、保留周期和预计运行窗口选档，说明样本规模及其与生产的关系。低频操作可记录逐次耗时和最大值。无法在实盘重现时，用等价卷或副本测试并记录差异。合成磁盘探针衡量 I/O 本身，完整调用链另测查询、队列、事务和确认。

每次核验记录各阶段的处理量与累计量。对后台任务，观察积压深度、最老任务年龄和恢复速度。对数据库和日志，观察每新增一个真实业务事实增加的记录或字节、剩余空间和保留周期。增长或时延超出预期时，沿原身份查具体慢点并登记处理责任。评审先核操作次数是否随历史失控，再用同环境耗时判断业务影响。资源指标用于诊断和容量规划，交易准入沿既有业务规则。

WT 的实际例子是 61 个成交编号产生 84,421 条查询收件。单笔成交的金额对得上，仍可能随查询次数堆积。开发和评审应从回报接收与去重，继续核对账本提交、策略读状态、重启待处理回放以及观衡分页。分别确认一次处理只访问必要记录，找出历史增长最先拖慢的环节。相同回报新增记录数、扫描范围和分页边界等可稳定断言的条件，沿现有回归自动检查。D/E 盘对照及已定位写点见[写入排查](../migration/wt-private-persistence-migration.md#已定位的重复写入)。

## 规则自动检查

对重要、稳定且可自动判定的约束，优先复用现有工具建立检查并接入日常验证，覆盖禁止的跨层依赖、循环依赖、公共接口兼容性及高频缺陷。模块依赖规则以模块说明为依据；检查用明确的符合与违反样例核对有效性，并记录实际入口、覆盖范围和限制。

尚未建立的自动检查登记为待建立，当前约束通过人工评审核对。工具引入按实际语言、风险和维护收益选择。架构测试做法参考 [ArchUnit 官方手册](https://www.archunit.org/userguide/html/000_Index.html)的包依赖、分层与循环依赖检查（Java 示例；核对日期：2026-11-07）。

## 副作用与恢复

隔离环境使用能独立记录实际副作用的替身，区分“请求可能已执行”与“有证据确认未执行”。在消息收发、持久受理、原生调用、结果保存和回报确认前后注入适用故障，核对实际调用数和事实连续性。

测试工具、模拟账户、服务商测试环境和真实账户分别登记。真实交易及权限变化以明确授权覆盖的账户、动作、范围和停止条件执行。

## 证据有效性

记录源码身份（有未提交差异时含文件摘要）、规格、依赖、数据、配置、环境和命令/步骤。标明退出码、实际观察、通过/失败/未执行以及限制。

只复用输入仍匹配的既有证据，并说明适用范围；新增变化、失败或未解决疑点才扩大或重复验证。编译、单测、契约、实际终端及生产用户入口各自证明对应层级。

本地文档工具检查只覆盖其声明的静态范围。构建成功、进程健康和路由返回分别作为中间证据，功能完成还需对应业务调用链正常。

## 私有资料与工具输出

含私有配置的生成脚本、启动入口、日志和命令行整体按私有制品处理。诊断先定义允许输出的字段名、类型、枚举或去敏计数，再在读取侧构造新对象输出。提取生成脚本字段采用静态读取与结构解析，避免执行或import入口产生服务、环境或凭证副作用。源码与配置在同一行时，按行匹配仍可能携带完整凭证；文件过滤、长度截断或调用标题不能替代结构化白名单。未知字段和值保留在受控运行环境，工具结果及会话记录同样属于信息输出边界。

认证资料误输出时立即停止该读取方式，通知维护者并登记字段级影响、记录位置及传播动作；丢弃已知私有内存引用。后续不复述值、不复制原文、不通过再次打印验证是否泄漏。凭证轮换、撤销、重新配对及运行服务变更沿明确授权处理；工具记录的已发生暴露与本地文件清理分别说明。

## 审查与交付

审查围绕最终规格及源码身份，记录发现、严重程度、处理和复验结果。任务完成报告说明实际行为、验证结果和未覆盖范围；详情使用[证据模板](../evidence/TEMPLATE.md)保存。
