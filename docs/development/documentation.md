# 文档规范

类型：长期规范。适用范围：规范、架构、模块、规格、手册、任务及验证记录。

## 信息分层与唯一正文

| 信息 | 位置 | 更新时机 |
|---|---|---|
| 长期产品目标 | `docs/product/` | 产品范围变化 |
| 职责、执行链与长期决策 | `docs/architecture/` | 架构或事实所有权变化 |
| 模块接口、状态与依赖 | `docs/modules/` | 模块边界或运行契约变化 |
| 通用开发与运维规则 | `docs/development/`、规范性 runbook | 工作方法变化 |
| 单项功能要求与验收 | `docs/specs/` | 需求或方案变化 |
| 环境命令与操作步骤 | `docs/runbooks/` | 工具链或部署方式变化 |
| 当前事实与活动任务 | `docs/roadmap/` | 状态或续接点变化 |
| 验证、发布与故障记录 | `docs/evidence/`、`docs/releases/`、`docs/incidents/` | 对应事件发生 |

同一要求维护一个权威正文，其他位置使用链接。长期规则以整个系统的稳定职责与工作方法为范围；单次开发的选择、临时限制、对话过程、机器路径和进度保存在规格、环境或任务记录。源码入口、运行事实和已验能力分开标注。

## 文档要求

正文说明类型、适用范围和状态。要求使用可观察、可验证语言；区分已确认要求、提案、观察和缺失证据。术语、字段和状态沿已有定义，示例明确标识。

仓库内链接使用相对路径，源码符号配可定位入口。外部引用标明来源和适用版本/日期，关键结论由实际依据支撑。

标准与模板保留长期结构，具体任务填写实例。计划只写目标、根因假设、关键决策、步骤和验收；调试日志、命令重试和临时分析留在 `.tmp/` 或专门工作记录。

## 文档变更与索引维护

文档变更的实施者负责同步维护所属索引、上层导航和引用，文档与导航修改放在同一提交中。按下表处理文档生命周期；完成时人工核对从 `docs/README.md` 到正文的实际阅读路径。

| 操作 | 同步维护内容 |
|---|---|
| 新增 | 将正文加入所属索引；新增目录索引时，将该索引接入上层导航，保证从总入口可达 |
| 删除 | 按历史记录保留规则确认可删除范围；同步移除索引条目，逐一更新引用到有效的后继正文，或删除已经失效的引用和说明 |
| 移动或重命名 | 更新所属索引、所有引用旧路径的文档和正文内受位置变化影响的相对链接；跨目录移动时同步调整原目录与目标目录索引 |
| 合并、拆分或替代 | 明确各部分的权威正文及适用范围，更新索引和相关引用；历史记录保留原身份并关联后继结论 |

目录内 README 已列出子文档时，仍需确认该 README 本身连接到上层入口。检索引用时同时核对 Markdown 链接和正文中的路径、命令；目录整体移动时核对受影响的全部文档。共享索引按提交前的最新内容整合，保留其他任务已成立的条目。

## 状态与证据

规格使用 `proposed / accepted / superseded`，任务使用开发流程定义的状态。完成结论链接到与输入匹配的证据。证据说明代码、依赖、数据、配置、环境、命令/步骤、实际结果和未覆盖范围。

既有证据和故障记录通过追加更正关联后继结论；历史观察保留当时语义。实现偏离规格时先确认需求与实际行为的差异，再修正责任层。

任务分支中的未合入记录可随最终候选修订；记录进入正式主干后，验证、故障、发布和已生效 ADR 的历史正文冻结，新增后继更正并更新索引。规格维护当前行为，历史实例保留当时身份与结论。提交前重读共享索引及状态快照，保留其他任务已成立的结果。

## 检查

执行 `python -B scripts/project.py check` 检查配置所列文档的本地链接、索引可达性与项目技能清单。人工核对事实来源、职责一致性及规范是否夹带任务信息。静态检查不验证外部网页、标题锚点、应用构建或运行结果。

生成器仅用于初次接入；后续通过项目自己的文档和维护工具演进，保留上游说明和许可证。
