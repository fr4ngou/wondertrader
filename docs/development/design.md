# 方案规范

类型：长期规范。适用范围：功能设计、结构调整、协议与状态变化及技术决策。

## 方案深度

小型修改在原规格的适用要求中说明预期行为、影响和验证；跨模块、新接口、状态或副作用变化使用[规格模板](../specs/TEMPLATE.md)。长期职责、事实归属、权限及恢复原则变化同时登记 ADR。

对可核实的事实先调查源码、接口、测试和部署说明。未知项写出缺失内容、影响、所有者与下一核实动作；只有阻断实现的必要决策才请求补充。

设计必须引用[原生能力目录](wondertrader-capabilities.md)中的对应能力，按[复用规则](wondertrader-reuse.md)列出原生接缝、配置条件、实际缺口和重合旧实现退出项。WonderTrader已提供的能力采用原生实现；相关能力未核实时先调查和写明边界，再开发。

## 必须回答的问题

1. 用户需要什么可观察结果，需求由谁确认，涉及哪些现有流程？
2. 模块位于完整调用链哪里，谁拥有输入、状态、配置、权限和结果？
3. 现有实现能否承担该能力，新增实现的缺口、代价和退出旧实现的条件是什么？
4. 主流程、状态变化、异常、取消、超时及重启恢复如何推进？
5. 接口、字段、时间、单位、版本、容量与外部依赖如何约束？
6. 正常、失败、恢复及兼容性如何验证，何时允许发布和回滚？
7. 涉及框架行为适配时，[配置分流](upstream.md#框架行为的配置分流)的键、默认原生路径、显式适配路径、选择时机及双路径验收分别是什么？

## 契约与决策

稳定要求使用功能前缀和连续 ID，逐项对应验证入口。需求变更修订原要求并保留变更依据，避免多份互相冲突的最终方案。

跨模块先冻结输入/输出、身份、错误、副作用、状态所有者和兼容规则，再修改生产者及消费者。将连接、受理、持久确认、外部结果和业务就绪分别定义。

可变事实指向唯一配置来源；方案可写约束和估算依据，真实部署值由环境记录维护。影响资源、费用、权限、数据保留或恢复时，明确预算、负责人和停止条件。

## 验收与生效

方案完成需具备完整调用链、明确所有者、可执行验收和已登记未知项。`accepted` 表示需求及设计获确认；实现、资格验收和生产生效分别通过各自证据确认。

实现中发现边界变化，先同步适用规格/ADR再修改相关调用方。临时探索与被放弃方案保存在研究或任务记录，长期规范维护稳定方法。
