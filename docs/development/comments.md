# 注释规范

类型：长期规范。适用范围：源码注释、公共接口说明和配置字段说明。

## 内容与位置

注释说明设计原因、约束、职责边界和容易误用的行为。代码直接表达的逐句动作交由命名和结构说明。注释放在对应声明或关键决策旁，随实现同步维护。

| 位置 | 应说明的内容 |
|---|---|
| 公共接口/导出入口 | 能力、参数单位、返回/异步完成、错误、副作用、线程和对象生命周期 |
| 状态转换与恢复 | 不变量、推进条件、持久边界、重复与未知结果的处理原因 |
| 并发与资源代码 | 谁拥有对象、持锁范围、回调线程、释放顺序和重入条件 |
| 时间/数量/价格转换 | 时区、交易日、精度、舍入、累计或增量含义 |
| 配置与协议字段 | 含义、范围、默认值来源、生效方式、兼容性及敏感程度 |
| 测试中的故障场景 | 原触发条件、模拟的失败窗口及所保护的业务结果 |

公共模型新增或改变字段时，同步说明定义、缺失/零值语义、来源时点、消费者和与相近字段的区别。回归样本使用能区分业务口径的真实形态，避免所有字段取相同数值而掩盖混用错误。

## 结构体与字段

自有代码中新增或修改的结构体、数据类、DTO及协议对象，每个字段都在声明旁写中文注释。字段注释说明业务含义；涉及金额、数量、价格、比例或时间时写清单位、精度与时区；涉及外部事实时写清来源及来源时点；允许缺失时说明缺失、零值和未知的区别。对象或缓冲区字段还需说明所有者、有效期和释放责任。

类型名称和字段名不能替代上述业务说明。多个字段共享单位、来源或生命周期时，可在类型注释中统一说明，再在各字段旁写清各自含义及差异。复杂约束链接所属接口或协议正文，代码旁保留使用该字段所需的说明。

上游原有定义沿原许可证和维护规则保留，自有适配模型按本节补齐字段契约。修改涉及的现有类型同步补注释；全仓历史清理单独安排。

## 表达与维护

- 新增业务说明使用清晰中文；符号、协议字段和 SDK 名称保留原文。公共接口可沿目录既有 Doxygen 格式。
- 描述可验证事实，解释约束理由。历史、讨论和完整方案链接到对应文档；代码中保留理解当前行为所需的最小上下文。
- `TODO`/`FIXME` 包含可追踪事项、实际缺口与完成条件。已失效说明随逻辑一起删除，保留的折中记录来源与适用条件。
- 注释示例使用虚构值，明确示例身份。账户、凭证、机器路径和当前故障进度保留在适当的受控记录。
- 参数已通过类型和命名完整表达时省略重复标签；复杂契约通过接口文档集中说明。

## 示例

```cpp
// 回调对象仅在本次调用期间有效；跨线程处理前复制所需字段。
void on_quote(const QuoteView& quote);

// 只有持久确认才能释放待恢复记录，连接成功只更新连接状态。
void acknowledge(const DurableReceipt& receipt);
```

示例只演示说明方式，实际接口和术语以所属模块定义为准。
