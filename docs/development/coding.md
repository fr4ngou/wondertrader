# 代码规范

类型：长期规范。适用范围：源码、维护脚本、配置模型和自动化代码。

## 结构与接口

实现前完成[原生能力与复用核实](wondertrader-reuse.md)。与WonderTrader重合的能力使用其原模块，旧实现退出目标架构；业务特有规则只补原生不覆盖部分。原生能力未知不能作为新增重复实现的依据。

- 按事实所有权组织模块，公开接口围绕稳定业务能力定义；实现细节收敛在所属模块。
- 接口明确输入、输出、错误、时间语义、单位、有效范围和副作用；公共契约变化同步调用者。
- 业务规则只有一个实现来源。缓存和投影标识来源及重建方式，重复逻辑通过职责或接口收敛。
- 外部服务商细节放在适配器；依赖通过显式构造或接口注入，方便隔离测试与替换。
- 使用项目语言版本及相关目录既有风格。新 C++ 代码采用现有工程配置的标准，保持局部命名、缩进和括号风格；格式化范围限定在实际修改部分。

## 状态、错误与资源

- 状态命名表达业务阶段，转换定义条件、所有者和恢复依据；返回值、异步受理和最终结果分别建模。
- 外部输入在信任边界验证类型、长度、枚举、身份、单位和版本；协议/价格数值处理边界值及非有限值。
- 共享对象明确线程、同步方式和生命周期；使用 RAII 或语言提供的资源管理机制处理锁、句柄、连接和引用。
- 回调说明调用线程、对象可用期和重入限制。跨线程传递不可变值或具有明确所有权的对象。
- 队列、重试、等待、缓存和订阅有容量及截止时间。耗时操作放到适当工作线程，保留背压和取消语义。
- 异常在能够决定业务结果的层处理，保留原因与关联身份；副作用不明确时返回相应未知状态并进入核查流程。
- 金额、价格精度和舍入由业务契约指定。时间同时明确时区、时钟来源及交易日关系。

## 可用性与限制的职责

### 前端页面先设计后实现

新增或修改页面时，先给出可审看的设计图或交互原型，说明信息层级、主要操作、数据映射及桌面/窄屏布局。用户确认设计后，按已确认设计实现；已有明确设计授权时直接沿用。调整布局、交互或视觉方向时同步更新设计，避免在实现中随意叠加标签、说明和控件。

接口与来源核实可在设计期间进行。验收把实际页面与确认设计对照，并逐项核对核心数据、交互及加载、空、错误状态。设计示意数据和实际来源数据分别标明。

只读查询及页面展示遵循[只读查看与可用性](../product/brief.md#只读查看与可用性)。输入格式与来源能力在所属边界校验；测试证券、临时验证范围和策略证券集合各自保持用途。读取链按来源支持能力提供数据，交易授权状态由执行链处理。

资源容量在服务层通过分页、按需加载、排队、缓存和取消管理。默认值须覆盖实际主路径；限制附具体依据、实际影响及可继续方式。刷新异常保留同查询条件的成功数据并标明时间，局部依赖异常只影响对应字段和功能。

## 配置、依赖与日志

配置有唯一所有者、模式校验和生效边界；示例使用脱敏虚构值。凭证从受管配置注入，日志遵循最小必要字段原则。

依赖登记用途、来源、许可证、版本与适用平台。升级评估 ABI、数据格式及客户端兼容性；保留上游版权与修改说明。

日志以事件、原因、影响、关联 ID 和处理状态为核心。热点路径限制量与开销；面向用户的错误提供可理解的业务说明。注释规则见[注释规范](comments.md)。
