# 开发流程规范

类型：长期规范。适用范围：功能、修复、重构、依赖升级及配置行为变更。

## 入口与计划

1. 执行 `python -B scripts/project.py start`，查看工作树和相关规格，先按[WonderTrader能力目录](wondertrader-capabilities.md)及[复用规则](wondertrader-reuse.md)核实原生支持与边界，再沿模块入口核实完整调用链。
2. 明确预期结果、根因假设、事实所有者、影响范围、关键决策、步骤和验收标准。计划保留这些内容，调试尝试放临时记录。
3. 已确认需求直接实施；改变预期行为先更新原规格。职责、权限、事实所有权和恢复语义变化按[方案规范](design.md)形成适用决策。

## 主路径优先

1. 先实现整体模块的功能主路径，连接实际入口、生产者、消费者和存储，跑通可用的完整调用链。
2. 整体模块主路径完成后，集中处理边界情况、bad case和恢复验证。
3. 再进行代码评审、必要修正和交付检查。

开发中优先解决直接阻断主路径的问题。阶段进度以已可运行的功能和实际业务结果汇报；纯测试数量、局部契约和审查材料分别记录其范围。

当完整恢复或自动化显著扩大实现范围时，先交付职责完整、状态可核实的最小可用流程；列明适用条件和未覆盖能力，再按实际需要扩展。沿用已有入口、查询与状态管理，增加的持久状态和分支须对应明确的业务缺口。

## 实施

- 功能按可以验证的完整切片实现，保持接口、状态变化、消费者和错误语义一致。
- 修复先保留原触发条件，沿输入、状态及副作用定位根因，在责任层统一处理并清理失效重复逻辑。
- 重构明确保持的行为及验证方式；新旧实现并存时写明切换、观测和旧实现退出条件。
- 可变业务事实使用权威配置，协议常量集中定义。配置修改包含范围、默认值、权限、生效与恢复规则。
- 并行任务先明确公共契约和文件所有权；共享文件按最新快照合并，保留其他任务改动。
- 先检索现有实现和公开接口，再决定新增模块。新增持久化或跨层协调说明现有能力缺口、收益及运维成本。

## 验证与评审

按[主路径优先](#主路径优先)的顺序开展验证与评审，再按[验证规范](verification.md)覆盖正向、异常、恢复和受影响调用链。复用输入仍有效的证据，代码、环境或契约变化时重验受影响部分。

编写核验脚本前，读取实际公开接口、返回结构、缓存布局和已验证构建命令；脚本字段及路径须有源码或实际结果依据。同一组源码、依赖、配置和运行输入已有有效验收时，复用该结果；新增变更只重验受影响链路。每个完成的功能增量统一打包，避免相同输入反复构建、安装和全面回归。

送审资料包含最终规格、源码差异、验证入口、结果及限制。审查分别核对规格符合性、代码规范、事实所有者、异常恢复和职责完整性。涉及交易副作用、并发、状态持久化、权限或发布切换时，由独立审查者核对关键路径；审查结论关联实际源码身份。

发现问题先修正，再重验受影响条件。保留明确风险接受记录及相应权限，代码审查通过与运行资格分别登记。

审查范围记录为 full（首次或规格/公共契约/风险边界变化）、delta（同一要求内局部修复）、reuse（当前输入已有有效报告）或 none（适用规则未触发独立审查），逐项说明理由及代码身份。delta 由审查者确认全部适用要求的影响范围；历史通过结论按实际输入核实。

独立审查资料以最终规格、适用规则和源码为依据；任务过程、历史评语和开发者自评保存在独立记录。审查按要求给出 complete/gap/unknown、位置和证据，缺失行为证据明确列出。当前自动分类与收据校验能力以实际工具交付为准，文档中的流程要求不表示已有自动门禁。

## 完成与回写

任务状态使用 `planned → in-progress → pending-verification / done`。`done` 表示任务要求的验收全部满足；环境缺失、失败或关键入口未验收时记录 `pending-verification`、原因及下一步。

回写改变的规格、模块说明、运行手册和适用证据，更新 NOW/CURRENT；使用 `python -B scripts/project.py check` 验证本地文档完整性。功能交付以相应运行环境中的真实入口、核心数据、主要操作和异常状态验收为准。

汇报分别说明已开发、主路径已验收、已合入、已交付及已部署的范围，并列出尚缺的具体功能和下一动作。仍有功能缺口时按该缺口汇报，完成时间以实际进展为依据。

## Git 与交接

使用明确文件清单暂存和提交，提交前核对最新工作树、差异及敏感内容。保留上游许可证及来源。合并、推送、打标签、构建制品、部署和交易授权分别解释，依当前任务授权执行。

共享集成由明确的单一集成者执行，先核对最新基线及公共契约，再组合各任务结果。跟进上游与控制自有差异遵循[上游规范](upstream.md)，避免将框架升级与无关业务变化混在同一候选中。

交接说明最终行为、源码身份、验证依据、剩余风险和下一动作；临时尝试不写入长期规范。
