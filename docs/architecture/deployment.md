# 部署与运行身份

类型：系统部署设计。状态：proposed。范围：长期组件边界、发行单元及运行身份；实际环境支持见 CURRENT 和发布记录。

## 按运行条件部署

WT运行与观衡分别部署和启动，职责遵循[ADR-0016](adr/0016-independent-wt-runtime-and-observer.md)。WT运行发行单元拥有QMT Host、采集、历史服务、策略和交易执行；观衡只读消费这些服务。关闭、升级或故障退出观衡时，WT自动交易持续运行。共享发行介质只记录组合版本，运行进程之间不形成观衡托管WT的父子关系。实施要求及隔离验收见[独立运行规格](../specs/independent-wt-runtime.md)。

| 组件类别 | 部署形态 | 版本依据 |
|---|---|---|
| 原生策略/执行/接入组件 | 匹配 OS/架构的二进制包；桌面 SDK 按会话约束运行 | release ID、source/base commit、文件哈希、SDK/ABI |
| 数据准备与回测 | 原生包或经过验证的 Linux 容器，按数据/依赖能力选择 | 包哈希或镜像 digest、输入数据版本 |
| 业务服务与界面 | 本仓库业务Python安装包及浏览器静态制品，独立受管进程运行；其他形态按实际条件单独验证 | 包及静态文件摘要、锁定依赖、配置和协议兼容版本 |
| 外部终端及持久存储 | 独立生命周期与受管运行目录 | 终端支持版本、配置、状态模式与兼容性 |

先核对WonderTrader原生文件存储与观衡剩余业务持久化职责，数据库不作为默认必需组件。确需保留时采用Windows原生服务，数据与程序独立，避免Docker/WSL；条件及迁移要求见[数据库规格](../specs/windows-native-database.md)。其他组件的容器依赖分别登记。

发布清单将这些组件关联为一个已验证组合。原生部署和容器部署采用相同的源身份、测试、制品校验与业务验真原则。

业务服务与底座通过独立版本化服务契约发布，见[ADR-0002](adr/0002-independent-market-interface.md)。当前行情服务只绑定本机回环；跨主机或容器边界需要受管的 TLS 入口及单独网络验收，回环开发链路通过不表示容器可直接访问该地址。原生资源保持服务内部所有权，业务消费者不依赖其磁盘布局。

## 原生目录模型

```text
<runtime-root>/
  releases/<release-id>/app/      # EXE、库与插件，不原地覆盖
  releases/<release-id>/manifest.json
  instances/<instance>/config/<config-version>/
  instances/<instance>/work/     # 固定工作目录，运行状态独立于包
  instances/<instance>/logs/
  instances/<instance>/active.json  # 托管器的期望包/配置身份
  data/                         # 受管数据集与运行数据
```

这是目录约定示例。`active.json` 属于拟议托管入口元数据，原生上游程序不会自动读取它。监督工具、字段、配置解析及切换需要实现和演练后才可宣布可用。

当前原生 Runner 支持配置与日志配置路径，框架可按工作目录生成状态并在工作目录/实例目录搜索插件。发布演练必须核实相对路径、模块搜索优先级、残留插件及动态依赖，保证实际加载文件来自目标包。

## 身份与恢复

运行观察包含实际 EXE 路径、PID/启动时间、库/插件哈希、生效配置、会话/路由以及资格；期望 active 元数据与真实进程分别核对。不同实例使用独立状态目录与明确的执行权。

状态升级、包回退和配置回退分别判定兼容性；持久账本及已发生交易保持连续。详细步骤见[原生部署手册](../runbooks/native-deployment.md)，通用授权及验真规则见[发布规范](../runbooks/release.md)。
