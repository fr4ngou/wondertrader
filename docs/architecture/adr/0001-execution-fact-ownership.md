# ADR-0001 执行事实与运行投影的所有权

状态：accepted。所有者：架构、执行及运行维护者。替代关系：无。

后继补充：[ADR-0003](0003-native-runtime-and-business-state.md)区分原生运行状态、独有业务事实与恢复机制选择。本文的原子基线/连续水位是受管投影采用的机制；原生插件的替代恢复按同等行为证明与切换规则验收。

## 背景与约束

策略目标、实际账户事实、命令持久受理和框架运行观察具有不同生命周期。外部查询与成交回报分别正确时，重叠的事实范围仍可能让运行持仓重复计入。职责及术语见[领域用语](../../../GLOSSARY.md)。

## 候选与决定

系统采用每条执行路由的单一权威事实所有者，并让框架与业务消费者维护派生运行投影。券商拥有实际账户事实；对应执行状态所有者持有唯一受理、幂等及恢复记录；组合审批和签名继续由各自业务所有者承担。运行组件复用这些事实及原框架归约能力。

另一种组织方式是各接入通道分别维护真实持仓和命令账本。该方式增加事实合并、权限与恢复的长期成本，因此本系统将持久事实归属集中，并承担跨边界完整证明和接口准入的成本。

## 职责与兼容性

运行投影从权威原子账户基线及已吸收事件水位开始，连续消费后续事件。传输包络身份与柜台成交身份分别检查；框架投影、命令关联和有界去重状态各自保留明确来源及恢复边界。

查询成功证明对应观察范围，执行账本的核查证明提交阶段，消费者恢复证明运行应用范围。提交结果未知与消费结果未知使用各自的核查与恢复路径。连接和进程状态分别展示，交易就绪由相应事实及授权确定。

接口缺少完整边界、连续性或恢复证明时，受影响能力保留原因与诊断，新增准入等待权威依据。源端能力资格、真实签名及持久许可由所属边界提供，适配层负责严格映射和拒绝冲突。

## 验证与生效

接口实现与回归入口见[原生接入规格](../../specs/guanheng-native-adapters.md)、[交易执行](../../modules/execution.md)和[受管运行时](../../modules/managed-runtime.md)。必要验证包含快照已吸收成交的重发、断线期间事件、重复柜台成交、未知提交、消费者部分应用及恢复后的零重复副作用。

本决策定义长期事实归属；各路由的启用、切换、回退与生产资格以其实际环境和相应证据登记。恢复及回退持续保留原账本、账户事实与未完成命令身份。
