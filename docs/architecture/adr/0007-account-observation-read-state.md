# ADR-0007 账户观察的进程内请求身份与重新读取

状态：accepted（职责决定；实现和运行资格待验）。所有者：账户接入、受管原生宿主与观衡展示维护者。范围：固定账户position/order/deal/account四个只读查询。

## 背景与依据

账户页面需要本轮持仓、委托、成交和资金观察。原生TraderAdapter负责正常四查询及统计；每轮新进程、新Adapter隔离前轮内存。新接线复用BoundReadCore一次令牌、原ID GET和Host既有通信Journal。通信绑定与券商登录证据继续分别表达。

[必要性审计](../../evidence/2026-10-23-qmt-shm-account-read.md)核对了固定三参数SDK、封闭只读registry、插件写拒绝、Core身份及HostJournal、Adapter四查询和页面刷新路径。当前入口没有交易写调用，也没有必须恢复上一次四查询的产品需求。强制客户端收据目录只能找回旧读取；旧恢复结果本身不具备当前观察资格，却增加磁盘、ACL及累计容量阻断。用户已要求复用原生能力、按实际需要决定持久化，相关边界见[ADR-0003](0003-native-runtime-and-business-state.md)。

## 决定

1. 本轮原请求身份只保留在活客户端有限内存。每阶段只消费一个move-only token、只提交一次POST；有界跟随只查询原UUID。未知终态使本轮失败，不自动重POST或循环造新ID。
2. 每轮使用新的TraderAdapter/插件。整批验证、相同来源绑定、stage/token/实例代际、原截止及一次SPI保持；异常可能部分应用的Adapter整体隔离和回收。
3. 进程死亡使旧轮结束为未取得完整结果。确认旧子树实际回收后，后续明确刷新开启新的scan_id、Adapter和四个新请求；这是新的观察。Host可能执行过旧读取，该事实及原终态仍由原Journal保留，旧结果不套入新身份。
4. 账户观察链移除强制客户端收据持久化、恢复目录、根锁和累计目录/字节额度。Host原Journal和其容量/认证/派发/终态边界保持；历史导出分页恢复按[QH](../../specs/qmt-shm-history.md)独立维护。
5. 父进程准入、单轮并发背压、创建时Job绑定、隐藏窗口、原总截止、管道排空和关闭证明保持。没有回收证明就不启动重叠新轮，没有完整关闭与完整结果就不宣称成功。

## 契约与兼容

[QAR-R5/R6](../../specs/qmt-shm-account-read.md)是字段和验收唯一正文。新schema2使用六个顶层配置字段，CLI保持config/scan-id；不要求recovery或receipt-directory。私有内存注入仅保留runtime_deadline_ns，旧配置schema1及其默认行为保持。新v3/inspection3/IPC2/公开DTO2.0、去敏和券商登录unknown保持。

本决定替代[ADR-0006](0006-account-read-source-boundary.md)中的客户端持久收据和累计容量要求，其原生复用、金融映射及来源职责决定继续生效。尚未编译的AccountReceiptStore/RecoveryBoundary候选及相关配置需要按此收敛；已有静态报告保留其封存源码范围，不能直接授予收敛后实现资格。运行入口保持新配置启动前拒绝，直到匹配新契约的整链验收完成。

## 边界与验证

真实下单和撤单带有外部经济副作用，继续按交易执行契约核查原命令身份与券商结果。本决定不授权交易重发、不启用order_ready或写接口。SDK缓存、实际单位/权限/字段、四表执行时点和登录身份仍须真实来源证据。

验收须覆盖活进程unknown只GET原ID、零重复SPI、晚回/切代、child/parent死亡实际回收后新轮新Adapter、前轮统计不累加、无客户端收据目录依赖、截止和容量、正常/空/部分失败/不可用页面。当前只有源码职责证据；实际测试、安装和真实用户入口仍未完成。


## 配置输入身份的实现收敛

只读父端不递归锁定配置路径的祖先或重解析目标。schema2由应用一次配置准入取得原始bytes，核同一不可变配置后计算内部SHA256，raw不保存在实例中；每轮将该已有摘要经本child私有--config-sha256参数传递。父端每轮没有配置文件IO或读取句柄，原生宿主对同一次read_config的body先核摘要，再解析、装载及连接。内容改变或缺失握手失败关闭，相同bytes可由合法别名读取；父全局环境不承载每轮状态。公共配置仍为六字段，无恢复目录/收据/根锁。配置变更需要显式重新准入；旧实例在native读到不同bytes时明确失败，不自动接受文件替换。该摘要是输入一致性证据，不替代源端认证、安装身份或金融来源资格。

私有握手、中央Job原截止/真实整树/逐句柄关闭与现有消费者的实现及运行资格分别登记。该收敛源于只读输入身份职责，未改WonderTrader框架；实际Windows、安装及用户链仍须匹配证据。

## 显式已消费只读责任回收

[AAR](../../specs/qmt-account-read-retirement.md)沿本决定的进程内scan/原ID及可重新查询边界接入RR。Native在本进程完整验证并取得原结果的有界值所有权后，沿原D确认消费；无需客户端文件。Host只回收已确认、确定完成且票据失效的读取责任，未知和既有无票据责任保留。v4金融命令/事件表及额度保持，附加读取元数据不能清空或替代金融Journal。旧配置省略显式能力时沿原行为；具体运行资格按后继证据。
