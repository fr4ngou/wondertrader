# ADR-0003 原生运行状态与独有业务事实

状态：accepted。所有者：架构、数据、策略与业务集成维护者。补充ADR-0001、ADR-0002；不改变交易授权和唯一命令身份原则。

## 背景

系统需要统一回测和实盘，减少重复运行机制，同时保留配置、研究、任务与审批等用户功能。数据库表、消息队列和服务进程是实现方式；事实的必要性由用户功能、恢复和并发语义决定。

## 决定

行情序列以WT原生存储及接口为持久与读取边界，策略通用运行状态、理论持仓、回测与执行目标由对应原生上下文承担。与旧系统重合的能力全部采用WonderTrader，旧设计和实现退出目标架构。先核实原生能力、条件和边界再开发；仅对明确缺口增加业务扩展。外部消费者通过独立、版本化接口读取同一事实；不得仅因旧消费者使用SQL接口而新增全量行情副本。

通道订单成交记录和查询优先复用原交易模块。记录其实际覆盖条件：终态订单与成交推送日志、账户快照、策略日志各有不同范围。展示投影可以重建；未知提交、审批消费和命令去重由唯一执行事实所有者持久处理。存储格式不扩大原记录的保证。

观衡保留必要的配置版本、研究结果及证据、用户任务、人审和业务归属事实。是否采用数据库、对象存储或文件，由最小事实集合、并发写入、故障恢复和独立发布需求决定。原服务边界可以收敛，必须保留的用户功能和事实由契约明确。

恢复协议选择与事实所有权分开。ADR-0001的原子账户基线及连续水位描述适用于采用该机制的受管投影；它不是上游所有插件的强制ABI。替代实现必须证明快照/增量交接、重复处理、未知结果核查及就绪资格。选择失联后重建消费者时仍须验证这些条件。实现替换及核心源码变更遵循相应审批与切换程序。

## 后果与验收

2026-10-22范围补充：研究等退出范围以ADR-0004为准；用户进一步明确资金及风险能力优先复用WT。前述业务归属/人审不是必须迁入清单，当前不新增独立资本账本、资金划拨及逐单人工风险审批工作流，策略预算保留明确配置。产品范围以[系统目标](../../product/brief.md)为当前正文；未知提交核查、接口认证和账户许可继续归各自接入职责。

读取适配承担单位、时间、来源、覆盖和错误的明确映射，不复制行情算法或业务确认账本。策略确认绑定业务效果，不能从行情最高时间推定。部署按组件独立发布，选择持久后端不强迫行情与业务同库。

职责迁移逐字段验证旧事实、新owner与用户入口，保留未决操作和回退输入。只有完整调用链及故障恢复通过后才能停止相应旧活动入口；数据保留或删除按单独授权。当前实现与运行资格由规格、任务和证据维护，ADR不代表已完成迁移。
