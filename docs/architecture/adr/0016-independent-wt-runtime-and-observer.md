# ADR-0016 WT运行与观衡只读服务独立部署

类型：长期架构决策。状态：accepted。依据：用户明确要求WT独立完成自动交易，观衡仅负责观察。

## 决策

WT运行发行单元拥有QMT通信Host、行情采集与归档、历史查询及补齐、策略、账户接入和交易执行的生命周期。该单元使用WT原Runner/CTA、DataKit、Writer/Reader及Parser/Trader插件；自有启动适配只组合这些已实现入口。QMT终端内继续通过命名共享内存通信，维持无外部文件读取和网络连接的约束。

观衡为独立部署、独立发布的只读服务，消费WT运行侧提供的行情、账户、订单、策略状态和回测报告。观衡的启动、停止、升级、故障及浏览器访问均不启动、停止或重启WT、QMT Host、行情采集和交易执行。WT运行及策略代码的安装依赖不包含观衡Web包、SPA或其服务进程。

两侧配置分别拥有。运行参数和生效策略由WT运行实例管理；观衡的展示偏好、自选和缓存由观衡管理。行情或账户查询走WT公开只读接口；触发历史下载、修改运行配置、下撤单和进程启停属于运行侧操作，不由观衡页面或服务承担。

已验读取发行的永久源码保存于packages/observer-read-side，WT执行发行继续由原执行项目拥有。读取变体保留其原发行版本、依赖及兼容行为，分别构建和安装，避免一个源码目录同时代表两个不同版本。永久构建与验收沿[读取侧源码发行规格](../../specs/observer-source-build.md)；源码归仓不扩大观衡的运行或交易权限。

同一分发介质可以携带两侧制品，组合清单只记录已验证的版本关系。两侧分别安装和启动，独立升级；共享制品目录不形成父子进程关系。QMT Host是WT接入适配的一部分，WT原生框架本身不提供券商私有共享内存协议。

## 取代范围

[QSW-R20.8](../../specs/qmt-shm-wt-binding.md#r208-观衡统一管理独立host进程)及[EAM](../../specs/execution-app-management.md)中的观衡生命周期所有权被本决策取代。已有源码和冻结验收原件保留实际身份，其通过结果仅证明原组合下的组件行为。后续实现将可复用的进程适配移至独立WT运行包，观衡退出进程管理职责。

## 验收

1. 仅安装并启动WT运行制品，保持观衡Web包及SPA不可用，完成Host连接、采集、历史读取、策略目标和隔离执行整链。
2. WT持续运行时启动、关闭并重启观衡；WT的PID、连接代际、采集计数和策略运行保持连续，无观衡引发的停止或重发。
3. 观衡重启后从WT只读接口重新取得当前事实；接口故障只影响相应展示，不改变运行侧状态。
4. 两侧制品分别在新根安装；WT运行依赖闭包不导入观衡包。原关闭收据、未知委托处理及恢复责任沿原唯一所有者保留。
5. 原生框架算法与默认行为保持；任何新增框架源码修改继续按既有审批规则处理。

实现与验收状态见[独立运行规格](../../specs/independent-wt-runtime.md)，部署边界见[部署正文](../deployment.md)。
