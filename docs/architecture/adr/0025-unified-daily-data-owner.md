# WT统一日线和定日事实归属

状态：实现与验收中；当前线上入口保持，统一交付后由Root接收切换。

同一市场指标曾分别读取公开股票报价、QMT分析包及WT历史，来源日期、补齐责任和恢复身份容易分离。WT数据侧统一拥有原价/供应商前复权、证券资料、定日股票池及补充事实的采集、缓存优先缺口补齐、原生落盘和版本发布；观衡经统一WT入口只读同一版本，保留原指标计算。高管、回购、利率和GDP继续由各自披露来源拥有。

原QMT未解请求保留原operation、UUID、证券和日期区间，其他证券可独立推进。调用返回与实际缓存覆盖分别确认；上市前、停牌和未知资料分别表达。原价和供应商前复权各自保留来源参考，日线数据日期与来源实收时刻分别记录。

公开补充事实复用仓库已有输入适配器和同一份原件解析实现；WT数据角色构建时组合这套共享源码和精确依赖，独立运行。源代码保留的历史Python命名空间不授予观衡采集所有权，也不要求WT连接运行中的观衡服务。观衡新活动配置消费统一入口，旧来源实现及数据随回退制品保留。

持续部署复用原SMP及WT SourceMarketProcess，通过显式daily_update描述符在同一受管进程组合单个生产线程和原HTTP读取线程。两者分别拥有客户端/SQLite与Reader，发布通过同一CURRENT连接；父Job拥有最终资源关闭截止。该选择将进程故障域绑定，已成功快照、原请求槽及数据历史留在外部持久根，重启沿原身份恢复。未选择该配置时保持原读取角色。启动时校验生产者与读取者指向同一发布根，防止配置形成分离入口。

见[统一日线规格](../../specs/qmt-source-daily-history.md)及[独立部署决策](0016-independent-wt-runtime-and-observer.md)。
