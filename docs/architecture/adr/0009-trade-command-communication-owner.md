# ADR-0009：共享通信Journal承载写命令身份

状态：accepted（开发职责）。类型：长期架构决策。

WT原生模块继续拥有策略目标、交易执行、持仓/未完成量与成交归约。券商拥有实际账户事实。供应商接入需要在跨进程调用前保存原命令身份，调用后结果不明时按原身份核查；原生委托日志与通信受理事实分别负责各自边界。

外部Host复用同一个受管通信Journal及独占owner/事务，版本化扩展命令原文、派发/SDK回执和来源关联；不增加金融账本、资金服务或逐单审批。源Agent只保留有限会话内索引与回调缓冲，不读取文件、不建立网络，原策略线程调用SDK。

券商回报在交给原生消费者前的通信窗口由同一Host owner保存原事件与连续交付前沿。Host持久接收、源缓冲回收和WT已应用分别表达；前两项不能替代第三项。事件记录不归约账户事实，unknown后仍可接收和核查回报；各类记录有显式额度且不自动删除。

queued在派发前持久化；dispatching在外发前持久化。源SDK调用与Host持久结果之间没有跨进程事务；重启后派发状态保留unknown，不自动重发。已知未调用与结果未知分别表达，查询不到订单不能证明未调用，正常SDK返回不等于柜台受理。

写能力采用显式版本、默认关闭，旧只读owner拒绝不理解的新Journal表与profile。容量有明确上限，既有命令结果可读且不自动删除；未知命令的核查和实际切换沿受管维护范围。接口和验收见[QST](../../specs/qmt-shm-trading.md)。
