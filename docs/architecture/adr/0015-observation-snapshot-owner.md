# ADR-0015 独立观察快照与目录所有权

类型：架构决策。状态：accepted。依据：保留独立市场观察和本仓独立App发行目标。

## 决策

观察特有定义、计算和不可变快照归观衡业务owner；WT继续拥有重合行情存储/查询。原独立观察使用PG事务CAS、session采集锁及MinIO镜像，语义需要迁入；旧部署组件形态不构成新安装依赖。

本地独立安装采用SQLite目录事务，SHA256内容文件只增保存。manifest与current及成功receipt同一事务，expected-current执行CAS。单独lease数据库的写事务拥有跨进程采集排他，避免发布事务与采集锁相互阻塞；退出/崩溃后由OS释放，不据锁文件存在判断占用。受控根须位于本地磁盘；多主机共享文件系统不在该实现资格内。

导入保留原冻结manifest身份，核验全部引用对象后原子采用。读取、导出和恢复使用同一owner及原纯计算；公开观察不会改变策略配置或执行资格。数据库连接每次操作显式关闭，App的读取沿既有有界读池，采集调度由显式配置的独立受管进程拥有。读取不触发更新。

2026-10-30部署收敛：独立观察监督命令复用原ManagedLocalProcess拥有采集子进程及其Job，与Web App分别启动和关闭。Web只读外部数据根，观察服务只读WT行情接口。日常页面只显示独立服务的最近心跳与原发布回执，停止Web保持调度继续。该接缝补齐原App退出运行管理后缺少独立监督入口的部署缺口，采集、窗口去重、内容存储与事务发布继续使用原实现。

同日实际持续采集复现大目录发布与只读查询争用：默认rollback journal在页缓存溢出及提交时持排他锁，查询返回catalog_unavailable。目录改为WAL/FULL，保留事务CAS与发布原子性；调度生命周期持无事务目录连接，普通查询仍短连接，避免频繁触发最后连接的清理锁。SQLite官方[WAL文档](https://sqlite.org/wal.html)说明并发读写、PASSIVE checkpoint、最后连接清理及旧版WAL-reset缺口；本实现要求SQLite3.51.3或更新版本，实际发行绑定所验运行时。原两份lease数据库继续各自排他，WAL/SHM属于目录持久状态，由SQLite负责恢复和清理。

实际人工更新后继进一步复现心跳写者与大manifest写者争用，调度因此退出。心跳改由有效scheduler lease的唯一写者原子替换同根有限scheduler-status.json；它只表示最近调度检查，不承担快照、窗口或业务回执。数据发布保持原目录事务，心跳与停止状态独立于发布写锁。新状态文件为当前事实；旧catalog的scheduler_state只作没有新状态文件时的历史归档迁入，首次独立监督即写新事实。该职责拆分使用已有排他lease与同目录原子替换，增加一份有限状态文件，避免人为重试、加长锁等待或另建状态数据库。

采集后继继续使用同一目录发布owner。计划窗口完成索引、成功回执及新快照/current共同提交，窗口恢复按原身份查询完成索引；最近100条回执仅承担展示。采集进程拥有来源网络/SDK及原始字节预算，普通读池保持零采集。独立调度沿[OBI5–7](../../specs/independent-market-observation.md)验收，接线和实际资格分别登记。

长期调度与短批次采集各有排他责任。scheduler.sqlite3只承担调度进程存续期租约，不存业务账本；同根第二实例在就绪和状态写入前拒绝，状态写入须持有效租约。collection.sqlite3继续只锁单批次，保留人工更新与定时等待的组合。新增协调文件解决多调度实例覆盖心跳的缺口，连接关闭及进程崩溃均由OS释放，无遗留锁文件删除操作。根调度事实与本App进程事实分别投影。

发布事务准入沿原批次D及停止信号，未进入提交前可回滚。提交结果未知沿原snapshot/窗口核查完成索引；已提交事实保持，不另写失败覆盖或自动重采。该语义由原SQLite目录承担，未新增第二份发布账本。

## 影响与验证

旧PG/MinIO迁移通过受控离线manifest/内容包；包的来源和最新性保持原语义。独立安装额外需要固定Parquet codec。须验证事务失败/竞争、完整校验后发布、崩溃释放及原身份恢复。镜像备份、采集、正式调度和统一升级回退按[独立观察规格](../../specs/independent-market-observation.md)继续验收。
