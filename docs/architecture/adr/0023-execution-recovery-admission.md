# ADR-0023 执行恢复准入与兼容发行交接

类型：架构决策。状态：accepted。日期：2026-11-02。范围：自有执行适配层。依据：主会话确认的故障核查恢复需求和固定前后发行协议。

## 背景

原正常恢复证明同时绑定安装清单、原金融文件和成功关闭。运行期间只读来源失败会留下已保存策略状态和故障收据；原正常关闭证明已经消费。自有适配升级还会改变安装/Python来源身份，原模型仍可能完全兼容。

## 决策

执行owner拥有恢复准入，WT继续拥有金融JSON、用户KV与原保存/读取流程。正常关闭依据与故障核查依据分别表达；显式resume_reconciled复用同一原券商查询、原自有单收束、同根租约、WT加载及正常关闭，仅增加首次准入依据。

固定前代→本代发行材料绑定两代实际安装/Python来源、原配置和状态文件摘要。模型兼容独立核验：原输入、纯策略/NSQ、周期/止损和状态不变量保持；自有适配来源变化沿显式身份交接处理。当前发行解释器入口是身份的一部分。原金融命令和未知责任沿原ID核查，恢复材料不授重发权限。

正常关闭后的兼容发行核原closed/clean并按原协议消费真实clean；故障依据核原ready/failure/close-prepared和物理退出。前代安装依据缺失、状态不完整、未决责任未核清或不兼容时保留明确保护。成功后重新进入现有正常close/resume协议。

整树退出缺原关闭收据时，由原运行入口在实例OS租约内核原身份和所有已记录PID退出，发布独立owner-loss故障及faulted观察。执行恢复owner对原Native另记只证明进程退出的owner-loss，Native在原输出租约内再次核原ready摘要、进程退出和相同发行/金融状态及当前券商责任，记录process_lost_reconciled认领。该依据保留原关闭结果未知，原正常closed和clean仍只由实际成功关闭产生。

## 影响与边界

新增材料和核查收据属于准入/审计证据；金融事实与策略状态保持原唯一owner。观衡只读取结果，WT核心源码和库保持原样。只读来源跨运输绑定的完整观察代际交接另按独立方案处理；单纯等待503不获得跨绑定资格。契约见[执行故障恢复](../../specs/execution-fault-recovery.md)。

2026-11-03补充：只读执行授权在原策略边界显式收为空集合，计算建议、WT理论账目标和券商事实各守原owner。原件恢复保留最新真实生命周期和被恢复状态来源；就绪前失败则核其已准入且逐字节未变的原状态，后继发布独立初始化失败核查依据。正常关闭证明继续只由真实成功关闭产生。具体EFR-16至EFR-20接口及[候选验证](../../evidence/2026-11-03-strategy-readonly-recovery.md)分别维护。
