# 策略状态兼容身份与程序部署身份分责

状态：accepted。所有者：自有策略宿主与策略状态协议。范围：Retained、OriginalLive及确认回调的恢复状态；不修改上游WT行为。

策略记录原来包含整套Python源码的摘要。维护日志或账户金额转换也会产生新的摘要，INIT随即逐策略改写ASA身份。后一个策略初始化失败时，ASA已更新、Native金融文件尚未保存，下一次恢复便面对两个不同版本。这一职责混合使正常维护触发业务状态迁移。

状态记录复用原 `StrategyStateRecord`，以版本化的模型身份合同绑定状态schema、策略实例、业务参数、证券映射、模型配置及算法契约。Retained对空状态也绑定算法与配置。原Native `python-binding`、安装清单及恢复transition继续核实实际程序来源和授权发行。程序版本变化不改变状态兼容身份；状态含义或算法变化必须更新契约版本并明确迁移。

INIT严格恢复、校验并镜像已有记录，保留其原payload，不产生仅因初始化或代码部署而变化的业务记录。真实成交、费用、目标及随后策略状态变化继续沿原owner提交。ASA保存后、Native镜像保存前中断时，下一次仍以ASA原记录恢复；NativeKV镜像按原版本补齐，不引入整组分布式提交器。

已有代码摘要身份通过一次性运维迁移到新模型身份。迁移核原配置及发行来源，使用原状态owner的CAS，校验资金、持仓、目标、价格cap、来源、时间、序号和未知委托完全保持。独立NativeKV模式需要在原恢复租约及材料重新生成前完成相同迁移。产品不保留旧身份猜测或失败日期特判。具体要求与验收见[执行故障恢复](../../specs/execution-fault-recovery.md#策略状态模型身份)。
