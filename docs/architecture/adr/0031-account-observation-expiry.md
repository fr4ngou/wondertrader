# ADR-0031 账户观察结果按原期限回收

类型：架构决策。状态：accepted。日期：2026-11-21。范围：显式保留模式的 v3 账户、v4 交易 Host 只读账户观察。

## 背景与决策

账户查询完成后，消费者退出或消费确认丢失，会留下已经确定完成的结果。原实现同时要求消费确认和票据结束，过期结果持续占据固定容量，后续持仓、委托、成交和资金查询因此无法完成。

账户观察由活进程取得完整结果，原观察期限结束后可明确开始下一轮观察。Host 在原独占事务中回收原票据已经结束、结果确定、且未被金融订单关联引用的 `account.trade_detail` 记录。消费确认继续表达交付成功；期限回收单独表达该结果的交付窗口结束，保留 `410 read_ticket_ended_unretained` 的原查询语义。

运行中、结果未知、无票据旧记录及金融证明继续持有原身份和额度。原交易命令、事件、账本及默认未启用模式保持。普通读取与 HPR 继续沿原消费确认规则；共享回收实现按操作和所属 owner 明确区分。

## 验证与后继关系

覆盖失去消费确认后跨期限及 Host 重开连续完成四查询、期限内原结果可读、未知与执行中请求保持，以及金融引用解除前后回收。部署沿正常停止、同库恢复和单一写入者流程。

本决策补充 [ADR-0018](0018-confirmed-read-responsibility-retirement.md) 与 [ADR-0024](0024-host-http-read-retirement.md) 中账户观察的期限语义；规格以 [AAR3](../../specs/qmt-account-read-retirement.md#aar3-host回收与金融隔离) 为准。现场验收见[恢复记录](../../incidents/2026-11-20-trading-recovery.md)。
