# 观衡中文操作员手册

类型：操作手册。适用：独立安装的只读观衡App、生产SPA及独立WT运行环境。功能与验收沿[COP规格](../specs/guanheng-operator-platform.md)，当前候选资格见[模块C交付](../migration/module-c-delivery.md)。本手册汇总日常入口；具体配置格式仍由所链接的唯一正文维护。

## 安装与启动

维护人员先提供同一候选的App解释器、SPA目录、WT安装清单和只读连接，逐项核版本、SHA、配置及状态兼容性。WT拥有Host、历史、采集、策略、账户查询和交易生命周期；观衡拥有Web读取线程及个人自选。两者使用独立环境。历史、回测归档、个人自选和独立观察数据保存在外部受控目录，程序更新沿用原数据身份。

从已安装解释器启动，以下两项路径替换为本机实际安装值：

```powershell
& "<已安装Python绝对路径>" -I -X utf8 -B -m guanheng_app `
  --host 127.0.0.1 --port 18120 `
  --static-directory "<生产SPA绝对目录>"
```

打开本机地址`http://127.0.0.1:18120`。先到“系统状态”核WT最近发布状态与行情读取，再进入相应业务页。状态带发布时间；“就绪”表示该份WT发布的状态，当前存活及连接持续性按WT运行侧核实。数据日期、来源质量和业务结果继续从实际页面核验。缺少连接的工作区说明待接入，其他读取继续可用。

行情地址、令牌、连接IP和超时沿原SDK读取配置；令牌及账户凭据保留在受管环境。WT状态读取的四项身份沿[账户手册](account-observation.md#安装与读取连接)。GUANHENG_BACKTEST_ARCHIVE_ROOT绑定已保存报告，GUANHENG_WATCHLIST_ROOT绑定个人自选，GUANHENG_OBSERVATION_ROOT绑定独立观察归档。缺观察根会使观察目录和更新状态无法读取，启动前应核实际归档。各能力设置见[历史查询](source-market-app.md)、[账户](account-observation.md)、[WT补齐](history-preparation-app.md)和[原生回测](native-backtest.md)。旧Host、采集、执行、扫描和回测运行环境项由当前观衡忽略。当前统一安装及全系统升级回退仍待最终组合验收；各切片证据分别保留。

## 查看日常业务

| 工作区 | 操作与核对 |
|---|---|
| 总览 | 查看账户资金、券商实际持仓及最近一次策略状态；核决策时间与持仓查询时间，刷新失败时保留原结果 |
| 行情 | 输入证券代码，选择分钟或日线并读取；核最后来源日期、来源单位、覆盖和本次观察时间。个人观察保存只改变自选资料，策略交易范围由其配置独立拥有 |
| 策略 | 查看唯一保留策略的名称、简介与正式版本，按名称或版本搜索。实际运行结果见总览，委托与成交见交易记录 |
| 回测与报告 | 在策略工作区切换标签，读取已保存报告，查看日末绩效或选择另一份报告比较；运行与取消使用独立WT入口 |
| 账户 | 核WT发布的资金、总持仓、可卖及各批接收时间。当前未提供账号、环境、交易日或查询区间时保持未知 |
| 交易记录 | 查看当前来源的委托及成交。活动、部分成交、撤余、拒绝和未知结果分别处理，按原命令身份核查 |
| 系统状态 | 查看WT最近发布的中文组件状态、发布时间和独立行情读取结果；重新读取只更新观察。WT关闭和恢复沿其运行入口执行 |
| 市场观察 | 看板选择指标和日期；“指标说明”查看中文来源、覆盖、公式与读法；“导出”选择指标和日期下载CSV/JSON/JSONL；“更新与数据缺口”核每路来源及最近更新结果 |

账户与交易页保持只读。维护人员配置WT独立账户发布后，可读取持仓、委托、成交及资金四类原查询；各批时间和来源分别显示。策略运行结果中的券商观察保留该次策略记录的接收时间，可能早于独立账户页的最后查询，查看最新持仓时核对账户页时间。来源只提供部分类型时，其他类型明确标为缺失；刷新只读取已发布副本。停止后页面保留最后成功结果与原时间。当前同一九组件SDK来源的四组和页面范围见[消费证据](../evidence/2026-10-30-nine-component-observer.md)，实际账户、运行中联合和生产资格沿最终交付分别核实。

策略页面按用户确认只显示名称、简介和正式1.1.2版本。参数、预算、实时隔离启停及实际配置由维护人员使用已配对WT入口处理；公开任务与配置定位尚未提供时页面说明待接入。旧配置回执及存储原件保持，当前只读App不注册配置写入口。当前M1 Runtime稳定性与真实历史知晓模型继续验收。

总览中的“本轮调仓已完成”表示WT已按券商实际持仓确认本阶段完成；“本阶段策略计算已完成”表示已取得计算结果，当前来源尚未提供执行完成确认。查看实际数量和可卖数量时，以对应持仓及原接收时间为准。WT停止后页面保留最后结果并显示已停止，刷新只读取已发布记录。

系统状态中的“策略数据通信”和“策略数据更新”分别显示通信服务与数据更新服务。“基础就绪”只说明服务状态；“尚未发布策略数据”“保留最近发布数据”及其交易日/发布时间用于核数据。等待通信或正在刷新时可以同时保留上次发布数据，停止后也会显示最后发布事实；数据是否满足当前策略时效仍在策略工作区核验。数据扩展缺失时本项显示未知，其他组件继续显示。当前实际资格见[WT组件状态证据](../evidence/2026-10-30-wt-runtime-observer-components.md)。

运行侧发布了可解释的故障时，系统状态页分别说明问题、影响和处理方向。“首先报告的问题”沿原运行侧记录，“同时报告的问题”列其他已报告故障；报告顺序不证明因果关系。关闭失败、停止超时和强制回收按各自来源表达，正常停止中保持等待；具体原因未知时明确待核查。维护人员在WT原运行目录核对关闭记录、资源回收和未决责任，观衡继续只读。状态针对最近一次发布，页面不探测当前进程存活；读取失败保留上次成功的问题和原时间，恢复读取清除本次读取错误，原运行故障按其发布状态保留。

## 回测、比较与未知结果

观衡读取独立WT已完成并保存的报告。回测启动、取消、未知结果核查和归档发布使用原运行入口及命令身份，详细步骤见[回测手册](native-backtest.md)。关闭或升级观衡保持原WT任务及归档。当前公开任务状态定位仍待接入，当前页面提供报告、绩效和比较。

完成报告显示所选实验的显式本金、原生日末净值、回撤、费用及条件差异。比较读取两个已准入报告；同一对报告刷新失败时保留上次结果及原读取时间，重试成功后更新。切换报告后按新选择读取。真实历史采用本批最终前复权基准和显式日末回放假设，历史首次可知时间仍未知；撮合和本金属于已声明的模拟模型。回测表现、BT/RT目标与真实券商收益各按相应数据核实。

## 高管增减持

高管增减持看板提供净增持额、增减持金额净占比，以及增持/减持/任一变动公司占比。当前已验证范围沿[高管观察证据](../evidence/2026-10-30-executive-observation.md)，指标名称直接标注市场范围和已披露口径。先看日期和范围，再结合待确认笔数阅读；本人关系、职务或交易性质待核、缺金额或公司身份时相应完整值留空，已确认金额保留小计。公司同时增持和减持会进入两个分项，“任一变动”只计一次。披露存在滞后，后续更新可能修订旧日期；需要实际资金流水时查看券商记录。

## 每天09:00市场观察

独立观察服务负责按北京时间09:00检查更新窗口；观衡App读取其归档。来源读取、计算、验证和发布归观察服务，App启停保持该服务独立。窗口完成后保留原回执，重启沿原窗口核查。独立部署与调度功能闭环已完成[限定验证](../evidence/2026-10-31-observer-a68-continuity.md)，受控时钟验证与真实自然窗口、未来每日来源分别登记。已有归档的读取不授持续采集资格。每天指标有效日期依各来源发布时间而定，09:00是计划调度时刻。

来源失败时保留此前合格数据，页面展示本次失败及原数据日期；整组结果可为partial。目录页留存与已解析数值分别标注。看到partial时按“更新与数据缺口”逐路核原因；修复来源后由维护人员沿原窗口/attempt事实决定恢复，原回执与快照保留。完整来源资格和自然窗口结果以当前证据记录为准。

## 停止、恢复与升级回退

通过原启动进程的正常停止入口退出App。App停止Web读取准入并回收自己的读取线程及个人自选owner，WT、Host、历史、采集、补齐和执行保持原实例。App异常退出后沿原只读连接恢复；资源关闭异常保留原日志及控制证据。WT自身的停止、恢复和退出码沿[独立WT手册](wt-independent-runtime.md)处理。

恢复观衡前核WT读取连接与公开身份。委托结果未知、活动责任或不匹配状态根由WT运行侧核查，保持原命令及运行目录。券商持仓与个人展示资料分别由其原owner核实。本次交付省去目标仓位明细，旧开仓记录、历史交易和旧持仓周期不做迁移恢复；行情K线与回测报告继续保留。

升级观衡先记录旧/新App与SPA、外部数据和读取配置摘要，正常退出观衡；新程序装入独立目录，重新绑定只读路径与身份。WT继续运行。启动后按“系统状态→行情→账户→策略资料→既有回测报告→市场观察”核主要数据，再正常停止一次。回退使用已保留、兼容当前读取状态且符合独立只读边界的App/SPA组合。独立版本的精确命令、状态兼容范围及观察快照回退见[独立安装与更新](observer-runtime.md)和对应交付记录。旧托管型App会重新介入运行生命周期，其[早期演练](../evidence/2026-10-30-independent-observer.md)保持原范围；当前独立版本不沿用该托管入口。全系统演练完成后由发行记录提供固定候选命令，原生WT升级沿[原生部署](native-deployment.md)及各组件手册执行。

真实委托/撤单、生产配置切换与生产发布按相应明确授权执行。一般读取和候选开发验收沿当前已授权范围继续。

当前只读候选后继修正了观察取消后的自有线程关闭：预算覆盖观察原15秒、报告5秒与行情原配置截止。旧a31虽已完成空闲读取条件的版本兼容演练，仍有观察在途关闭预算缺口，当前全面回退资格保持待验；维护人员按最终候选证据核回退范围。浏览器读取等待各通道最多32项，满额提示稍后重试，取消释放等待名额，状态和审计各自保留容量。
