# 观衡中文操作员手册

类型：操作手册。适用：独立安装的只读观衡、市场观察更新服务及独立WT运行环境。功能依据为[COP规格](../specs/guanheng-operator-platform.md)和[用户验收规格](../specs/observer-acceptance-repair.md)；本机版本、地址、数据覆盖与未完成项见[交付记录](../releases/README.md)。

## 启动与独立运行

维护人员按[独立安装手册](observer-runtime.md)安装App和SPA，配置行情连接、WT发布身份、报告归档、个人自选及观察数据根。使用该安装的`observer-web.py start/status/stop`管理Web。

本机观衡正式地址固定为 **http://127.0.0.1:18143**。用户要求后续发布、升级和回退保持18143；变更前须取得用户明确同意。部署沿用observer-current/web-profile.json的host/port及DEPLOYMENT定位，核实际监听；端口占用沿原实例排障，测试端口仅服务隔离验收。

WT拥有QMT通信、行情、历史、采集、策略及交易生命周期；市场观察更新服务拥有公开资料采集和归档；观衡只读取结果、保存个人自选。三个入口分别启停，关闭或升级观衡后，WT和市场观察更新继续运行。运行身份与维护命令分别沿[WT手册](wt-independent-runtime.md)、[市场观察手册](market-observation.md)和[Web维护入口](observer-runtime.md)。

程序版本与数据目录分开管理。行情、报告、观察原件和个人自选保存在程序目录外，升级沿用原路径及身份；凭据保留在受管私有配置中。

观衡配置公开CURRENT读取后，WT日常启动、停止和重新启动沿[原服务入口](wt-independent-runtime.md#日常启动停止和状态查看)操作。观衡保持运行，账户、策略和系统状态页每15秒读取当前实例；用户无需修改运行UUID、配置摘要或重新启动观衡。当前实例读取失败时页面保留原成功结果及时间并显示失败；已知换代后等待本代账户结果，清除上一代账户回退。实际版本、网页地址及已验证新代见[联合验收入口](../evidence/2026-11-04-observer-current-joint-acceptance.md)。

## 查看日常业务

| 工作区 | 操作与核对 |
|---|---|
| 总览 | 查看账户总资产、可用/冻结资金和持仓、委托、成交记录数；通过快捷入口查看明细 |
| 行情 | 在顶部输入代码、代码前缀、中文简称或拼音，直接从下拉候选选择证券；自选显示真实名称、类型和最近5日小图。默认日线，可选分时、日、周、月及显示范围；核来源末期、实际根数和单位 |
| 策略 | 在“选择策略”下拉框明确选择实际登记策略；查看运行与持仓、策略说明，通过“查看该策略回测”进入对应报告列表 |
| 回测 | 先选择策略，在报告列表选择主报告及可选同策略对比报告，再打开分析；点选日期查看持仓盈亏和当日成交，“全部交易记录”查看完整成交；回测运行与取消使用独立WT入口 |
| 账户 | 查看券商资金、持仓数量、可卖和市值，分别核每组数据的查询时间 |
| 交易记录 | 切换委托、成交，核来源订单号、数量、状态与原查询时间；结果未知由WT沿原委托身份核查 |
| 系统状态 | 按实例查看账户、行情、历史和采集状态；展开说明查看故障及最后更新时间；重新读取更新页面观察结果 |
| 市场观察 | 在看板选择指标和日期；用“指标说明”查看名称、覆盖与读法，用“更新与缺口”核数据更新状态，用“导出”取得当前版本的数据 |

行情快捷键：`/`聚焦搜索，`D`日线、`W`周线、`M`月线；在文本输入框内保持正常打字。5/30/60日表示最近相应数量的交易日；1/2/3年按最后来源日回溯公历年。周/月按实际日线聚合，来源不足时保留实际范围。个人自选仅保存观察偏好，策略证券范围由WT配置独立管理。

## 资金、持仓与运行状态

账户资金来自券商全账户查询；策略资金来自WT已发布的策略资本和账务结果，两者分别显示。查看策略总资产、现金、可用资金、持仓市值及本次运行盈亏时，同时核原估值和资金时间。观衡直接展示原金额；预算、分配和策略计算由WT负责。

持仓数量和可卖以相应券商查询为准，策略归属按运行侧发布。没有发布策略资本时显示待更新；没有启动执行器时显示未启动。历史累计收益需要相应本金、现金流和连续净值，缺少这些事实时保留未知；本次运行盈亏与历史累计收益分别阅读。

账户查询、策略计算、报价估值和组件状态各有自己的来源时间。状态页的就绪表示对应运行发布，数据是否满足当前交易日和策略时效还需核实际记录。多实例按各自名称和身份展示，局部读取异常只影响对应结果。

盘后恢复可以沿同一账本保留的合格估值展示资金，同时刷新本代账户可用额度。价格、账户查询和恢复发布各自保留原时间；“等待新行情”表示尚未发生本代自然策略计算，交易是否启用仍由运行侧配置决定。

刷新读取已发布数据。更新失败或WT停止时，页面保留同查询条件最近成功的结果和原时间，并显示当前异常或停止状态；维护人员沿WT原控制ID、状态及日志核查原因。个人自选与券商持仓分别由各自所有者保存。

## 市场观察与高管披露

独立更新服务按配置的北京时间窗口采集、计算、验证和发布，页面显示实际计划、最近心跳及最近完成结果。原窗口和尝试记录保留，恢复沿其身份接续。手动来源更新、自动窗口和已归档历史分别登记，当前可查看历史与持续采集资格各自以交付证据为准。

先看指标资料截至日期，再看更新服务是否完成检查。日频使用实际闭合交易日，月/季/年频使用真实报告期；本次查询时间和报告统计日期分别保留。来源尚未披露新期次时保留上次数据，曲线中的缺口按实际覆盖显示。单路失败保留该来源旧值；部分成功时进入“更新与缺口”定位具体来源，成功来源可以继续更新。

高管增减持统计已披露变动，披露可能晚于实际发生时间，盘后检查也可能修订旧日期。看板提供净增持额、增减持金额净占比及增持/减持/任一变动公司比例，名称标明市场范围。先核日期、范围及待确认笔数；缺金额、身份或交易性质时保留相应未知和已确认小计。公司同时增减持可进入两个分项，“任一变动”只计一次；这些资料与实际券商资金流水分别使用。

## 回测、比较与导出

观衡读取WT已完成并归档的报告。回测启动、取消、结果未知核查和归档发布沿[回测手册](native-backtest.md)及原命令身份处理；关闭观衡保持WT任务及归档。

回测主图可切换累计收益率和净值；悬停查看真实日期、日收益和日末回撤，点击日期同步右侧明细，滚轮或底部滑块缩放。“买卖标记”控制买入、卖出及多笔成交日的显示。右侧日期选择器提供相同的键盘操作；比较报告时可以明确选择明细所属报告。

“持仓与盈亏”显示所选日期的非零日末持仓、浮动盈亏和累计已实现盈亏，盈亏均未扣费用；已平仓证券可在成交列表查看。当天没有成交仍可查看当天持仓。日收益在首期或跨缺失观察时保持未知。比较曲线各按自己的实际本金和日期计算；条件差异在指标下方提示，短报告结束后的日期保持空白。

报告中的本金、撮合、复权与日末回放均按所选实验的实际声明解释。查看净值、回撤、费用及两份报告的差异时核条件和覆盖；回测表现与真实券商收益分别阅读。读取失败保留同一选择的成功结果和原时间，切换报告后按新选择读取。

报告列表列出所选策略的不同本金和区间实验，默认主报告为截止日期最新一份。选择“查看分析”进入单份报告，选择另一份“设为对比”后可打开比较；“返回回测列表”继续选择。策略当前资金与历史实验本金分别取自各自发布。读取请求包含排队和完整原件校验，切换后等待该次读取结果；超时或繁忙时保留原归档，按页面按钮重新读取。

市场观察表格与导出绑定相同数据版本和日期范围。页面金额按元/万/亿等中文量级显示，可查看精确原值；CSV、JSON及JSONL保留原数值语义、单位和缺值。导出用于观察与离线分析，数据的历史当时可得资格以来源说明为准。

## 停止、恢复与升级回退

使用原`observer-web.py stop`正常关闭Web；该入口回收App的读取线程和个人自选资源。未知或超时沿同一控制身份查询，保留本代日志和退出记录。WT及独立更新服务分别通过自己的正常停止入口维护。

升级先记录旧/新程序、SPA、读取配置和外部数据身份；正常停止旧Web，使用新安装和新控制目录启动，沿用个人自选与数据路径。随后核搜索、行情、账户、策略、既有报告、市场观察和系统状态。回退使用保留的兼容安装及其原配置，正常停止新Web后再启动旧版；具体兼容范围和命令以对应交付记录为准。

WT或市场观察数据的恢复与回退分别沿其原存储、快照和控制身份处理。委托结果未知时保留原命令并先查原委托，数据版本切换不能撤销外部副作用。真实委托、撤单及生产发布继续按对应明确授权执行。

## 独立策略的线上表现

策略页按当前WT实际发布的策略身份显示线上标记、持仓、成交和目标仓位变化。选择器里的历史回测版本与当前线上版本分别显示；新策略启用后的记录才逐日积累，首次100万元空仓点来自其独立资金声明。

手续费未确认时，页面明确显示参考净值及棕色虚线；实际手续费补齐后按发布值显示实际净值。缺少持仓报价时保留最后已核点和原时间，当前估值显示缺口。相对配置资本的变化率属于参考值；缺少连续资金流时，投资收益率继续显示未知。

回测曲线悬停直接显示当天持仓和买卖摘要，点击固定日期并展开详细内容；悬停不触发网络读取。正式入口沿observer-current/DEPLOYMENT.json和web-profile.json定位，升级后复核实际版本与18143一致。
