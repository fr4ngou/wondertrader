# 国信 QMT 维护、升级与回滚

类型：长期运行手册。适用范围：国信QMT终端、受管策略入口、通信Host与WT接入制品的维护。沿[发布与回滚规范](release.md)管理身份、授权、兼容和验真；终端/账户/在途命令的事实所有者参与相关窗口。

本仓库承接后续维护；独立Host/Agent制品和离线工具由本仓库维护。配对、源包安装与身份核验命令见[操作手册](guosen-qmt-operations.md)，实际发行资格和终端加载证据分别核对。备份、升级、回滚与活动实例操作仍按本手册的受控顺序执行。

## 维护前确认范围

记录要改变的制品、目标安装路径、券商版本、Windows桌面会话、依赖/协议版本和现有活动入口。分清行情只读、账户只读、策略计算、目标执行与历史数据；通信升级不会自行授予新的账户权限或执行资格。

先核停止新增准入、在途任务与未知提交、原回报摄取、旧写端/新写端唯一性及恢复依据。启动或恢复环境可能恢复此前已授权的自动流程，应保留前后事实；不能笼统记为“零交易副作用”。未知订单尚未解决时，保持其后继执行关闭并按原身份继续查证。

一次维护候选须具备：可追溯源码/构建身份、完整制品清单及SHA、配置/状态兼容说明、适用测试/独立审查、当前安装基线、备份和可用回滚候选。仅有某个脚本SHA、端口或终端界面不构成完整准入。

## 备份与保密

分别保存以下材料，标明创建时间、用途、源版本、SHA和恢复方式：

|材料|备份与恢复要求|
|---|---|
|受管包与QMT入口|保存当前完整文件清单和实际磁盘字节；包含必要依赖/协议生成物，不仅保存入口文件。|
|私有配置和认证材料|放入访问受控的备份位置，公开清单只记引用和摘要；恢复时重新核用途、配对和有效期。|
|Host/接入端持久事实|使用事实owner支持的一致快照，或确认owner已关闭后取得一致备份；保留日志/终态/恢复水位。运行中不直接复制数据库文件冒充一致备份。|
|终端用户数据与历史行情|保留原归属及券商支持的备份方式。代码维护不删除下载文件，不迁移或重置账户/日初/历史命令事实。|
|操作与故障记录|保存脱敏的活动版本、代际、未完成/未知工作、停止证明及验收证据。|

备份存在与可恢复分别核实。恢复测试使用隔离路径及合成身份；不在生产状态目录通过试恢复覆盖事实。旧包不能读取当前状态格式时，采用已验证恢复程序或前向修复，保持受影响入口关闭。

## 制品与配置核验

安装路径、文件集合、策略别名、Host与QMT包、协议/能力profile、配置摘要由单一受管发行记录给出。发布包不得隐式导入旧工程，Python兼容性按QMT实际解释器核验；终端版本号与Python版本分别记录。

可用Windows原生命令核对**已由维护计划确定的绝对文件路径**。以下变量由当前发行记录填写，不指向旧项目脚本；命令只读取文件。

```powershell
Get-FileHash -LiteralPath $ApprovedEntryPath -Algorithm SHA256
Get-FileHash -LiteralPath $ApprovedHostArtifactPath -Algorithm SHA256
```

这两个单文件摘要只核所指文件。源包导出/安装核验其白名单，`verify`进一步核配对中绑定的Host/Agent源和生成文件；解释器、完整发行依赖及实际加载仍依发行清单和运行证据核实。路径、依赖文件集合或实际加载来源未核全，维护条件即未满足。私有配置不输出正文；认证秘密不进入Git、截图和故障报告。

## 升级顺序

1. 固定本次候选与当前基线；确认备份、回滚兼容和停止条件。复核受影响入口授权及现存策略/账户活动。
2. 停止新增工作，保持原身份的终态/回报可读取；收束在途并隔离未知副作用。终端中各策略的停止有独立证据。
3. 更换已加载的包之前，等待相关QMT与策略自然退出，并由维护owner核进程路径、创建时间、桌面会话和完整归属。解释器缓存不能用磁盘新文件SHA代替；不热覆盖仍被活动实例使用的包。
4. 沿已交付安装器替换完整受管制品，保存旧版。安装器未交付时保持候选未部署；不使用旧仓库部署命令填补。
5. 关闭旧编辑器缓冲区而不保存旧文本；核新磁盘清单，生成并审核本轮私有配对。新连接使用新代际，禁止带旧会话重新运行。
6. 启动独立WT，由其配置声明带起Host并核本代际监听，再在QMT加载/运行配对入口；完成认证、允许的只读业务和WT实际数据采用核验。观衡独立读取，启停不控制Host。隔离Host直启按专项维护计划执行。
7. 按能力逐项验收正常、空、错误、断连与停止/恢复；保持未验能力关闭。账户/执行权或生产启用由对应授权和事实owner另行放行。

预算由实际发行配置拥有，不能通过延长连接/订单期限、降低新鲜度、增大每tick重任务数或取消签名来取得维护成功。只读行情探针成功也不能代替账户一致性、旧写端退休或未知委托恢复。

## 回滚顺序

出现源码/配置/代际不一致、认证失败、数据来源漂移、资源关闭未确认或业务验真失败时，停止扩大新版本准入并保存原件。

先核旧候选能读取当前状态及协议，收束新增/在途，保留原命令ID、终态和已有回报。仅替换回滚计划批准的制品与兼容配置；不会因代码回滚撤销已发生的外部委托或成交。禁止把旧数据库/账本整体盖回当前金融事实，也不恢复已过期的会话、一次性许可或旧连接代际。

按升级相同的完整进程归属及自然退出边界完成替换，使用重新审核的新配对代际启动Host及QMT；重新核实际加载身份、只读数据、状态兼容与退出确认。未决事实或旧版兼容不足时保持相应入口关闭，转入[排障](guosen-qmt-troubleshooting.md)及受控前向修复。

### 订单查询关联的状态兼容

采用[订单查询关联R21Q](../specs/qmt-shm-trading.md#qst-r21q-当前订单查询观察恢复)的Host在原通信表trade_order_links增加query_request_id、query_row_index及query_result_sha256三列，并引用原read_operations记录。reference.v1响应保持兼容，只说明对应接口形状保持；旧Host使用精确列集检查，会拒绝打开已增加这三列的Journal。

升级前在隔离副本验证当前Host、候选Host和明确回滚候选对同一状态格式的读取行为，记录匹配制品身份。已经产生新通信事实后，保留完整新Journal与原查询结果，优先使用已验兼容版本或前向修复。删除新增列、删库重建或覆盖为升级前备份会丢失原指令及查询关联，不能作为版本回退步骤。查询记录与关联引用共同保留；后续保留策略需先提供引用完整性和未决操作恢复验证。

## 工具与维护能力对应

|能力|操作入口与边界|
|---|---|
|私有配对与物料生成|`check/pair/verify`；显式schema、创建时访问控制、拒绝覆盖和摘要绑定；核验不授实际QMT加载资格。|
|源包安装与身份审计|`export-agent/install-agent`及`verify`；完整发行清单、终端保存入口和实际加载分别核实。|
|专用Host启动/停止|日常由WT运行入口及其Host owner管理；接收/并发预算和首次关闭期限明确。配对`host.py`直启用于声明的隔离验收，WT行情接入沿明确Parser及配置。观衡只读。|
|备份/升级/回滚|按本手册受控步骤与发行清单执行；没有可据成功回执自动替换活动终端的命令，不以代码回滚覆盖新金融事实。|
|状态/故障采集|离线`check/verify`、Host诊断及WT来源/请求原件分别使用；统一运行诊断与实际加载审计以发行记录列出的工具为准。|

离线工具和启动命令不授操作其他活动终端或Host的权限。维护记录绑定具体发行命令、安装路径、原件及适用验证；缺少某层证据时明确该层未取得资格，不由其他层成功代替。

迁入源及取舍见本仓库`build/guanheng-workspace/guosen-qmt-docs-001/SOURCE-MAP.md`；旧源码路径仅作追溯。日常顺序见[操作手册](guosen-qmt-operations.md)，异常恢复按[故障处理规范](incidents.md)。

## 客户端、解释器和API升级核对

按[内置Python手册](guosen-qmt-python.md)独立登记产品显示版、PE版本、实际解释器/DLL及SDK；公开更新记录、安装元数据和内置回调实测分别保存。比对[API目录](../modules/qmt-native-api-index.md)的已用函数签名/返回字段、调用阶段、ContextInfo回滚、线程及停止行为。Python库下载和libs_path不能作为解释器升级证据，外部XtQuant支持的新Python不能自动套用到内置。官方公告未说明的权限/版本变化保持待核，现有受限规则继续生效。
