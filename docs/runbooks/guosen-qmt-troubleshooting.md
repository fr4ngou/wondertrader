# 国信 QMT 与 SHM 接入排障

类型：长期运行手册。适用范围：终端登录、受管策略、共享内存Host及WT接入的只读分诊。依据当前安装身份、来源与请求事实判断；操作恢复沿[维护手册](guosen-qmt-maintenance.md)，故障记录沿[规范](incidents.md)。本手册不提供下单、撤单、修改账户或放宽风险的权限。

## 先保留事实，再定位层级

记录首次/最近出现时间、终端与包版本、受管入口/配置/代际摘要、Windows会话、请求ID/原命令ID、来源时点、错误码、影响能力及已做动作。日志使用脱敏身份；不输出账户明细、私有配对、token、签名秘密、完整命令正文或带凭据URL。

按五层分别核实：预期GUI进程及桌面会话；本会话交易服务器连接；账户授权；策略原线程回调与Host认证/来源；WT业务采用及相关执行资格。端口、窗口、一次成功读取与交易就绪各是不同事实。来源缺失或状态未知时先停止受影响的新准入，继续保留可读取的原终态和回报。

优先用[操作手册](guosen-qmt-operations.md)的`check`核配置、`verify`核配对/源身份；这些离线命令不连接终端，也不能诊断实际认证或报价时效。运行层使用受管发行记录允许的Host/WT诊断、界面、日志和Windows只读进程/文件摘要检查，不调用旧工程的doctor、qmtctl或部署脚本。

## 症状与定位

|症状|核查证据与含义|处理与恢复条件|
|---|---|---|
|终端未出现或多实例|预期路径、StartTime、SessionId及登录桌面；快捷方式可能指向另一安装。|先查归属，由终端维护owner处理；不凭名称杀进程或强制提权。|
|交易服务器初始化前失败|本会话日志、单实例、DNS/链路与已有代理分流规则；与账户拒绝分开。|保留错误与当前网络配置；受控只读重试。网络规则由网络owner核实，不通过关闭全局代理/TUN或改变其他程序通路试错。|
|初始化后多个账户同时出现8202/811/6100|对齐同一时间窗及交易服务器阶段，优先排查券商后端/账户登录服务；单条错误码不足以认定根因。|记录受影响账户数量和脱敏错误时间段；持续时转国信支持。重启恢复只证明新会话恢复，不证明服务节点已切换。|
|仅一个账户授权失败|该账户与其他账户的授权结果、许可及本会话日志。|由用户在券商受控界面处理凭证/权限；不借其他账户或改配置绕过。|
|策略启动等待且行情处理缓慢|核同进程的自定义图表指标是否在每次报价/最新bar做全历史读取、Pandas逐行转换或全量重算；用有界、无局部变量的线程采样定位，记录不完整采样范围。|先保留指标及来源身份，在已授权范围临时停用单个重指标做前后对照；根因模块按增量或有界刷新实现，复验数值一致及其他策略回调。重新启用与来源实时资格分别验证。|
|策略看似运行但无回调|核入口/依赖实际加载身份、doRun及stop日志、原ContextInfo/线程；编辑器可能仍是旧文本。|不反复点击；按受管材料重核。需要替换包时先按维护流程自然退出，不热覆盖。|
|Host监听ready但无Agent|ready只证明本代际SHM对象已发布；检查配对、Windows会话、实际策略状态，以及发行选择的常驻或单连接生命周期。|WT常驻模式持续等待，QMT登录后启动原匹配策略，核新认证和真实读取。单连接模式沿其原有限期限关闭。配对物料变更时重新准备核验；常驻来源晚到由现有owner继续处理。|
|peer_claim存在但认证未过|peer_claim仅证明对端到达；进一步核challenge/MAC、协议/profile、路由/配置/包摘要和代际。|固定失败关闭；核配对完整性和私有材料引用，不打印秘密、不关验签。|
|对象被占用、代际或头损坏|核本代际owner与创建身份、现有映射/句柄状态及损坏/abandoned诊断。|隔离本代际并由owner收口；不手动改共享头、删对象名、覆盖锁或沿同名猜测恢复。|
|连接建立但读取超时|核原请求ID、准入/排队、实际策略回合、原生调用、Host持久终态与返回阶段。|按原ID查证；不以超时推定未执行，不换ID重复投递。资源满或原生调用长耗时按根因处理，不加重每tick负载。|
|读取成功但WT无有效数据|核WT是否加载当前制品的`ParserQMTHost`，认证bound-read、source/session/generation、schema、证券/单位、源时间及实际采用证据。|原ParserQMT/QmtReadTransport的capabilities/health契约与新Host不同，单换URL不足以兼容。核新插件、显式profile和实际binding；拒绝不匹配的结果，不假造数据或回退旧服务。|
|账户/委托/成交为空或不可用|各datatype自己的查询时间/会话/范围及完整性；空持仓/委托/成交可合法，账户未取得另报不可用。|保留原空/缺失语义；不以零填补缺字段，不把跨时点记录拼成一致完整快照。|
|报价不新鲜或盘后不满足交易条件|区分策略回调存活时间与交易所源行情时间；检查市场阶段及来源资格。|保持新委托阻断；盘后缺新鲜报价不等同Agent/Host宕机。不得用当前墙钟覆盖源时间。|
|stop超期或窗口已消失|核资源owner的线程、句柄、进程退出/等待证明及未完成工作。|保留owner和依赖，继续受管确认/升级处理；窗口消失或stop请求已发不能当收口成功。|

供应商日志中的`AI_ETF parse error`、customModules缺失、nil-call、`not all accounts entrustable`或threadpool提示可能伴随启动/断连。只有它们与上述权威状态持续失败及实际影响相关时，才升级为根因证据；不以字符串计数替代分层状态。

## 断连、过期与未知委托

SHM断连、认证到期或Host重启终止本连接代际。传输恢复与业务恢复分开：原持久事实可能已提交，旧Session不能靠重新握手延长；新连接需新的受管代际及相同业务事实owner的恢复证明。

WT选择常驻生命周期时，由原owner撤销旧代准入、等待已进入的工作及资源关闭，再建立新认证代际。QMT重开可继续使用本发行原已核配对；客户端重新取得新binding。配对文件、解释器、源码或权限配置发生变更时，按维护流程生成和核验相应新物料。单连接入口继续遵循原有限生命周期，运行状态须明确区分两种模式。

对正在提交或结果未知的原命令，保留原command_id/序号、准备/许可身份及Journal终态。通信超时、404暂未取得、进程退出、原生同步函数返回都不足以证明“从未提交”或“已成交”。按原owner读取确定事实；未有可信未调用/未受理证明时，保持后继执行关闭，不新建ID、自动重投、重新签许可或换通道重放。

本轮只读接入没有命令权。历史命令/账本、账户日初、外部手工归属和单执行权的迁入/恢复未闭合时，应明确缺项；不得为了健康检查通过而重置Journal、清空队列/账户事实或合成reconciled。

## 恢复验收

恢复按本次故障影响逐层核：当前安装/加载身份；终端/交易服务器/账户授权；新代际监听与认证；原策略线程回调；允许范围内的真实只读结果；来源时间/完整性与WT实际采用；旧请求终态连续；资源有界关闭。需要执行能力时还必须由相应授权和事实owner独立核交易前提，本手册不放行。

有新数据后持续观察配置规定的窗口，保留正常、空、失败及恢复样本。与最初基线对照实际变化，确认没有重复业务、来源回退或未知事实被覆盖。仅有一次200、日志无新增错误或旧探针的成功报告不足以关闭当前故障。

## 工具范围与追溯

`check/verify`成功只授离线配置/物料身份；失败统一给去敏工具错误，不回显私有输入。记录具体子命令、退出码、发行清单及失败阶段，不把同一固定错误文字直接当根因。运行诊断另需脱敏的Windows会话与代际、监听/认证/业务层、source/session/行情时间、原请求终态、预算/背压和资源owner。工具未覆盖的层由相应运行原件补足，实际加载及真实数据仍分别取证。

`run-attestation-012.json`已有历史证据仅限国信指定版本的SHM行情只读，明确`host_order_ready=false`，未作历史迁移或平台切换。配套材料实际名称为`RUN-012.md`，已静态核对；记录终端外HTTP、终端内SHM及原策略线程、专用Host所有权与新配对要求。原先所给`RUNNING-012.md`名称未命中，已按实际文件追溯。本次文档迁入未采集当前进程状态。

逐源路径、SHA、采纳/退出/待补及静态验收见本仓库`build/guanheng-workspace/guosen-qmt-docs-001/SOURCE-MAP.md`。旧路径只作来源追溯；操作步骤见[日常操作](guosen-qmt-operations.md)。

## 原始日线正常、等比复权价格无效

先保留同一证券、日期、复权模式、原 SDK 参数、原始回包、因子回包及缓存摘要。分别检查 `none` 和 `front_ratio` 的 OHLC，再检查该证券的历史除权事件及事件前收盘覆盖。当前窗口的原始日线完整，历史事件所需的前收盘仍可能缺失；供应商生成的零值或非有限系数会影响等比复权价格。适配器应继续保留原值并报告无效字段。

在已有行情补齐授权下，通过 WT 管理的历史准备入口补该证券所需的日线，起点覆盖相关除权事件前收盘。按当前已认证接口的 `max_calendar_days` 分段，分别持有原请求 ID 和截止。观察返回 pending 时继续查询原请求；一次 SDK 调用已返回还需要实际复读验证覆盖。补齐只由来源接口写其缓存，应用保留原缓存和回包；生产数据的删除、因子替换和清库另需明确授权。

补齐后按原窗口、复权方式复读：原始 OHLC/量额应逐值核对；复权 OHLC 应有限且为正，并通过正式适配器；事件现金红利及送转等原字段与修订的系数分别比较。核对除权系数时保留理论参考价和实际精度，避免把分位参考价带来的舍入差异当成坏数据。补齐前后的观察各有来源时间和摘要；消费修订时显式登记单证券后继，保留原批次。

具体已复现及恢复的边界见[单证券等比复权恢复证据](../evidence/2026-10-31-qmt-single-front-ratio-recovery.md)。该样例只确认相应供应商版本和证券的行为，其他无效数据仍按实际字段定位。
