# 发布与回滚规范

类型：长期规范兼发布操作清单。适用范围：服务、程序、原生库、插件、配置和数据格式的运行版本变更。

## 发布身份与授权

区分候选构建、内部验证、制品分发、部署和生产启用。每次发布记录源提交/差异摘要、构建环境、制品哈希、配置版本、依赖、目标环境、授权范围、操作者与回滚候选。发布授权不自动授予账户操作或新的交易权限。

具体渠道、命令、健康地址、存储和启停方式由目标环境的发布记录提供；未建立部署入口时保持待验证，不使用其他系统命令代替。

正式制品基于已集成正式主干的干净候选和不可变注释发行标签，记录完整 source commit；构建目录允许固定提交检出，现场运行环境只接收可验证制品。实际发布器需校验来源、标签与内容，门禁工具未交付时保持相应自动化资格待验证。

原生组件按[二进制部署手册](native-deployment.md)管理包、逐文件清单、动态依赖、稳定状态目录和实际加载身份。容器组件记录镜像 digest；两类组件通过兼容清单组成同一系统发行。

## 发布前

组合升级先核全部反向精确依赖及实际运行解释器绑定，在停止旧服务前完成pip check和真实前后代码身份预检；执行CLI与无控制台worker分别按其实际python/pythonw及基础解释器计算身份。已知活动单、撤单受理和券商终态分别记录，按目标组件的真实恢复前提决定切换时机。

1. 核对任务最终规格、代码审查和适用验证；对未覆盖范围作明确决策。
2. 构建可追溯制品，核对编译器、运行库、架构、插件 ABI、SDK 及许可证。公开分发范围核查敏感资料与第三方资格。

   复用旧源码闭包或覆盖文件时，对比当前已合入源码，逐件说明采用或保留依据及摘要；未分类差异须在构建阶段解决。Python运行器可用`python -B scripts/runtime_composition.py --help`的逐件核对入口。先用短区间验证实际计算、完成归档及读取者，再执行耗时长区间；回测计算完成和页面归档可读分别核验。
3. 确认配置/协议/数据格式兼容性、升级顺序、状态备份及回滚可读性；备份可恢复性需有依据。
4. 列出实际用户入口、核心数据、关键操作、正常/空/异常/恢复场景和停止条件。
5. 涉及活动执行路由时，核实新增准入、未完成命令、未知提交、回报摄取和唯一活动入口的切换条件。

## 部署与启用

后台服务通过正式服务入口启动，核实启动命令退出后服务仍真实存活。一次性测试启动器可能在结束时回收整棵进程树，适用于隔离测试；常驻服务的所有权应交给正式生命周期入口。状态文件和ready收据与实际PID/创建身份、监听和业务读取共同验真。

按已验证环境步骤分阶段替换，保持状态及审计连续。核实实际加载的程序/插件/配置身份；仅在适用依赖与业务资格满足后开放相关入口。

每个操作记录时间、目标、结果及异常。数据格式升级及清理分别按其授权和恢复方案执行，避免通过重置生产事实获得表面健康。

## 发布后验真

受管父进程ready后继续核实际Native已创建、ready收据、业务观察及后继状态；只有父端早期ready而Native随后失败时，发布状态记为未恢复。独立组件分别记录上线结果，部分成功与整体主线完成分开说明。

先检查进程、依赖、连接及资源，再验证用户实际入口到真实下游、核心数据和主要操作。中文界面核实业务说明、空状态、异常提示和恢复结果。

从本次启动/切换时刻检查受影响组件的新日志、持久异常摘要和退出码，沿关联身份核查未解释ERROR/WARN、重复失败及仅存内存的输出缺口。记录组件、时间范围、路径、发现/处置和未覆盖项。空日志先核是否启用并实际落盘。数据/策略变更核逐角色输入覆盖、最近有效计算与业务结果，正常无信号和输入缺失分别登记。这是开发发布验真要求，不新增用户策略上线人工审批。

健康接口、容器运行、路由 200、模拟成功与生产业务成功分别登记。观察窗口和阈值来自适用服务目标；出现停止条件时暂停新增准入并执行回滚或修复流程。

## 回滚

回滚核对旧版对当前配置和状态格式的兼容性，按既定顺序停止新增工作、处理在途与未知副作用、替换版本并恢复入口。继续摄取已有订单和成交，保持原身份与账本；版本切换不会撤销已产生的外部副作用。

旧版无法安全读取当前状态时保持受影响入口关闭，采用前向修复或已验证恢复程序。恢复后重新执行发布验真，并记录实际版本与剩余风险。

每次发布填写[发布记录模板](../releases/TEMPLATE.md)，在[发布索引](../releases/README.md)登记，关联[证据](../evidence/README.md)及适用故障记录。

## 用户入口保持

升级、回退和独立发布沿用既有用户地址及端口。部署前读取稳定profile与DEPLOYMENT记录，部署后核实际监听和用户URL一致；候选验证使用独立测试入口。正式端口被占用时先核占用进程和原实例，不自动换一个端口发布。用户明确同意后才变更正式入口，并同步操作手册和所有访问入口。

本机观衡的固定正式入口见[观衡操作员手册](guanheng-operator.md#启动与独立运行)。

## 通用问题与复查入口

发布问题在责任层修正后，将可复用检查并入下表；单次命令、错误及现场证据留在对应发布记录。后续发行直接执行适用行。

| 曾出现的问题 | 下次发布的具体检查 |
|---|---|
| 重用旧源码闭包漏带已合入修正 | 构建前逐件对照当前集成源码，显式登记保留成员；先短区间走完生产者、归档及正式读取者，再跑长作业 |
| 后继增量编译仍被最初源码清单代表 | 每次增量保存实际源码、头、对象/库及产物摘要的新收据，显式记录复用；保留初始清单的历史身份，接收时核当前输入与实际已部署制品 |
| 开始构建后，模块交付者继续修改同一源码 | 交付明确冻结时点和最终摘要，构建绑定最终集成提交；后续修正先交差异再由构建owner接收，来源变化校验失败时保留失败目录并从新固定输入重建 |
| 全目录来源检查被未参与产物的验证文件变化触发 | 先冻结全部声明输入；保留原失败及原快照，独立核实际编译、头依赖、链接和自定义命令闭包。能证明完全无产物影响时另立有范围的制品验收，原全目录结果保持失败；参与产物或影响未知时从新固定输入重建受影响目标，禁止改写原RESULT或冻结来源 |
| 测试JSON显示success但命令非零或漏掉所选套件 | 同时核命令退出码、实际登记的文件集合和断言数量；异常或缺套件不算整组通过，复验只覆盖未完成部分并保留原失败材料 |
| 验证导入生成缓存，改变冻结安装 | 使用独立验证环境及隔离/禁字节码选项；按[验证规范](../development/verification.md)核新增文件，保留完整性检查 |
| 一次性测试启动器结束了新常驻服务 | 通过正式服务入口移交所有权；启动命令退出后重新核实际PID/创建身份、监听和业务读取 |
| 关闭收据出现时进程仍在退出 | 在原停止总截止内确认实际进程退出，再准备需要其退出的交接；保留原收据，不用瞬时查询代替完整关闭 |
| 只更新生产者，读取侧仍使用旧契约 | 独立服务分别发行，逐项核实际安装版本、模型/报告协议及读取依赖；用本次真实输出经过正式消费者验证 |
| 读取发行的来源声明仍标成执行发行版本 | 同步自身METADATA、精确依赖、锁及包内来源声明；通过普通安装验证，来源身份严格校验保持 |
| 状态文件ready掩盖进程丢失或业务未运行 | 分别核进程存活、依赖连接、有效输入、实际计算/执行及页面；恢复序号和历史成交不能作为本代自然运行证据 |
| 阶段状态里的旧pending被误判为整个任务停住 | 同时核原任务身份、实际进程及相邻观察的完成槽/文件变化；共享额度不足沿原未消费结果的owner恢复，保持原请求、回执和容量，不清队列或重复提交 |
| 更新进程heartbeat正常，业务窗口却连续发布失败 | 同时核最近一次成功发布、应完成窗口及实际失败收据；沿生产者目录增长和发布步骤定位原因，不能仅检查调度进程存活 |
| 服务配置已更新，桌面快捷方式仍指旧解释器或旧操作组 | 发布后重新读取实际快捷方式TargetPath、Arguments和组配置摘要；启动与停止入口同时更新，保留旧入口备份 |
| 数据批次已发布，来源恢复后仍停在未知覆盖分母 | 核已发布结果的完整性和来源状态，由原owner沿原修订链恢复；以各类别实际分母和真实数据读回验收，保留原请求 |
| 维护脚本误用缺少SDK的独立读取解释器 | 执行前核工具自身导入及对应维护环境；读取服务和交易运行包保持独立，配置生成工具不据业务包名称猜依赖 |
| 控制台编码显示被误判为源数据损坏 | 先核原始UTF8字节和JSON的Unicode码点；独立Python诊断使用ASCII JSON或显式`-X utf8`，再决定接口或数据修改 |
| 页面列出回测记录前等待全部报告的完整绩效 | 分别计时目录、可选列表、主报告和对比报告；列表只读完成身份绑定的轻量归属，详细计算只覆盖当前选择，核实际请求集合 |
| 公开数据运输中断被泛化为解析错误，界面仍显示旧失败时间 | 先核是否取得完整HTTP原件，再归类运输或解析；代理按角色和官方主机显式配置，保留其他来源代理；分别展示计划回执和当前数据发布时间，并从正式页面核新快照 |

| Windows CRLF被Git空白检查视为整行尾随空白 | 先核仓库原字节与行尾约定；对保留CRLF的范围使用`git -c core.whitespace=cr-at-eol diff --check`，保持已审冻结字节；真正尾随空白继续修正 |
| 诊断工具传入错误的读取预算，误报状态不可用 | 先读实际SDK入口及预算合同；64KiB状态使用原专用读取器，大投影沿各自已声明接口读取；检查真实reason与调用参数后再判断服务故障 |
| 延迟打开的正常日志尚无文件，被核验脚本视为读取失败 | 按实际日志owner区分未发生输出、写失败降级与已有记录；回读原故障/关闭收据，不能用空文件或文件不存在证明业务健康 |

| 验证脚本按仓库新SDK调用旧发行尚无的函数 | 执行前核实际解释器、模块位置、发行版本、函数签名及实际请求/响应DTO；使用该发行已有公开入口，验证工具不通过替换正式SDK来绕过版本差异 |

本表属于开发发布工作，不增加用户新增或修改策略的人工上线审批。

| 配置变化后的遗漏 | 下次发布的具体检查 |
|---|---|
| 修改被引用的目录文件，App仍缓存旧实例 | 查明配置在启动时加载还是动态读取；启动加载型按正常生命周期重载读取侧，核正式接口返回的新实例身份和嵌套业务runtime.ready |
| 发布者换了工作目录，Reader仍绑定原owner目录 | 切换前将发布者directory/publication与Reader的source_root/status_file/publication_file逐项核对；原状态恢复按其原发布字节身份处理。包升级优先保留已验证数据接线，路径变化另核完整恢复，不改来源校验 |
| 辅助合并覆盖了原生价格输入身份，模型读取通过但原Reader拒绝 | 合并后核input_sha256仍等于原NATIVE-READ.inputs.sha256；辅助与完整业务输入沿所属身份更新。以实际原Reader和纯核两端验真，窗口JSON可解析只证明其中一层 |
| HTTP200或外层available掩盖嵌套组件closed | 按接口层次核具体运行状态、业务就绪、进程创建身份及真实数据；保留外层可访问与下游运行两类结果 |
| 预检断言失败后，Shell继续后续变更 | 把依赖操作放入同一受检查控制流；命令非零或预检失败立即停止变更。瞬时读写竞争沿原截止重新读取，核实后再执行 |
| 现场脚本凭印象读取控制器返回字段或遗漏控制目录 | 先核该发行CLI的实际JSON合同及维护前置目录；沿已完成的停止回执续接，保留原失败输出；恢复脚本不重复安装或重复启动未知代 |
| 把首次bootstrap配置当成已纳管服务的重启升级配置 | 区分正常重启与显式配置升级；重启沿前代generation恢复。配置升级准备原账transition及新的完整接线，核实际生成代中的descriptor、Reader和配置摘要，再登记当前入口 |
| 验证脚本假设每代配置都叫generation/runtime.json | 沿原generation.json记录的runtime_configuration及摘要定位真实配置；首代升级的bootstrap与后继重启可使用不同物理位置，核同一权威引用 |
