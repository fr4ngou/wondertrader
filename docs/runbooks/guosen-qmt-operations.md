# 国信 QMT 日常操作

类型：长期运行手册。适用范围：WonderTrader使用国信QMT终端的登录、受管策略加载、通信、启动与停止。WT管理终端外Host、行情、账户与执行组件，观衡独立部署并只读观察；终端操作者负责登录及界面动作，部署维护者负责制品、私有配对及WT配置。运行所有权沿[ADR-0016](../architecture/adr/0016-independent-wt-runtime-and-observer.md)，组件命令和关闭顺序沿[WT手册](wt-independent-runtime.md)。

工具入口由本仓库独立连接包提供，具体制品、安装资格与实际终端加载证据按当前发行记录核对。工具可执行、离线核验成功、实机只读与交易资格分别登记；行情读取不授账户或委托能力。操作活动实例、账户、权限与交易沿具体授权。

## 登录前先核对运行对象

使用受管安装登记中的终端路径、客户端版本、Windows桌面会话和策略入口。确认当前已有实例及其用途，再决定是否启动；避免为排障多开同一账户环境。进程存在、界面可见、通信认证、数据可用和交易就绪分别记录。

普通用户可用以下Windows只读命令查看终端实例；它不启动或停止程序，不读取登录凭证。路径权限不足时保留“未能核实”，由桌面用户补核。

```powershell
Get-Process -Name XtItClient -ErrorAction SilentlyContinue |
  Select-Object Id, ProcessName, SessionId, StartTime, Path
```

预期绝对路径及会话来自当前受管安装记录；本手册不固定某台电脑的D盘软件目录。启动使用该安装记录对应的快捷方式或程序。登录账户由用户在券商界面输入，运维日志使用脱敏标识，不收集密码、验证码或认证秘密。

登录后依次核实：本次交易服务器连接结果、当前账户授权结果、行情来源、策略状态。 逐个确认目标共享内存策略已实际启动：待运行列表和启动三角控件仅表示已登记；再核本次运行记录、认证绑定、递增策略线程心跳和一条真实读取。终端、报价进程或Host进程存在，分别只证明各自进程状态。账户授权失败时按[排障手册](guosen-qmt-troubleshooting.md)分层处理。盘后没有新鲜报价属于数据资格问题，应与终端离线分开显示。

## 准备策略与私有配对

Host运行在QMT终端进程之外。终端内仅由受限策略的原线程调用QMT API，并经SHM与Host交换消息；已有校验中的签名HTTP发生在终端之外，不允许据此在终端里开启loopback网络。WT对Host的接入协议还需匹配验证，不能只替换旧HTTP客户端的URL。

### QMT重开及恢复连接

先按当前WT发行记录核对Host生命周期。常驻模式由WT管理等待、旧连接清理和新认证；QMT登录及策略启动沿用户实际操作时间完成，每项业务请求继续使用自身截止。原单连接入口按其有限期限运行。

1. 关闭终端前保存当前运行状态；正在提交或结果未知的委托沿原身份核查并保留，由执行owner恢复。
2. 常驻WT实例保持原运行配置及通信owner。终端离线期间观察等待/断连状态，资源故障沿排障流程处理。
3. 重新登录QMT后，按本发行受管策略清单启动匹配的原正文，核对策略本次真实运行状态；配对、源码和权限保持当前已验物料身份。
4. 核新认证binding、递增策略心跳，以及授权范围内一条真实行情或账户读取。原运行进程、ready及页面存在分别只证明对应层状态。
5. 核WT实际采用的新结果和来源时间。闭市报价可以保持上一交易时点，策略心跳和来源报价时间分别表达。未知金融命令继续沿原owner查询，通信恢复保持原命令身份。

配置或安装物料需要改变时，再走下文准备、核验及维护流程。原连接代际终止由常驻owner处理，源程序晚到沿常驻监听恢复。

每个活动入口对应明确用途：行情只读探针、账户只读接入、或另行取得执行资格的策略。只读入口不能因登录成功而扩大为下单入口；`market.full_tick`能力也不能证明账户查询已接通。

维护者交付一套相互匹配的材料：

- 已审源码/制品及完整文件SHA、Python兼容性和安装位置。
- 本轮Host与QMT入口的私有配对材料、配置摘要、协议/能力profile、Windows会话与新连接代际。
- 明确只读能力、预算、认证密钥引用和资源所有者；不把秘密写入公开清单。
- 具体启动、就绪、停止和回滚步骤，以及各阶段的停止条件。

物料生成、核验与启动采用下面的独立工具；缺少当前发行记录或实机加载资格时保持等待受管材料。凭证经受管私有通道注入；IPC认证、业务签名、执行许可等秘密保持各自用途。

## 复用其他既有安装

既有install-008与本仓新发行分别操作：前者按已归档原手册使用同安装的配对Host/策略和Journal，先Host后策略；本仓新发行采用下面的独立工具及显式版本。两者配置和生成物保持各自身份。完整正文内存加载/内建mmap为受限终端接入方式，当前来源、能力及验收边界见[手册核对](../migration/qmt-successor-source-handoff.md#用户指定手册再次核对)。

先核该安装的HTTP操作契约、能力白名单、受限策略来源和解释器身份。通用operations接口与本仓read-binding/bound-operations接口分别按显式版本适配；路径、端口或健康接口相同不能授协议兼容。既有安装引用旧项目解释器或运行源码时，保留其当前状态，先准备本仓独立发行与搬迁验证，再按维护授权替换。当前交接与待验差异见[接入调查](../migration/qmt-successor-source-handoff.md)。

## 受限券商的无文件入口

券商限制策略读取本地文件时，采用完整源码嵌入的内存策略及builtin-mmap传输。配对材料必须包含运行依赖闭包、目标内置模块/解释器身份及CPython许可；QMT加载完整正文后，策略不再从磁盘导入外部包或配置，不加载外部DLL，不访问网络。HTTP、Journal及包文件读取归终端外Host和维护工具。

本仓`pair`通过显式transport.kind选择加载方式：旧shm生成磁盘入口与v1配对，builtin-shm要求目标SDK元数据和CPython许可，生成完整正文与v2配对。受限券商使用后者，并核发行记录中的精确制品及实机资格；离线verify成功保持qualified_in_qmt=false。已运行的外部安装保持原位；核对其实际传输类型、私有配对及能力，不在排障时覆盖策略或替换Host。来源及缺口见[交接核对](../migration/qmt-successor-source-handoff.md)，要求见[QSW-R12](../specs/qmt-shm-wt-binding.md#qsw-r12-受限终端无文件启动)。

## 离线准备与核验命令

以下为命令形状，尖括号内容由当前发行记录给出，均不是可直接粘贴的真实路径。`HostPython`属于终端外的独立Host安装；`AgentPackage`是新安装目录内实际含`__init__.py`的`guanheng_qmt_shm_agent`包目录。

```text
<HostPython> -I -B -m guanheng_qmt_shm --help
<HostPython> -I -B -m guanheng_qmt_shm export-agent --output <新Agent源ZIP>
<HostPython> -I -B -m guanheng_qmt_shm install-agent --archive <Agent源ZIP> --output <新Agent安装目录>
<HostPython> -I -B -m guanheng_qmt_shm check --config <私有Host配置>
<HostPython> -I -B -m guanheng_qmt_shm pair --config <私有Host配置> --agent-config <私有Agent配置> --installed-agent <AgentPackage> --output <新配对目录>
<HostPython> -I -B -m guanheng_qmt_shm verify --directory <配对目录> --installed-agent <AgentPackage>
```

`check`验证配置及凭证引用，`export-agent/install-agent`验证白名单源包，`pair/verify`绑定Host解释器、Host/Agent源与生成文件身份。它们不启动终端、Host、共享内存或券商API，不打开通信Journal；成功仍保留`qualified_in_qmt=false`和`order_ready=false`。输出目录独占新建，私有配对在创建时设置保护DACL；保持其受控访问，不输出文件正文。

配对生成`host.py`、`strategy.py`、`policy.json`与`manifest.json`；内存v2另含`CPYTHON-LICENSE.txt`及memory_runtime身份。显式内存命令在原pair参数外增加`--memory-sdk-manifest <目标SDK元数据JSON>`及`--stdlib-license <CPython许可>`，详见连接包说明。SDK物料在终端外准备，配对生成器不自动启动解释器。`strategy.py`含私有内存bootstrap，交受控QMT加载；`host.py`由生成时绑定的Host解释器运行。移动包、解释器或生成文件后重新核验或新建配对，原manifest不自动获得新身份。完整字段、逻辑字节/并发预算及API详见[连接包说明](../../connectors/qmt_shm/README.md)；物料核验不能替代实际加载与资源关闭证据。

在QMT该版本的策略导入/管理界面，选择已核验的受管入口文件，核对策略名、文件身份及用途后加载。只加载运维计划列出的入口；不复制整套旧项目，也不把业务源码路径临时加入解释器搜索路径。实际导入菜单与保存行为须在对应券商版本验收。

策略编辑器可能保留旧内存文本。外部部署已替换文件后，旧编辑器提示保存时选择不保存并关闭；再次打开前先核磁盘SHA，避免旧缓冲区覆盖新入口。磁盘SHA只是文件身份，实际运行仍须核对本次入口/配对摘要及回调证据。

## 策略保存与执行方式

按[迅投官方界面说明](https://dict.thinktrader.net/innerApi/interface_operation.html#策略运行)，编辑器中的“编译”负责保存 Python 策略，不检查语法或引用；Ctrl+S 是保存快捷键。部署时分别核受管生成文件、编辑器保存结果与实际运行回调。外部文件已经替换只证明磁盘身份，既有运行项是否刷新必须通过该券商版本的实际加载证据确认。避免用反复运行按钮代替保存与装载核验。

官方说明中，“独立 Python 进程”勾选后将正文作为 main 执行，init、handlebar 等平台回调不按通常方式触发；常规回调策略采用对应的导入执行方式。维护时只读核对当前模式与发行要求，模式调整按维护授权执行。程序化 run_strategy_file 属于另一公开入口，不能用其运行成功代替内置策略交易页验收。

生成器的局部/全局回调发布要求见[QSW-R15](../specs/qmt-shm-wt-binding.md#qsw-r15-策略回调的命名空间发布)。模板版本变化后保持旧配对原件，并以新物料身份重新核验；保留原回调函数及其上下文，不通过重复初始化或重新赋造 ContextInfo 绕过装载问题。

## SHM启动顺序

1. 维护者先核对当前活动入口、在途读取和未知交易事实。存在未决委托时按原事实owner处理，保持相应执行准入关闭。
2. 启动独立WT运行入口，由WT按components.host及所需交易/账户/分析组件声明带起相应Host，等待**本代际监听建立**。Host ready证明进程和监听就绪；QMT认证及业务读取分别核验。观衡可以单独启动或保持关闭。维护人员直接启动Host用于明确的隔离验收。
3. 用户登录QMT后，运行匹配的完整策略正文一次。系统常驻resident-read/HPR入口持续等待，日常无需在60秒内配合启动；单次连接、认证及业务请求仍按各自预算执行。旧单连接入口沿其已登记期限运行，维护时先核实际配对类型。Agent在原策略线程初始化并启动I/O owner，使用同一配对建立通道。
4. 核对对端到达、挑战认证、generation/路由/profile及能力一致。`peer_claim`仅表示对端打开过本代际；认证成功与消息处理另有证据。
5. 发起该入口允许的只读请求，核实际QMT回调、来源时间、完整结果及请求终态。再核WT接入端实际采用的数据与来源身份；只读Host成功不自动证明WT链路完成。
6. 分别登记终端、Host连接、行情/账户数据和策略就绪。没有授权与完整证据时，执行资格维持关闭。

获准启动本次专用Host时使用`<HostPython> -I -B <配对目录>/host.py`。它会创建/恢复本配对的通信Journal和SHM对象，并开始监听；不能当离线检查运行。Host只处理当前配对/profile明确开放的操作；行情、历史及账户能力分别以对应契约和真实读取结果核验，委托能力另按交易授权启用。其终端外HTTP与QMT终端内SHM分工保持。WT行情插件需明确配置`ParserQMTHost`及来源profile，不设置自动旧HTTP回退或默认100倍量换算。

连接等待与认证I/O各有自己的原期限。常驻入口在来源缺席时继续监听，连接失效后由原owner清理旧代并重新认证；配对文件与每次连接generation分别核对。旧单连接入口按其终态重建实例，策略文件或配置身份改变时重新离线配对。SHM不可用时不自动换回HTTP、TCP或管道，也不自动重放原生调用。

## 策略线程与API边界

受限QMT入口保持Python3.6.8标准库兼容。QMT原生API只在其原策略线程、对应ContextInfo和本次代际调用；HTTP线程、Host工作线程和自建线程不能直接调用行情、账户、下单或撤单API。

策略回调只推进有界内存任务、复制原生值和登记来源时点。SHM收发、等待、持久化和网络属于各自Host/I/O owner；回调内不联网、不读普通配置文件/数据库、不阻塞join。受限入口包括loopback在内的网络访问保持关闭；Host是否对外提供其他接口由其显式发行配置决定。

只读入口不调用`passorder`或`cancel`。查询账户的范围、类型及每类返回时点沿已验接入契约；“空持仓/委托/成交”和“账户未取得”分别表达。不能用零、当前时间、旧缓存或截断结果补齐缺事实。

## 停止与重新开始

运行/停止控件会随当前状态变化。每次动作只执行一次，随后核QMT日志中的本次运行/停止记录、原回调停止及Host实际连接收尾；不凭按钮图标反复点击。

系统停止沿[WT正常停止](wt-independent-runtime.md#正常停止及故障)：停止新增准入，保留原请求身份，由WT先收束执行和数据消费者，再关闭它持有的Host，核closed、实际进程和资源退出。停止观衡只关闭观衡自己的读取资源，WT继续运行。维护计划需要停止QMT受管策略时，在运行侧责任已收束后按该策略原stop回调关闭；同终端其他策略保持原归属。完整终端停机另核维护范围及未知委托。关闭超时保留owner和状态，转入排障。

重新启动使用已审核的新配对代际，重新验证加载身份与来源。旧操作的终态仍按原身份读取；新连接不能把未知操作当作新业务重发。

## 现场读取就绪与时间预算

认证read-binding成功后，先核原策略线程的两次递增且新鲜的agent_tick，再发本入口允许的读取。队列期限覆盖Host受理、异步认领、SHM传送及等待QMT原线程的时间，SDK执行预算单独核对；现场一秒回调不能直接采用毫秒pump合成夹具的队列预算。根据当前受管政策与实测选择一次有限总截止，并核queue+native+I/O满足control最大调用窗口；固定预算值归发行配置，按原ID恢复结果，不通过重发延长截止。

快照返回成功后检查来源time及新鲜度，盘后报价保持原时间。只读探针的能力白名单代表该次验证范围；正式入口还需账户/持仓/可用资金、委托成交查询和下单撤单的各自实现及验收。实际资格见[实机后继记录](../evidence/2026-10-23-qmt-memory-terminal-read.md)。

## 内存启动与磁盘访问的职责

完整策略正文由终端外准备工具读取受管源码并生成。QMT执行时，私有加载器从正文源码表加载依赖；模块中的伪文件名用于报错定位，不代表打开了该路径。Agent使用mmap(-1, …, tagname=…)建立系统内存支撑的Windows命名共享内存，不读取普通磁盘文件来通信；受限入口的open/FileIO被拒绝。Host包文件、通信Journal及HTTP接口属于终端外进程。核对实际transport与完整生成入口，避免将磁盘import旧入口用于受限终端。

策略运行回归与整个券商进程的系统级文件监视分别留证；平台加载策略和SDK缓存行为须按平台事实说明。实际账户能力与币种来源边界见[实机账户记录](../evidence/2026-10-23-qmt-memory-account-read.md)。来源币种空/缺省表达unknown，配置币种继续作为显式声明；原始金额保持，不能将unknown币种当成查询失败或编造来源值。


## 系统常驻连接入口

系统常驻入口的目标顺序为：系统启动Host并持续等待，用户登录QMT并启动配对策略，双方认证后核真实读取。Host属于同机系统组件，以独立进程运行；统一启动器负责管理，用户日常无需手动协调60秒。

显式只读v3配对及Host-only普通离线安装沿[连接模块](../modules/qmt-connection-lifecycle.md)。既有App管理Host的[真实只读安装证据](../evidence/2026-10-29-qmt-account-installed-real.md)和[真实历史主链](../evidence/2026-10-29-source-demand-real.md)保留其当时输入与结果，当前运行按独立WT所有权验收，见[独立WT与观衡历史组合](../evidence/2026-10-30-native-history-observer-composition.md)。晚来源、重连、全日采集及当前发行分别核验。原v1/v2单连接默认协议保持。

### 常驻只读入口的部署与操作

维护者离线生成显式resident-read的v3配对，核完整verify和独立Host安装身份。受管Host pythonw、配对与Agent安装路径、摘要和预算登记到qmt.host-process.v1描述；在WT配置的components.host声明kind=qmt_read、descriptor及sha256。历史准备、交易、独立账户和分析组合沿[WT手册](wt-independent-runtime.md)选择对应组件。私有pair由WT运行实例管理，观衡仅读公开查询、发布结果和状态。

使用安装后的WT运行命令统一启动，Host持续等待来源。QMT登录并运行匹配正文后，核本代认证、递增策略线程心跳和实际读结果。WT ready/status与业务读取分别观察；观衡可消费WT公开状态，观衡启停不改变Host生命周期。

正常关闭向WT控制目录提交原stop请求，沿首次关闭截止核消费者、Host、实际进程和资源。未知操作仍按原身份读取，不自动重发。配对或制品变化沿维护手册重建相应实例，不通过反复点击策略运行绕过原因。

日常运行入口为独立WT；登录自启属于部署配置，按实际安装记录核验。QMT登录及策略就绪沿平台实测方式确认，行情采集由WT持续组件负责。

## 内置Python资料入口

解释器版本、函数/属性索引、调用阶段、ContextInfo状态、受限访问与并发性能方法统一见[内置Python手册](guosen-qmt-python.md)。每次升级沿实际版本核对；本机与官方发行事实分别留证，库路径设置不等于切换解释器。

### 每操作读取预算

取得认证binding后，核read_profile原字节摘要，再消费该operation的execution_timeout_ms、policy_id及policy_version。请求timeout_ms在对应声明的范围内；账户、行情和历史分别取值。HTTP/队列等待、源SDK执行、结果读取和总停止截止各有自己的owner，某一读取允许更长预算不会扩大另一项的权限或时限。现场成功与合法拒绝见[两代记录](../evidence/2026-10-28-qmt-resident-real-two-gen.md)。

## 全推行情与原生落盘的运行核对

运行时同时核对接收状态的采样时间、来源时间和真实进程身份。状态停止刷新时，先检查原管理owner及进程终态；保留最后状态和原文件。计数在增长而来源时间落后时，保留同一连接代的SDK入口、心跳、自有队列和Writer观察，按[全推模块](../modules/qmt-quote-stream.md#运行观察与真实来源资格)逐段定位。

停机由管理owner先停止接收并确认唯一producer退出，再关闭本实例Writer。显式WtDataStorageLifecycle可调用archive_and_close提交原归档并收束实际线程，随后原Helper核历史条数、字段、最后时间和错误时保留的DMB。默认原库仍沿原运行路径；库选择、日间时段模式和发行资格须与部署身份一致。写入失败保留现场和未成功归档的实时数据，处理存储原因后再按单写者流程恢复。

界面操作连续无法激活时停止自动输入，保留已执行动作和本次策略身份，由终端操作者完成明确的单项动作；收到停止确认后才能恢复该策略文件。其他运行策略按原归属保持。
