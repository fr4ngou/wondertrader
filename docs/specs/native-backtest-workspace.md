# 原生回测工作区

类型：功能最终规格。状态：accepted。前缀：NBW。细化GBW-R2/R4、NSH-R4；configured 1.2.0及[NVB](native-v2-backtest-session.md)的V2冻结输入共用本工作区，其他策略族仍按NSK推进。各输入、安装和运行资格分别验收。

## NBW-R1 复用与配置

浏览器→观衡业务HTTP→受管StrategyHost→原WtBtPorter→NSB/NSK/NSQ→HostResult→中文工作区。复用WT-B01/B02的回放/撮合、NSH进程生命周期和NSB唯一报告准入/按需重建；不另建撮合、行情、账户、订单或任务数据库，不修改WT核心。旧回测服务退出此链；终端HTTP、共享内存及旧工程均不是运行依赖。

部署显式提供有摘要的nbw-config-v1文件：受管安装manifest/摘要、已有运行根、冻结session路径/摘要、回放起止、策略名称、展示名称和总期限。文件、安装和会话沿NSH本机固定盘/重解析点/类型/容量准入。默认未配置；配置变更由部署重启生效。浏览器只读展示该配置，不提供路径、DLL、命令、源码或会话上传；启动请求只含当前owner_id和request_id，均为32位小写十六进制。部署配置最多64KiB，会话最多16MiB，总期限0.1..1800秒，名称沿Porter纯窗口准入。摘要、来源、费用和模型资格来自冻结输入/报告，合成数据明确标注。

## NBW-R2 单轮所有权与重复

业务owner每进程一个，lifespan拥有；独立worker同步调用原宿主，HTTP事件环不加载DLL或阻塞等待回放。最多1活动、零队列。启动以单锁原子准入；同owner/request重复只读取原运行，不能再执行；繁忙拒绝不登记新请求。内存保存至多128个已受理请求及完成投影，满额拒绝新运行，不自动删目录。不同进程同根仍由NSH的OS锁负责。线程对象在start前绑定该entry；start返回异常先发cancel并保留活动名额/原线程，worker最终出口确认业务完成，标准join另证线程尾声已结束；下一轮先零等待续核原线程，两个条件共同满足后释放活动名额。标准Thread构造失败且尚未调用start的确定失败保留失败投影，可释放名额。实际启动尚未确认时保留未知状态、拒绝新运行，必要时由运维重启业务进程处理，不能把异常等同于没有创建线程。

owner_id为每次进程生命周期新UUID；重启后旧owner请求拒绝，原目录保留，禁止自动恢复执行、重新下发或从目录存在推定完成。持久实验输出由NSH保存，内存索引属于可丢弃展示投影。取消必须显式指定同owner和已受理request；只设置原cancel事件，最终回收以HostResult为准。浏览器关闭、读超时或刷新只停止自己的读取，不隐式取消或重跑。POST不自动重试。

## NBW-R3 截止、关闭与结果

准入后会话读取、宿主运行和报告准入共用一次monotonic截止；传给宿主的预算扣除已耗时，不重置。关闭先停准入并发cancel，再按共同关闭截止等待worker；尚未结束显示关闭未确认，保持真实owner与NSH句柄，不发布完成。等待不占用进程锁。关闭核对全部已受理entry的线程及唯一业务完成事件，逐个取得标准join证明；启动未知、join异常或仍存活均返回未确认，且继续续核其他owner。

只有HostResult为completed、非forced、exit0、pid_reaped、pipes_joined且报告通过唯一NSB准入才展示完成；其他状态保留中文原因和未知事实。安装/目录路径、凭据、原始异常和argv不返回浏览器。公开投影含owner/request/run身份、状态、原因、耗时、模型范围及进程回收事实，接收成功与运行成功分别展示。

完成报告通过深不可变ValidatedSessionReport消费。内存至多缓存一份已准入报告；已完成运行只保留有界状态、报告SHA及原NSH结果文件位置，再读时核原摘要后加载，不能把文件存在提升为运行成功。分页每次至多50个记录头；单日详情通过唯一公开project_session_record取得当日capture/outcome及完整非增长header，避免先重建完整前缀再删除字段。完整增长历史仍由原NSB重建接口和原NSH实验文件提供，页面摘要不称完整报告。configured原响应字段和值保持；V2详情额外明确report_schema=nsb-v2-report-v1，摘要保留实际策略身份、原始目标准入及输入资格。报告读取有限worker/截止和响应容量；运行/未完成没有成功报告。

## NBW-R4 HTTP及页面

GET /v1/ui/backtest/workspace返回配置可用性、owner身份和至多128个投影；POST /v1/ui/backtest/runs受理启动；GET /v1/ui/backtest/runs/{request_id}读状态；POST对应/cancel显式取消；GET对应/records?offset=&limit=读完成记录头，GET对应/records/{index}读当日详情。未知/旧owner、非法输入、繁忙、满额分别有明确4xx中文原因；未配置保持503。所有输入严格有界、拒绝额外字段和查询；修改入口要求JSON及同源浏览器Origin/Fetch-Metadata，畸形Origin同样403去敏拒绝，不启跨源权限。部署配置含非法回放时间时仅回测能力不可用，其余应用入口保持可启动。

独立/strategies?tab=backtests和/backtests兼容入口可访问；现有导航保持。页面展示配置、运行/完成/未完成、来源/模型范围、取消、逐日原生资金/持仓和目标阶段，保留加载/空/错误/恢复。实盘、账户和交易入口保持关闭，不把回测成功授予实盘资格。其他策略tab仍按实际能力明确未接。

当前新运行仅接受guanheng.retained-replay-input.v1及唯一正式1.1.2配置，旧版本回放输入在创建runner前拒绝。新报告准入、预热已有原生观察与逐日投影沿[RR112-R7](retained-resonance.md#rr112-r7-app任务与报告)；已封存configured/V2报告按其原schema读取。页面展示名称、版本、模拟资金/持仓、调仓目标及简短原因；内部身份、算法过程、资格字段与完整JSON保留在API及诊断资料。未知或矛盾schema拒绝读取，首次失败提供重读；同查询刷新失败保留上次成功结果及原时点，成功空响应更新为空。

## NBW-R5 验证

当前只读App回归沿ADR-0016验证：运行、取消、保存等写请求统一405且不构造执行owner；未配置归档与已知空目录分别为503和成功空集合。旧GUANHENG_BACKTEST_CONFIG及摘要不进入观衡配置，失效执行时间不影响有效归档的读取。绩效/比较走原有界读池与五秒总截止，错误、满额和超时后可在同身份重读；归档或绩效某项缺失只影响对应读取。新App生命周期继续读取原完成证明和request/report身份，保持原目录字节。旧运行owner的纯回归和历史固定候选验收独立保留，当前App测试采用真实只读装配入口。

### 逐日来源报告消费

观衡消费B公开的`guanheng_wt_runtime.backtest_reports`只读准入和逐日投影，支持固定末日基准及`guanheng.retained-per-date-replay-report.v1`两族；原WT-B01/B02资金、持仓、数量与撮合事实沿原报告。App声明精确本地WT包依赖，仅调用纯报告接口，不构造运行会话、加载DLL或管理WT进程。原App重复的唯一策略报告校验收敛为该接口的错误边界适配；已封存configured/V2报告保持原读取。

逐日来源每条保留原market_window及当日历史模型，绩效输入身份同时绑定报告per_date_source的目录与全部窗口摘要；不同复权基准按不同模型比较。浏览器仅展示原资金、持仓、目标、阶段与简短原因，内部来源身份保持API字段。两族均执行原截止回调，异常保留App公开错误及取消身份。验证使用B冻结的400期原报告逐日核对、独立金融重算及前端真实形态准入；输入或窗口身份漂移拒绝。

报告格式可读与已完成归档分别验收。NBW-R6原父端完成证明仍是历史目录的准入条件；B单独发布的REPORT.json及实验结果不生成App归档证明。WT产品CLI及正式归档交接到位后，再完成原目录→HTTP→生产SPA验收，期间该主链资格保持待验。

覆盖默认未配置、参数/摘要/路径/来源拒绝、同ID重试只执行一次、并发/满额、取消、断开读取继续、重启epoch拒绝、期限扣减、worker退出和完整/不完整结果。独立安装+原DLL冻结样本经真实业务HTTP和浏览器验证启动→状态→资金/原生目标→记录分页及取消/空/失败恢复。冻结源码后full独审；真实来源、其他策略族、RT与生产分别登记。

## NBW-R6 已完成回测只读归档

逐日纯值输入的C消费：`guanheng.retained-per-date-replay-input.v1`保留原schema/session/source三字段和完整请求/会话摘要；规范化复用WT公开输入入口，配置及绩效共同从规范化后的原session读取资本、费用、策略配置和模型。完整source绑定继续参与报告匹配与绩效输入身份，未知外层、坏内层和来源不符均拒绝。默认最终批次及旧报告族保持原合同。该读取适配不创建completed-archive.json；正式归档仍由原运行父owner持有，独立安装和原目录→HTTP→SPA按实际收据另验。

一次读取在原件边界完成输入规范化及完整来源/报告绑定后，将已准入内层交配置或绩效投影，原外层请求和会话摘要保持，投影不再次规范化完整历史。每次重新读原请求/结果/安装、核证明及原输出摘要；请求与结果原字节SHA相同时，复用至多一份深不可变的已准入报告，输入规范化和来源绑定沿该原字节身份复用。新身份重做完整领域准入，整条原件检查成功后替换唯一缓存；失败不授读取成功。可变请求/结果仍在各次读取内解析，缓存不保存它们。五秒总期限及WT逐日详情/绩效公开投影保持。

比较的两次原件访问共享同一读取上下文，绝对截止和192MiB累计读取额度都贯穿整对，第二份不重置。上下文只保留最后一次已完整准入输入的有序JSON摘要及原规范会话SHA；原字节核验后，完全相同输入可复用本次准入，两个不同报告仍各自执行唯一报告校验。每个报告重新核完整source绑定，配置的session_sha256必须等于原请求。输入顺序摘要保留字典顺序，避免同一排序规范SHA掩盖来源窗口倒序；新输入或顺序变化重新准入。此临时输入证明随操作结束释放，唯一报告缓存可同时保留其输入证明，整体仍至多一份已准入报告。

公共严格JSON守卫仍在标准解析前限制24层深度，以原64KiB字节窗口检查截止。每窗口由C正则筛选引号、反斜杠及括号标记，字符串和转义状态跨窗口保持；重复字段、非有限数值、UTF-8及节点额度继续由原解析/遍历核验。该实现适用于观衡原件和原Host辅助读取，不改变WT生产者或金融规则。
