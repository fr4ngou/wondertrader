# 公开全市场日终来源与09:00发布

状态：实现中。阶段基线为a75，a75继续独立交付。用户2026-11-01明确QMT暂停；本链仅使用公开只读来源和原观察存储。

## 目标与现状

固定原件消费已完成；后续每天更新需要自动取得同一收盘日的股票池、流通股事实和行情，自动轮换输入身份。原报告读取保持5秒，源采集使用既有有限预算。公开POST已沿正式Fetcher核通，北交所2026年接口优化原件已下载并核其状态字段。

## 复用与所有者

- WT原生DataKit/Writer/Reader拥有运行行情；此处公开市场横截面属于既有独立观察采集，遵循ADR-0016，不增加WT通信或终端操作。
- 原观察服务主线程、scheduler lease、collection lease、预算、Fetcher、ContentStore和catalog.sqlite3继续拥有生命周期与事实。
- `ashare_public`来源取得BaoStock证券表/日历/日线、公开公司证券类型、北交所同日证券表/行情及代码映射。股票池按当日上市资格与实际证券类型构造，数量随来源变化。
- 日终纯核继续唯一计算四项指标。原件捕获与09:00数据发布分别记录；沿原runs记录归档锚及尝试，不新建数据库、Windows定时任务或服务。

## 要求与接口

| ID | 行为 | 验证 |
|---|---|---|
| OAP-R1 | 普通refresh以稳定配置自动获得公开来源并发布；没有固定日期或5576名单限制 | 实际公开网络到HTTP/页面 |
| OAP-R2 | as-of为自然日；日历决定最近闭合交易日。休市/开盘前读取所需同日归档，日期保持实际交易日 | 实际2026-10-31/11-01休市、跨日边界 |
| OAP-R3 | 同一股票池、非限售/流通股事实和行情日期一致；每件原字节SHA与实际接收时刻保留 | 独立原件复算与不一致保旧 |
| OAP-R4 | 服务原循环在收盘后预归档；09:00才沿原窗口发布；重启读取归档并按原身份核查未知提交 | 原服务完整启动/更新/停止/恢复 |
| OAP-R5 | 北交所N/Y/D与停牌T/H分别按已核业务语义处理；未知状态与部分数值缺失局部计数，原数值和已核事实保持 | 官方契约与必要边界 |
| OAP-R6 | 来源不具备所需历史能力时明确记录缺口；保留旧快照和实际日期，不以当前行情代替过去 | 日期冲突与恢复 |
| OAP-R7 | 原a75实际原件可在同一对象库重新准入；方法变化要求覆盖已有日期重算 | 迁移、前后原数据一致 |

来源配置沿原schema，kind=ashare_public，url为已核公司证券类型接口，datasets固定为四项ashare指标，tables为source.ashare_day_universe；max_pages<=16。来源主机显式允许北交所与公司披露域。报告身份年度随所需交易日自动选择最近两个已完成年度，历史修订首次可得性继续未知。

## 数据流与持久边界

1. 原采集lease内查询有界原日历，确定所需闭合交易日；按来源当日记录日历身份。
2. 读取该日已核归档或捕获完整公开原件。北交所原件先存；证券资格、沪深日线分别通过共用准入后保存部件。日线迟到时复用同日已核部件。原runs在网络前登记尝试，按自然日执行既有retry/max_attempts约束；成功归档由内容SHA定位。
3. 源股票池从同日上市资格与证券类别构造；已确认CDR显式排除并记录。身份未核者保留待核数量，完整市场比例保持未知，不用已核子集冒充全市场。
4. 统一准入并计算；正常refresh沿原CAS一次发布数据、窗口和回执。后台日终归档仅写原件/归档收据，保持数据current。
5. 09:00使用前自然日对应的最近闭合交易日。若行情已经切到今天且前交易日归档缺失，保留旧数据并明确缺少哪一天。

北交所XXFXSGB按2026年官方优化说明为非限售股本；网页原始字段单位为股。XXSLDW为卖出申报数量单位，行情股数单位独立确认。证券表Y/D沿来源参考价计算涨跌，页面说明该参考价与前一日真实成交价的关系。停牌T/H且无成交时单列停牌；已成交时保留当日成交与涨跌统计。未知证券类别、身份和交易状态保留候选并单列资格缺口。缺少非限售股本仅影响换手资格；缺少价格仅影响涨跌资格。逐证券最后更新时间允许早于15:30，整批结算日期和原件接收时刻共同确认收盘后捕获。

四项ashare定义升级到/2，换手主值采用完整市场占比；任一换手分类未知时主值为空，页面单独说明已确认下界。旧/1数据必须从现有对象库的父原件完整重算全部日期后升级。窗口内已归档的其他交易日沿原runs按日期查询；所需历史原件缺失时保留旧快照，避免以当前行情回填过去。

更新页面将原件归档与09:00数据发布分别显示。原件保存成功表示后续发布输入已保存；当前数据版本继续由原窗口发布事务拥有。

原调度心跳phase在waiting、collecting、archiving间流转，停止后为stopped；归档阶段使用同一心跳写入准入，状态所有者与服务循环保持一致。

同一ashare方法版本的展示文案勘误由admit_definition在成功refresh中同步公式说明、阅读说明、限制和对应曲线说明；字段、计算版本和已存历史保持原身份。方法变更继续执行全日期原件重算准入。
