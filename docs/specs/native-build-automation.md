# 原生构建、打包与自动化测试

类型：功能最终规格。状态：accepted（本次实现范围）。权威范围：隔离原生构建入口、固定依赖、自动测试和开发候选包；沿用[原生发行方案](native-release-and-upstream.md)的身份与恢复原则。

## NBA-R1 独立构建入口

使用独立 CMake 入口组合已有原生核心、数据、回测、模拟插件和程序源码；保留上游总构建入口及其 SDK 选择。默认 profile 不包含真实券商插件，不读取账户或生产配置。原生测试和工具链的生成目录由参数指定，默认位于仓库忽略的 E 盘工作目录。

## NBA-R2 工具链与固定依赖

构建入口检查工具链、架构与依赖；依赖来源、版本、源码摘要和许可证集中登记。下载先写临时文件，摘要符合后才发布到缓存；离线缺失或不匹配明确失败。已有依赖可复用，默认不执行系统安装或修改全局环境。

## NBA-R3 自动测试

CTest 运行选定且明确列出的可隔离原生用例、Runner 启动入口及原生回放集成测试，产生可机器读取的报告和失败退出码。原有依赖专用环境或可能真实下单的调试程序不作为默认自动用例；说明未覆盖原因和后续资格。

回放测试复用实际框架的历史加载、策略回调、目标及模拟状态，断言确定输入下的结果；其通过不授予真实交易或业务审批链 E2E 资格。测试进程、输出和状态独立，具有超时与清理边界。

外部受控业务代码的有源/无源选择在配置中显式固定。复用构建执行测试或打包时，请求必须与已配置源一致；不同选择在运行测试前拒绝，不能由旧缓存覆盖本次请求。未配置外部业务源时，相应资格显式 skipped/unavailable；显式指定时须通过源码身份及实际核心调用链。

已在未改业务语义的基线上复现的上游失败可单独隔离，必须在 CTest 中显式显示 Disabled、保留失败证据和重新启用条件；启用用例通过数与隔离数分别报告。原生全天零点用例存在 0/2400 预期冲突，本任务保持时段实现，启用独立的分段日间时段回归；全天资格另行核定后恢复原用例。

## NBA-R4 制品与校验

开发候选包包括已构建程序、库/插件、依赖许可、示例配置及清单；记录完整源码与上游身份、未提交状态和相关文件指纹、工具链、依赖及逐文件摘要。固定制品目标、拒绝覆盖已有发行内容，禁止将运行状态、凭证或本机账户配置加入包。

校验检查身份模式、路径和重解析/链接、重复/缺失/额外文件、摘要、清单与外部包摘要，报告明确失败。解压后的包在独立目录执行无真实副作用的冒烟测试。开发包明确标识，正式发行另核实干净正式源、标签、审查与运行资格。

## NBA-R5 编排与自动化

提供 doctor、依赖准备、configure、build、test、package、verify 及完整流程入口。每阶段有输入身份、日志、退出码和有界等待，失败阻止依赖阶段。CI 使用同一入口，固定权限和构建环境，不部署、不连接账户；托管执行结果与本地结果分别登记。

## NBA-R6 验收

实际构建至少一个原生 Runner、回测核心及动态模块；运行默认原生测试、回放与包级冒烟并保留报告。适用负向验证包含依赖摘要不符、测试失败/超时、包篡改/额外文件/路径越界，以及输入变化导致资格失效。更新手册、模块说明、CURRENT/NOW 和证据，关键构建/打包/恢复代码经独立审查。
