# 证券接入、策略恢复与交易发布

类型：跨模块实施规格。状态：用户已确认目标，按下列步骤实施和验收。首个发布对象为七只 ETF 策略，独立资金 100 万元、空仓。新增策略实例通过正常重启 WT 生效。

## ESO-1 证券资料与执行配置

WT 数据组件发布版本化证券资料。资料标识交易所、证券代码、品种和上市区间，执行资料补充来源代码、价格步长、买卖单位和零股、交易日历和时段、结算与可卖、费用及可用订单类型。各字段沿负责的数据、市场或券商来源保留时间和版本。缺项报告具体证券与字段。

WT 用策略声明、待恢复持仓与未完委托确定本代需要的证券，从固定版本资料派生 Reader 映射和 Native 合约。Reader 按需订阅，映射与合约在同代一次采用。相同输入生成相同结果，代码冲突时保留上一个有效版本。当前 `GuanhengRealtimeReader` 和 Native 基础资料加载器继续消费原格式。

首个实现切片提供离线生成入口。输入为 `guanheng.security-reference.v1/v2/v3` 原件及 SHA256 和一个或多个 `交易所.六位代码`。输出 `guanheng.etf-execution-security.v1`，含来源 SHA256、Reader 映射和按交易所分组的 Native 合约行。首版对接现有沪深现金 ETF 合约模型，品种、上市日期、名称和交易所来自资料，现有交易单位、费表和时段仍由原 Native 配置校验。此切片生成候选材料，自动消费策略和恢复状态及覆盖其他品种由后续步骤完成。

## ESO-2 交易通道与执行能力

WT 与 QMT 的通用交易通道去掉按证券代码维护的白名单。WT 在准备委托时用实际合约规则核对价格、数量和资金可卖条件，绑定所用资料版本。QMT 复用已认证通道校验委托和账户身份，调用对应的券商交易接口。账户和券商权限继续由原职责层判断。市场路由、代码、订单类型、费表、资金计量和结算按市场及品种接入并逐条验真。只读覆盖与可委托覆盖各自发布。

QMT 通用入口使用显式 `qmt.trade-binding.v2`，保留 v1 的账户、环境、路由关联、策略名和通信预算字段，移除 `symbol_rules`。QMT 继续核对原命令协议、写权限、有效期及 SDK 可表示性，现有市场与订单类型沿原命令协议。v1 原件继续用于历史核查和原配置运行。使用原版本链支持一次 v1 到 v2 的同账户迁移，`rule_changes` 为空，移除名单的业务授权沿既有授权摘要绑定。迁移保留原记录和配对身份链。WT 动态规则准入及真实配对演练完成后采用新版。

一次性迁移使用原 [Host Journal owner](qmt-trade-binding-extension.md) 的租约、事务与连续身份链。升级材料绑定旧配置、新配置及完整旧账摘要。保留原命令 ID、原正文、回报和未决责任。配置采用前的失败继续使用前一版本。采用结果未知时按同一迁移身份回读。完成采用后按新配置恢复，采用前后可用的回退路径须先用实际制品演练。

## ESO-3 通用策略恢复和配置生效

公共启动与恢复由已登记策略类型、版本化配置、策略差异声明和前后状态证据驱动。旧策略保留原账户、持仓、资金和未完委托身份。新策略使用配置声明的独立资金，按恢复准入验证额度和空仓。校验器从新旧证券集合和资料计算合法依赖变更。运行中可变的配置在完整校验后于业务边界一次生效，既有委托仍绑定创建时的资料和配置。

新增策略的冻结行可显式列出 `execution_securities`，为完整 WT 执行代码集合。声明走 `guanheng.strategy-dependency-handoff.v2` 时，以证券资料派生 Reader 行，并从前代已有集合计算新增映射。`contract_additions` 按交易所及六位代码记录确需追加的合约行，已有合约、映射、环境文件原值保持。恢复同时核 Python 与 Native 的同一材料。旧 v1 依赖材料沿原规则兼容，新增通用材料使用 v2。

重启材料准备器接收已冻结的新代 Native 模板、原证券目录及可选的 Source 采用证明。它在新目录生成安装清单、合约、Reader 配置和依赖材料，调用原恢复校验核对新旧配置后交给原 `prepare_transition`。原安装和金融目录只读。准备材料可在停机前验证，实际状态摘要和启动许可在原 owner 停止后由既有接续入口取得。

退役证券采用受控恢复。核对当前实际持仓和在途委托，把已证实无券商责任的旧理论目标和信号移出可执行状态，保留历史与迁移证明。用 589680 验收，先证明旧目标重启后不重放，再解除全局屏蔽。策略主动选择该标的时按普通证券处理。

`strategy_extension_origin.retired_targets` 绑定退役的前代策略实例及证券列表。每项必须已离开前代 Reader 的活动集合，并在前代全局过滤中有 `ignore`。新安装仅移除相同证券的全局过滤行。首次接续以同账户最新完整持仓和委托证明零持仓及无在途，再由旧策略上下文清除恢复出的活跃理论仓位、挂起信号和条件。保留实际成交历史与理论已实现值，按剩余仓位重算理论浮动值。后继从已核配置续接同一策略范围，新策略可独立使用该证券。

## 实施与验收

| 顺序 | 验收 |
| --- | --- |
| 1. 生成映射和合约 | 用实际 A500 资料和另一只 ETF 生成配置，覆盖缺项、冲突和摘要不一致。已有 Native 配置及数据原件可回读。 |
| 2. 通用恢复与规则接入 | 用两个不同策略实例和不同新增证券通过同一恢复入口。覆盖配置错误、在途委托、退役目标及账户余额不足。 |
| 3. 通用 QMT 通道及迁移 | 用原账副本演练，核对旧订单、事件和资金。采用新版通用 QMT 脚本后，用同一脚本校验 A500 与另一只合格证券的模拟委托及回报。按市场验证路由、单位、费用和结算。 |
| 4. 正式重启发布 | 在已确认的账户环境按 [发布手册](../runbooks/release.md) 切换。观衡显示新策略版本、100 万资金和空持仓，原策略状态连续。自然交易窗口核对信号、目标与回报。 |
