# 原生策略目标代际与分阶段数量转换

类型：功能最终规格。状态：accepted。前缀：NSQ。依据[NSK](native-strategy-kernel.md)的完整算法、同核运行与原生事实所有权；本规格定义其业务数量转换要求，实现与运行资格分别验收。

## NSQ-R1 职责与身份

独立模块位于`apps/guanheng/strategy_native/guanheng_strategy_native`，只拥有经济目标身份、冻结数量及阶段转换。WT上下文拥有理论持仓、pending信号、成交和资金损益；转换模块不调用柜台、不撮合、不维护另一个持仓/现金账本或数据库。阶段输入是原生owner当次观察，保存的价格/NAV与数量basis仅用于复现冻结决策。

经济代际绑定策略/算法/稳定配置、执行policy身份、原allocation日期和完整规范化execution证券权重向量；角色与signal/execution映射由稳定配置身份绑定。每日input/source/price/NAV/观察时间摘要不进入经济代际。相同代际已完成时复用冻结数量；A→B→A由不同allocation日期区分。无allocation日期且全零属于initializing，不提交清仓；带allocation日期的全零是有效零目标。正权重却无allocation日期拒绝。

## NSQ-R2 数量与资本输入

首profile为显式CNY现金ETF理论模型：数量为份，金额乘数1，整手100，禁止重复乘100。调用者提供完整证券集合、稳定profile/policy身份、理论初始本金及来源；不得默认100万元或使用账户总资产替代策略资本。后续其他品种通过明确profile扩展并单独验证。

阶段basis包含明确时点与摘要、各证券raw未复权CNY/份价格、原生理论NAV、当次理论现金估值及本次全部买入的显式费用预留。native NAV由明确初始本金加原生策略flag0损益导出时，须核其无外部资金流、原生费用及仓位覆盖。费用预留是该理论模型输入，未知费用保持不可用，不自动置零。现金和NAV是原生事实的派生观察，不形成另一个持续现金账本。

每个证券目标为`100 * floor(weight * NAV / raw_price / 100)`。十进制输入进行有界精确取整，不依赖全局Decimal上下文；零权重直接目标0。正权重缺价格、非有限/畸形输入、维度错误或无法用native double精确表示的整数目标拒绝。价格、资本、权重和费用的单位、时点、来源全部可查。

## NSQ-R3 阶段与冻结

首次合格代际按同一basis算完整数量，只冻结卖出阶段目标：每证券为当前实际理论数量与计算目标的较小值，尚未买入的证券保持0。该向量在卖出完成前保持，价格或NAV漂移不重算。可卖数量不足时等待T+1资格，实际native适配器不得提交会被原生拒绝的超可卖卖出量。

实际理论数量全部达到冻结卖出目标后，取新的post-sell basis计算买入目标。若费用/NAV变化使任何目标低于现存数量，冻结残余卖出阶段，完成后再取新basis；不提前冻结买入。所有买入的新增名义额加显式费用预留能被同一basis现金覆盖时，才一次冻结完整买入目标；不足则整组waiting，保留原因及原代际，不按证券顺序抢余额、不缩权重或丢目标。阶段迭代有显式部署预算，超限停止并报告原因。

买入向量冻结后，原生实际数量未到目标时保持buying，达到后converged；此后同代际跨日观察、价格/NAV/每日input修订均复用原冻结数量。输入代际冲突、原生持仓偏离冻结阶段允许范围、未解决的pending或新的代际到来，需要明确的阻断/交接结果，禁止把pending目标回显当成交或无声覆盖已有阶段。本模块先定义并验证纯状态转换；原生提交与代际切换接线另按NSK取证，不以纯函数结果授成交资格。

## NSQ-R4 原生边界与恢复

原生适配器负责把实际理论仓位、可卖和pending目标明确区分后交给模块。固定BT实验中`get_all_position`含pending覆盖，新证券`get_position`可能回显目标；entry时间只描述当前持仓明细，平仓后归0，均不能单独作为通用成交确认。`set_position`为void逐证券操作，原生提交沿NSK完整预校验、目标回读及partial失败隔离。

固定原实现对“已有actual100、pending200、再set100”的行为须作为接线限制验证，不能据setter调用成功推定pending撤销。没有取得所需覆盖/撤销能力时，适配器返回明确不可执行状态，原生框架修改仍先提交必要性、范围与风险给用户批准。

状态对象递归不可变，绑定版本/policy/经济payload及冻结basis和向量；可由完整冻结输入重放。不新增数据库恢复owner，也不把本模块状态称作实际持仓。恢复及新代际切换由受管native宿主按NSK在启动前验证，真实通道与权限独立处理。

## NSQ-R5 验证与适用范围

验证同代际价格/NAV漂移不再平衡、A→B→A、initializing与dated-zero、卖后重算、手续费跨整手的残余卖出、T+1等待、整组买入现金不足后恢复、重复推进/重放、部分/超额实际数量、数值/容量与不可变输入。人工可核的Decimal/整数参考与真实native实验分别记录。

本模块首次独立full；修正按实际身份delta。纯转换、实际BT/CTA调用、同核日目标、HTTP页面、真实来源及生产分别登记；五策略及全观衡迁入仍是最终范围。
