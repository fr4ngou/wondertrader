# 全市场分钟采集、覆盖与自动恢复

类型：功能规格。状态：accepted。前缀MCC。需求来自Root本轮分钟模块分工；范围为既有QST接入、原生采集与历史补缺的自有适配。日线owner、账户交易、观衡UI及Root CURRENT分别由原模块维护。

## 目标与原生接缝

沿WT-D01/D02/D03/D05/D06/D11复用原ParserAdapter、DataKit、同步Writer、StateMonitor、标准Reader及已有来源补齐。Writer独占原存储根，负责分钟构造和自然收盘归档；Reader拥有形成中数据的读取，不直接解析、复制或映射活动DMB。既有SourcePreparingMarket、RetainedReadClient及Importer拥有补缺请求身份、来源原件、原生导入及恢复。自有采集owner负责将这些现有能力连成可观察的运行流程。

当前实际缺口为逐证券时点和覆盖不足、固定订阅与动态已知名册缺少对照、历史补齐依赖查询触发而缺少采集owner接续。框架原有归档与重连继续使用，新增实现只负责覆盖投影和有界接线，不新增行情数据库、常驻服务、系统定时任务或分钟算法。

## 所有者与恢复

QMT订阅和资料调用仍归原策略线程，接收线程将已校验批次同步交原Writer。覆盖投影只在成功交付后登记纯时间与计数；原消费失败保持其已知/未知结果。管理线程复用现有采集循环推进维护，不在接收回调内执行磁盘扫描、来源请求或历史导入。

盘中读取沿[受管分钟Reader](native-minute-reader.md)，归档读取及独立补缺来源沿[CNH](collected-native-history.md)。实际断线边界样本同时存在空白分钟和累积量额进入恢复首根的情况，因此完整闭合日恢复采用原来源全日版本。仅当来源标签与原WT交易时段完全一致、原Importer成功且原Reader回读通过时，原窗口收据才发布该日选择证明；查询在此日选用这一版本。原Writer文件、原来源及其他日期保留，其他原值差异沿既有冲突处理。来源只有历史日能力时，当前日缺口保持待闭合/待来源支持，并由原owner在可用范围内后继推进。

采集管理循环拥有唯一补缺生产者。公开查询使用显式`source-recovered`配置，读取固定生产配置所对应的原窗口成功收据和原生根，不提交来源请求、不获取生产者写锁。生产配置新增显式`partitioned_receipts=true`时采用v5收据，原workspace按证券/窗口SHA分目录；原请求及Importer产物留在窗口内。每次查询只查本证券，避免市场窗口数量令查询扫描全市场。旧平目录配置及v1至v4身份保持。

首轮空结果或部分来源继续沿原`follow_up`机制作有界只读观测，原下载请求至多一次。候选明确配置60秒最小间隔、15次后继和原24小时总截止；首次发布加后继最多16份导入。未知读取先续核原UUID，重启保持原截止、已消费次数和产物。完整来源发布前，部分来源仍可能与Writer边界冲突；该冲突保持可观察，同时原owner继续推进恢复。已结束整日的可读与首次准备判定均按原session完整标签核实，同条数和相同尾标签仍须检查盘中缺失；旧按需窗口保持原规则。额度耗尽明确保留停止原因，完整日证明仍只授实际240标签（以原session为准）及原生回读已通过的版本。

`source-collected.minute_native`显式固定薄桥、标准Reader、Writer根和三份基础资料SHA；今日和归档均由原标准Reader读取。`source-recovered`通过`producer={path,sha256}`固定原生产配置，分钟数据集`collection`和`minute_native`必须与生产者一致。日线读方保留自己的原base目录和文件Reader；已发布恢复根始终用生产者原文件Reader回读。新增模式仅扩展自有工厂及采集接线，原日线合同保持。

正式日线读取组合可为`source-recovered`显式增加`delegate`配置：只有`history.source-query`进入本分钟读取，其他请求原样交给原`source-market-current`动态读方。delegate由同一服务线程创建和关闭；其指针、Snapshot、日线叠加层和数据生产配置保持原件。省略delegate沿原行为。本接线不改写既有日线Snapshot/base，不更换日线任务根或复建资料；自然新日发布仍由原日线owner完整维护。切换前逐项对照原/新日线、资料、事实、53指数/CNI及旧历史响应。

动态名册的完整资格取决于真实Source分组和完整分页，既有6982或固定50指数分别只证明该原集合。沪深北或特定类别的接入缺口按源能力、代码映射、订阅和实际分钟分层列出。

## 已派发读取责任的接续

采集owner滚动扫描日期与已派发请求的消费责任分别维护。日期退出lookback、窗口已有发布或后继观测额度结束后，原保留slot仍归同一生产者。管理线程有界遍历同producer原窗口收据，续核已经attempted的未消费slot；仅使用既有slot和request_id，先保存并验证完整原结果，再由原RetainedReadClient确认消费。该接续不调用新bound-operation、不新建slot、不重新准备历史，不直接修改Journal、结果或额度。原责任交接与窗口工作均可推进时轮流选择；窗口工作内部继续按原规则在到期重试与新窗口之间轮流。只有一种工作可用时继续该种工作，历史unknown或持续consumed都不会独占循环。未派发记录保持原正常规划；身份或内容损坏明确失败，未知结果继续原ID。外部Root执行维护时沿同一producer租约及原进程正常停止协议，公开读方保持只读。

每步扫描受原管理间隔和有限窗口批次约束，至多推进一项原读取；扫描游标是可重建的进程态，不替代原窗口和slot。维护投影增加retained_read_resume，逐项表达not_scanned、scanning、idle、pending、consumed或unavailable及原请求ID；当前日期已可读不能替代历史责任交接。已消费且完整验证的成功页可直接复用原窗口内保存的完整响应，避免每次补齐重新打开所有已完成页的slot；失败、未知及未消费页继续原客户端语义。

## 交付与切换

分钟恢复的到期旧请求与尚未尝试窗口同时非空时轮流推进，每步仍最多调用一个原窗口；仅一种队列可用时继续该队列。原retry截止、slot/UUID、取消、Source/Writer/Reader所有者保持。优先证券由原配置选择，部署可复用策略证券及config/market-collection-indices.json常用指数；排序只影响推进次序，其他已知证券仍进入同一队列，不构成读取允许清单。

配置准备请求显式提供`process_pythonw={path,sha256}`，用于新history/collection两个子进程；不从旧数据角色继承隐含运行环境。原HPR独立解释器及日线原解释器分别保持。验证使用各描述符的实际解释器以`-I -B`加载其实际入口，核模块来自本次release；Runtime配置准入与入口加载分别记录。直接脚本装配release根，按包导入helper保持宿主搜索路径及SDK身份。准备阶段接受完整Source目标处于已固定before或after任一CAS，其他字节拒绝；Source采用/回退仍由Root显式执行。

投影容量由单一文件预算表声明：原状态/收据64KiB、全证券覆盖8MiB、分钟维护16MiB。发布端将同一预算显式交给原私有文件创建层，再沿原SDK原子替换；读取端复用该预算。私有文件普通调用仍默认2MiB，只有显式选定预算的投影可扩至16MiB；创建期ACL、独占新文件、句柄回收和原子发布逻辑保持唯一。验收覆盖实际全集合乘配置日期数、完整字段及最大字段宽度，包含越界失败保留旧快照，禁止删字段、缩证券或关闭维护规避。

运行过的分钟候选升级使用`prepare-update`：固定原deployment和新program，只更新进程入口、控制根和当前日线角色接线。原producer配置、所有恢复workspace/收据/未知请求及其配置身份保持，不为代码更新生成另一份恢复状态。原Native文件及基础资料字节未变时沿其原固定引用保留；原程序若仍被这些引用使用，继续作为运行依赖保留。

所有新增工作树、候选、临时文件与证据使用E盘。旧原件和历史继续保留。候选固定生产源码及依赖身份，复用已交付标准Reader和原生组件；新增WT框架行为须沿原批准规则，当前方案不包含框架修改。

正式采集切换前交Root完整原/新配置、实际进程身份、影响的历史/报价监听、原请求交接点、关闭截止、成功条件及回退动作。隔离验证和候选提交自主推进；正式部署、自然收盘、断线恢复和长期运行资格分别登记。

Root统一合并GHWT来源正文时，移除该旧来源中已无消费者、writes_enabled=false但仍接收其他入口订单的旧trade回调及配置；保留当前真正交易Source与全部其他QMT策略。该变化由Root核对完整正文并实施，分钟模块只交付订阅/基础资料增量和具体动作，不自行操作QMT。
