# WT 私有状态持久化

类型为功能规格，状态为分阶段实施。适用于 WT 原生状态、策略自定义状态、QMT 通信、策略分账、运行投影和日志。各模块持有自己的业务事实，统一使用以下路径、提交、恢复和去重约定。职责决定见 [ADR-0030](../architecture/adr/0030-wt-private-persistence.md)，现场基线及逐项迁移见[迁移方案](../migration/wt-private-persistence-migration.md)。

## PERSIST-01 路径与开发规则

| 位置 | 写入内容 | 开发判断 |
| --- | --- | --- |
| 内存 | 当前运行状态、读视图、临时指标、可重算缓存、等待发布的最新展示快照 | 策略读取内存中的一致版本。重启重算所需的输入与版本必须有依据 |
| D 盘配置的私有根 | 实盘账户、委托、成交、分账、恢复状态、自定义策略状态、交易审计、运行日志、运行投影及业务检查点 | 运行安装使用受控绝对路径。按账户、实例和模块隔离，目录访问权限沿运行账户和只读消费者配置 |
| E 盘工作区及安装根 | 源码、部署模板、代码制品、已安装程序、可重建的开发构建输出 | 仓库只保存脱敏配置模板。现有独立行情归档沿所属数据模块的配置管理，大容量数据迁盘独立评估 |

运行配置声明私有根及原模块目录映射，盘符是本机部署值。新设受管 CTA 保存配置 `native_state_save`，接受 `native` 与 `on_change`，缺省为 `native`。仅在受管 CTA 启动时绑定到原序列化写入口，`on_change` 比较本代已成功提交的完整原生 JSON 字节及文件身份。首次保存、内容变化、文件缺失或替换，以及上次提交失败时按原保存时点写入。临时文件在原目录写完并刷盘后原子替换，失败保留旧文件及待重试状态，已有恢复流程须在三类文件全部成功保存后签发正常关闭证明。非法值在启动准入时拒绝。必需目录缺失、权限不足或租约已被持有时，按所属模块的既有故障入口报告。写入者创建同卷临时文件再原子发布。凭据由既有受控配置引用，策略状态、报表和日志只保存业务所需字段。开发新增写入时，在所属规格说明事实所有者、稳定身份、写入触发、是否可重建、提交时点、目录和恢复验证。

## PERSIST-02 各项怎样接入

| 对象 | 内存与持久化方式 |
| --- | --- |
| WT 组合、策略理论状态及用户变量 | 原 WT 上下文持有状态。第一阶段将原生目录作为同一恢复集合迁到 D 盘，继续按原加载/保存边界读写。第二阶段通过受管 CTA 的显式配置启用按内容比较、只保存实际变更。比较依据包含原序列化的全部恢复字段，加载时核同一提交代。现有默认路径保留原生语义 |
| WT 原生策略历史输出 | 保留原输出格式、事件顺序和读者入口，路径迁 D。逐笔明细按原事件身份追加。能从权威事实重建的导出采用快照/版本缓存，同版本重复导出复用已完成文件 |
| WT 运行快照及观衡投影 | 原发布者在内存保留最新值，变化时由同一后台写入者原子替换原文件格式。普通快照合并，ready、退出、故障和控制回执继续走原持久边界 |
| QMT 通信库 | 沿用原 SQLite、命令状态及查询回收协议。已提交读取可用缓存，命令受理/派发、源确认、未知结果等继续在原承诺边界持久提交。数据库及 WAL 在同一个 D 盘目录，先测盘再评估合并能在同一事务完成的步骤 |
| 策略分账库 | 沿用 D 盘 SQLite WAL、原账户唯一写租约、提交后内存视图、后台 checkpoint。按稳定业务身份在写入前判定重复，后到事实和冲突经原归属流程核验 |
| 运行日志 | 后台按批写入 D 盘。重复普通信息按固定事件和作用范围聚合计数。原生 CTA 日志保存原时点，普通记录队满时计数并跳过，警告及错误沿原边界写入并刷新。首错、关键状态变化和审计记录单独持久确认，记录原时间、关联身份和后续处置 |

受管 CTA 在本代控制目录将首个成功刷新的 ERROR/FATAL 独立保存为 `native-first-error.log`，普通日志轮转及后续错误保持该文件。正文沿原 UTF-8 单条 8192 字节预算，含时间和等级后的文件不超过 8448 字节；没有错误时不创建。`native-log-status.json` 的 `first_error_saved` 仅在独立写入及刷新成功后为真。首次保存失败按原日志失败计数报告，普通日志继续写入，后继错误可以重试该独立副本；失败重试覆盖未完成文件，保持体积有界。各运行代沿原唯一目录及 owner 隔离，诊断保存不改变交易或恢复准入。

SQLite 的 WAL 负责已提交变更的重放，数据库事务负责失败回滚，checkpoint 在后台合并已提交页。内存视图在提交成功后一次发布。重启先取得原租约，再恢复最新已提交状态并核对未完委托和未知回报。原生文件格式继续由 WT 拥有。后续如需将多个原生文件改为增量提交，须先验证所有写入者、完整版本的原子发布和启动加载方式，并按[框架配置分流](../development/upstream.md#框架行为的配置分流)验收原生和显式受管两条路径。

迁移后采用执行权限变更时，前代和后代配置分别核验各自的持久化迁移证明，再将输出目录投影回证明中的原业务目录，统一比较账户、策略、执行参数及金融状态归属。Python 准备入口与 Native 启动入口使用相同的投影顺序。物理目录和迁移证明的完整性继续由原持久化 owner 校验；该比较不移动文件、不删除事实，也不按某次迁移的日期、策略或目录设置特例。

Native 启动异常区分持久化、权限、行情和策略配置阶段。原私有失败收据的 `private_exception` 保存最多 512 个 UTF-8 字节的异常原因，同时进入本代有界 ERROR 日志和首错文件；公开状态继续只提供原固定阶段与错误枚举。读文件异常仍保留原文件名和系统错误码，插件原因独立保存。该诊断不改变停止、恢复或委托授权规则。

## PERSIST-03 策略如何保存自己的数据

策略在注册时声明需要恢复的命名空间、记录键、数据版本、默认值、可重建条件及升级方法。命名空间由宿主绑定到账户和策略实例，策略版本变化通过显式兼容或升级处理。策略通过宿主提供的状态读取和原子提交接口工作，沿用现有用户变量桥作为 WT 适配入口。上线先以现有 ATR 保护线、持仓最高价或冷却期状态验证。回测使用每次运行独立的内存状态，以相同的键、序列化和状态转换验证结果。

常见接口为读取已提交状态及其版本、按预期版本一次提交一组改动。宿主负责原子提交、校验、去重及错误返回。键值未变时不生成新的持久提交。需要与目标或委托共同生效的策略状态，先持久化同一决策的版本和可追溯身份，再按原执行边界发布目标。重启核原目标/命令身份以决定是否继续处理。同键并发更新返回版本冲突，由策略重新读取。已有实例状态缺失或损坏时报告原因，首次启动仅对声明可初始化的字段采用默认值。状态升级先在副本验证，生效时保留旧版本及回退依据。

共享账户的实盘策略复用原分账账本的写入者。策略状态槽按账本与策略实例隔离。首次采用时读回原 WT 用户变量并核对策略协议。目标相关状态随原策略目标在同一账本事务内提交，事务成功后才进入原生目标设置。没有新目标时，状态变更可独立提交。重启从账本恢复已提交状态，绑定过该状态槽的当前目标沿原目标身份、价格约束与原生合并入口继续处理。未完委托及实际持仓继续由原账和原生风险流程核验。原 WT 用户变量在账本提交后同步为兼容副本。回退旧运行包前，须正常停止并核对副本与账本当前状态一致，以及原生目标与账本接续材料可用。回测继续使用隔离的 WT 用户变量。

## PERSIST-04 只记一次的规则

每个业务事实由其所属模块持久保存。其他模块保存自身职责所需的投影、引用或证明。去重先使用已验证的稳定身份及正规化字段，查询编号、回包摘要和本次数组位置用于追溯。去重与收件状态在同一事务内完成，重启后仍可判定重复。

成交以已校验的账户范围与原成交身份定位，比较证券、方向、数量、价格、金额、交易时点及已确认费用。委托以原柜台委托身份及其账户和交易日定位，比较状态、累计成交、剩余量及原关联。完整身份不足时沿原路径留存待核事实。首份有效证据、补齐归属/费用、独立来源首次确认及真实状态变化各保留一次。完全重复的查询不新增收件、来源证明或账本变更；同身份经济冲突保留首份冲突证据，重复冲突仍按原规则告警或拒绝。迟到旧委托状态不能覆盖较新的状态。待关联事实在原委托绑定后沿原身份重放一次。

## PERSIST-05 验收

受管分账批次以原生查询为采样边界，后台日志按运行代记录收件、投影耗时和行数。已投影行数、投影识别的重复成交数、未归属行数分别使用原结果的对应口径。日志记录不含账户、订单、请求原文或回报正文，沿现有有界队列与轮转保存。批次计时从构造分账收件事实开始，不含券商往返、外层排队或回包解码。物理磁盘归因仍以系统采样为准。

- 对照相同输入下两套策略的信号、目标、状态恢复、未完委托、成交、现金、持仓、可卖、费用与审计。验证跨账户、策略实例、同证券不同交易日、部分成交、撤单、乱序、费用和归属晚到、经济冲突。
- 对重复回报重放和重启后复放，断言新增收件、证明、分账变更为零。覆盖提交前后强制退出、checkpoint 并发、双写入者拒绝、恢复文件损坏和中断迁移。
- 对缺省、显式原生、显式按变化保存和非法配置分别验证。对相同状态连续调度断言按变化模式不重复写，真实字段变化与退出后恢复逐字段匹配。
- 逐项比较相同批次，验收策略已提交内存状态读取 p99 不超过既有 1 毫秒目标。账本回报批次验收沿既有 p99 不超过 2 秒、单批不超过 5 秒的口径，重复回报额外报告零业务写入后的时延。
- 记录按进程、文件及业务触发统计的写入次数、逻辑/物理字节、同步次数、等待、p50/p95/p99、最慢一批及恢复耗时。快照覆盖读者并发、状态风暴和原心跳时效。沿用现有业务截止，实测数据用于验收。
