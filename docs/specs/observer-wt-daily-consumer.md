# 观衡统一WT日线消费与后继历史保留

类型：功能规格。状态：accepted。范围：独立观衡消费者、观察目录和更新服务；需求来自Root分配的统一日线接入模块。总体职责沿[独立市场观察](independent-market-observation.md)及[ADR-0016](../architecture/adr/0016-independent-wt-runtime-and-observer.md)，生产端契约沿[统一日线](qmt-source-daily-history.md)和数据侧交付。页面沿已确认设计。

## 目标与现有接缝

WT数据侧拥有价格、证券资料、定日股票池、补充事实、缓存优先补齐、DSB持久化和CURRENT发布，Root拥有其正式进程与接线。观衡复用原MarketClient、指标公式、观察内容仓、SnapshotRepository、更新调度和Web。新增最薄的wt_breadth/wt_t2108消费者，不建立另一套价格存储或数据owner。原WT能力采用WT-D03/D06原存储和Reader；独立观察指标及归档继续归原App。

## 要求

| 编号 | 可观察结果与约束 |
|---|---|
| UOC-01 | 活动全A广度/派生六指标及T2108从同一WT入口读取。每个批次固定snapshot_id，价格、股票池、日事实的日期和版本严格相符，真实缺价、停牌、预热不足与复权未知保持。Root提供唯一正式监听及凭据。观衡不管理WT、QMT或数据生产者生命周期 |
| UOC-02 | 活动配置以wt_breadth/wt_t2108替代ashare_public/ashare_snapshot/qmt_t2108条目。其他独立披露/财务来源、全局792请求等实际预算、40自然日批次、09:00/17:30/21:00计划、模型及日历保持当前原件。来源接替只改变所属条目；旧实现保留在旧版本回退制品 |
| UOC-03 | WT生产端全天以此前最近闭合交易日为目标。source-aware-v1配置中的新WT条目选择cn-prior-day：按原窗口北京时间前一自然日回查官方交易日历，并受显式as_of上限约束；手工历史读取以当前观察时钟约束可用上限，显式日期仍可读取。其他来源日期策略保持。wt_breadth使用原默认7天重叠，覆盖正常新日并小于现行40天批次，避免示例91天重叠使现行小批次停留在旧区间 |
| UOC-04 | 后继目录保留当前线上全部快照、对象、发布/失败收据、窗口完成与尝试记录、后继历史和独立指标。活动SQLite采用备份API；最终采用前正常停止原独立更新服务并核最后提交，原目录继续保留。新目录及所有新产物在E盘。通过原refresh/逐键日期合并和CAS发布WT更新，旧60日覆盖不缩短；有实际修订时保留原快照及修订记录，不把缺数据填成零 |
| UOC-05 | 独立App/SPA、独立更新、停止/重启、快照恢复和保留兼容版本读取分别验证。切换时读取配置及个人目录延续；CURRENT账户/策略跟代、既有报告和其他日常页面不退化。页面只读查询不触发采集或补齐。回退保持原身份与完整旧原件，不删除或覆盖旧历史 |
| UOC-06 | 从隔离提交和固定SOURCE-CAS构建/安装后继制品，实际API和页面核七指标、选择日期及WT对应值/缺口；交付源码SHA、契约、部署身份、操作入口、验证及真实未覆盖范围。Root继续账户/交易/数据侧运行，正式端点就绪前推进所有无依赖内容，不另启真实数据owner |

## 兼容与验收

来源配置v1增加cn-prior-day枚举，仅新WT来源可选；旧来源配置继续可读。旧App仍可读取兼容观察快照，其更新器回退使用保留的旧配置或明确已验证的兼容入口，不能把新配置传给不支持的新来源的旧更新器。

先跑通消费者与实际合并主路径；现场接线到位后核真实WT读取和完整页面，再集中覆盖版本冲突、缺失/不可用、源日期变化、失败保旧、全历史保留、既有预算、更新恢复及回退。新布局和WT框架变更均不属于本模块。
