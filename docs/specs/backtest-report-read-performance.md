## BRP2 规范化与快照

快照按原JSON树复制和冻结。标量长度可以直接使用标准JSON等值编码规则，保留严格类型、非有限数拒绝、整数位数、字符串、深度32、节点1048576及字节预算。节点和最终check调用时机、原控制异常对象及深不可变语义保持。短字符串的编码长度只在本次调用内复用，缓存最多4096项、每项原文最多256字符；缓存满后继续正常逐值计算，不拒绝读取或改变计费。领域验证继续调用原类型及接口，资金、持仓、数量和报告数学函数保持原实现；不同报告分别准入；原报告缓存和新鲜度职责保持，长度复用不跨调用存活。

纯值包 `guanheng_strategy_native._numbers.text` 可将逐字符控制字符扫描替换为预编译的 `[\x00-\x1f\x7f]` 搜索。保持原严格字符串类型、长度、空白、控制字符的检查顺序，原QuantityError类别、文本和返回原对象语义保持；字符集合与原 `ord(char)<32 or ord(char)==127` 完全相同。其余Unicode字符、数值解析、精确有理数、数量转换、策略和领域数学正文保持。验收包括全部Unicode码点及原type/length/blank错误顺序等价、完整报告准入同值和实际HTTP收益；纯函数下降只属于定位证据。

Core `contracts.json_value` 可在原 `check()` 之后，对类型恰为内置 `str/int/float/bool/NoneType` 的值直接返回原对象，省去后续通用类型分派。数据类、日期、枚举、容器和标量子类继续原分派；节点访问次数、检查时机、异常对象、JSON值及键序保持。原数值和领域验证职责保持，完整报告逐字段等价及公开HTTP主链分别验收。

## BRP3 发行与验收

### 原5秒503的成功标量转换复用

已规范化报告会在纯模型重建及完整领域校验中重复使用相同数值。读取侧纯数量包允许分别以最多2048项成功缓存复用原`number`及`rational`的确定性转换；算法、数量计算和报告校验继续调用原函数。`number`键绑定精确值类型、字段名和`signed`布尔值，仅接纳最多256字符的精确内建字符串、最多256位的精确内建整数以及最多256字符的精确字段名。其他类型、签名标志或长度沿原路径；失败不缓存，保持原异常类别、文本和上下文行为。

`rational`仅缓存最多128字符、无指数的ASCII有限十进制字符串的成功转换；其余输入沿原实现。缓存保存私有转换结果，每次返回新Fraction实例，调用者修改结果的私有属性也不能污染后续值。单项分子/分母大小由键长限定，两类缓存均不保留任意对象，不保存策略或账户事实，缓存淘汰只影响性能。使用独立Native读取后继0.1.0a1+read2，执行侧原发行保持；原原件/来源/报告完整校验、800点输出、5秒总截止及关闭语义不变。

以App a57实际使用的固定WT纯读取包为基线，完整保留其模块及依赖闭包，仅选择明确读取后继；与WT运行包分别记录版本、wheel及安装SHA。先取得原HTTP主路径及测量证据，再验证JSON等值/边界/回调、错误恢复、普通新安装和物理关闭。并发排队沿原有界读取语义，忙或截止失败如实保留；一次成功不授任意负载下的时延保证。真实QMT、回测重算、原生C++组件重编、WT核心及生产发布不属于本模块。

选择纯文本优化时，纯值包以独立新版本/wheel/SHA交付，原同版本字节保持；只读组合的精确wheel锁记录实际依赖。读取层没有新增实现变更时复用原WT wheel及全部模块，发行身份沿实际组合记录。预建普通安装按精确wheel锁和原pip检查核身份；后续App源码闭包构建明确声明所选完整版本，沿原安装器的版本准入。运行侧已验依赖独立保留，读取侧优化不隐式升级执行环境。

所选依赖使用local修订版本时，源码选择器和Core/V1共用的运行时身份入口采用一致的依赖匹配语义：未含local的公开`==版本`接纳同公开版本的合法local修订；显式local要求完整版本相符。包自身source_manifest与METADATA版本、两侧依赖声明文本继续严格一致，完整安装版本和文件摘要记录在实际组合锁与收据中。不同公开版本、非法修订、来源或摘要失配仍拒绝。此范围仅实现项目使用的规范版本形式，通用PEP版本归一化另验。
