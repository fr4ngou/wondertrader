# ETF与常用指数分钟历史批量准备

> 源码交付范围：本页标注的外部历史/待归仓路径用于追溯原记录，未随本次源码提交。其旧通过记录不授当前入口可复现资格；当前构建与运行以对应永久源码及正式安装手册为准。

类型：功能最终规格。状态：accepted。前缀：EIH。适用范围：WT运行侧按明确证券集合准备QMT一分钟历史；需求由用户2026-10-30委托确认。

## 目标、根因与关键决策

基金大类混合ETF、债券和其他业务代码；缓存存在、下载函数返回与完整历史分别是独立事实。使用QMT实际板块和证券元数据冻结ETF集合及50个具名常用指数，先复用缓存，再补实际缺口，保留2021-11-01至最新完整交易日之间实际可得数据。较晚上市或编制保留实际首日，交易日和分钟完整性缺少权威依据时明确unknown。

依[ADR-0016](../architecture/adr/0016-independent-wt-runtime-and-observer.md)，WT拥有通信、缓存准备和历史读取，观衡仅只读消费。复用WT-D03/D04/D05/D06/D11：原QMT内置下载→原缓存→DAT导出（外部历史/待归仓路径：`../../integrations/guanheng/qmt_local_dat.py`）→QMI Importer/WtDtHelper→标准DSB→NativeHistory→原source-stores与公开SDK。批量模块只补证券选择、缺口计划、逐项可恢复进度和完整store替换闭包；WT框架、通信协议及读取服务保持原接缝。

## 状态与恢复

逐证券保留计划、原下载请求、缓存观察、转换收据和回读结果。缺缓存、尾部过旧、源不可得、源变化、源质量拒绝、已导入及未知下载分别表达。下载与转换分阶段推进；任何失败均保留原目录和原数据。源变化先等待稳定并核原请求，随后以新独占输出转换。50是本轮用户选择的规模，产品的通用查询和补齐准入继续沿来源能力。

批量进度仅记录作业状态和已存在事实，不另建行情数据库。原source语义、未知单位和价格质量由既有Exporter/Importer/Reader拥有，禁止猜倍率、造分钟、负数调零/取绝对值或静默丢行。部署集成由主会话完成，旧活动配置与数据保留。

## EIH-R7 下载前快照、来源修订与历史保留

下载前留稳定完整副本及SHA；原WT成功store始终保留。逐分钟比较新来源和旧快照，记录原有标签是否保留、重叠数量及六字段变化。正式转换直接消费供应商新原值；原Exporter/Reader继续检查负量额和质量。新来源缺少原已观察分钟时明确登记source_range_reduced，保留旧输入和旧WT根，核实该证券范围后再替换。

2026-10-30三个指数的实际重取包含全部原缓存分钟，并修订旧负量额；未观察到旧分钟丢失。较早的临时“范围减少”判断经完整标签集合复核后已撤回。正式实现保持单一来源转换，没有增加分钟合并存储或人工价格修复。验收覆盖真实修订、原字节保持、未修复负值拒绝、未知请求原ID恢复及store闭包。

当前实施与真实范围由[专项证据](../evidence/2026-10-30-qmt-etf-index-history.md)记录。

## EIH-R8 可恢复批次、容量与完整入口

逐证券状态是详细事实正文；批次`RESULT.json`只保存证券、阶段、行数、首末时间、请求ID、剩余窗口数量及状态文件SHA，支持至少本轮1,764只证券而不复制完整逐日字典。输出根、证券子目录和已有JSON必须是普通目录/文件；junction、symlink及身份变化拒绝。

下载前先发布源身份intent，再复制DAT。完整副本已写、证据未发布时按原SHA恢复；部分副本通过稳定恢复事务保留，移动前、移动后及新intent发布后的中断均沿同一事务重放，确认请求尚未发送后以当前稳定源重建，不覆盖遗留字节。终态请求回读后仍有缺口时，默认保留`remaining_windows`；只有计划内全部原请求成功终结后，显式`retry_observed_gaps`才追加新的观察缺口，原请求仍只GET，窗口预算阻止循环重派。

正式入口分为`audit/prepare/freeze/convert/assemble/catalog/qualify`。`audit`将完整观察分证券保存并发布紧凑总收据；`freeze`只接收`cache_observed`且范围未缩短、量额合格的逐证券状态，并按清单身份从部分副本恢复；准备结果、manifest和状态均以同一批稳定字节同时解析并计算SHA。`convert`在原Helper调用前后两次逐项复核冻结完成收据、快照收据和实际DAT，转换条目的来源SHA必须与冻结输入全集一致，再由原Reader逐行核对；所有外部文件读取受截止时间和字节预算约束。`assemble`直接消费一个或多个转换结果，解析原生导入收据，逐成员核代码、市场、条数、首末时间、路径和SHA，并要求收据成员全集等于转换store成员全集；随后执行完整旧store闭包并绑定输入SHA。`catalog`生成原source-catalog配置；`qualify`在同一拥有线程创建/关闭原NativeSourceMarket及HTTP服务，由公开SDK实际查询新ETF、新指数、旧ETF和未替换股票，逐例核精确条数、首末分钟及完整六字段序列SHA，临时认证值不持久化。
