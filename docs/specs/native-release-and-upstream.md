# 原生制品发布与上游维护方案

类型：系统运维方案。状态：proposed。权威范围：原生运行组件的制品身份、部署、上游更新及验证门槛。本文定义目标流程；自动化发布器、进程托管和完整 E2E 的实际交付由对应实现任务与证据确认。

## 目标与职责

构建一次、校验后分发同一制品，运行版本可查询，升级可恢复；跟进上游时保持可追溯历史与较小的自有差异。业务服务、原生运行组件、服务商终端及持久存储按各自支持环境部署，整体使用一个兼容版本清单关联。

## NRU-R1 制品身份

原生发布单元为经过验证的程序、核心库、插件、必需运行库、获准分发的 SDK、配置模板和许可证集合。绑定发行版本、下游 source commit、上游 base commit、构建工具链/选项、平台/架构、逐文件哈希、配置/状态/协议版本及依赖。

程序版本号用于识别发行系列；完整运行身份由制品清单、实际加载文件与生效配置共同证明。容器组件记录镜像 digest，原生组件记录包与文件哈希，外部终端记录支持版本；整体兼容性分别验收。

## NRU-R2 部署形态

依赖桌面终端或 Windows SDK 的原生组件在匹配的 Windows 用户会话/主机运行。兼容的 Linux 数据、回测或业务组件可以使用容器；容器镜像继续按固定输入构建。采用某个框架不隐含改变所有业务服务的部署方式。

构建环境与运行环境分离。生产接收制品及受控配置，现场源码和在线编译不作为运行版本来源。进程由经验证的监督入口管理，桌面会话依赖先验收，再选择服务或用户会话托管方式。

## NRU-R3 程序、配置与持久状态分离

发行包按版本保留且不可覆盖；实例使用稳定工作目录、状态目录及配置快照。日志、数据、运行状态和执行恢复记录不随包替换或回退而删除。

路径解析、插件搜索、动态依赖、日志、相对数据目录及访问权限通过包级启动测试确认。生产实例与隔离实例使用不同状态和路由，不同时写入相同账户执行空间。

## NRU-R4 切换与回滚

顺序为：验证候选身份及兼容性 → 暂停受影响新增准入 → 核实在途/未知副作用及回报连续性 → 受控退出原实例 → 指向固定新包与配置启动 → 核实加载身份及完整调用链 → 逐项恢复准入。

回滚选择经过验证且能读取当前状态的旧包及适用配置，保留已发生的外部事实。未知状态、旧实例仍可写或状态不兼容时保持相关准入关闭，按恢复方案处理。单纯替换文件不等同于安全回滚。

## NRU-R5 上游基线与历史

`upstream` 跟踪原项目，`origin` 承载本系统代码；正式主干保存已集成版本。上游基线使用完整提交身份，跟踪值只在成功集成时更新，fetch 不推进生效基线。

共享主干吸收上游使用保留上游祖先的 merge。功能分支按项目集成规则处理；个人且尚未共享/发布的分支可以 rebase，已发布提交和标签保持原身份。上游更新经隔离集成分支验证，再进入正式主干。

## NRU-R6 差异控制

扩展优先通过公开接口、插件、配置和独立模块实现；公共核心确有缺口时，用小范围、单职责修改表达，并记录依据、测试及后续退出条件。

功能变化与上游格式整理分开。保留原文件风格，减少无关重命名、移动及全文件换行变化。构建接线集中到明确入口，项目规则、测试与文档使用自有路径；核心覆盖差异使用[覆盖登记](../maintenance/upstream-overrides.md)追踪。

## NRU-R7 更新验收

上游更新核对变更日志、公共接口/布局、状态格式、时间/单位、策略调度、风险/执行与恢复、依赖和许可证。按原基线、上游新基线、下游旧版和合并候选进行三方语义核对。

验证包含受影响 UT/组件、适配器契约、固定数据回放、无真实账户副作用的端到端链，以及适用的打包、重启和回滚。没有文本冲突只表示 Git 合并顺利。必要时向上游提交通用修复，保留来源和集成关系。

## NRU-R8 测试层次

系统验证由 UT、组件/契约、完整隔离 E2E、故障恢复、实际终端只读资格、受控模拟及发布后真实入口验真组成。各层结论独立，按影响选择和复用输入匹配的证据。

最小隔离 E2E 为：固定行情/历史 → 实际策略运行与审批接缝 → 执行插件 → 隔离后端 → 订单/成交/账户回报 → 业务读取；断言结果与退出状态，覆盖重启、重复回报和未知提交。适用层依赖未提供时报告明确缺口，测试名称和进程启动不充当通过结论。

## NRU-R9 通用治理承接

长期保留根因修复、最终规格、完整调用链、事实所有者、可变配置、按影响验证、内容身份绑定证据、独立审查、唯一集成者、状态/规范/历史分层以及发布后业务验真。工具与平台命令按实际工程实现，工作原则保持一致。

审查与检查明确 full/delta/reuse/none 的实际范围和原因；独立审查依据最终规格及源码，开发过程和历史自评单独保存。源提交、制品、运行身份与账户授权分别核对。
