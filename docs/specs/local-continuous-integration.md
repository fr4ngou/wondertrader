# 本地持续集成

类型：功能规格。状态：accepted。适用范围：开发候选的验证及合入本地master；用户明确要求CI在本地执行。

## 目标与职责

LCI-01：统一入口自动选择已有文档、Python回归和执行链测试，保存实际日志、退出结果及代码身份。CI调用现有`native.run`、pytest及产品CMake工具，测试进程在隐藏控制台和受管进程树内运行。

LCI-02：`integrate`默认先运行CI，再将同一被测内容快进合入指定本地master工作区。开发者可用`check`预跑，再显式复用匹配的成功结果。流程不访问托管平台、不执行推送、发布或真实账户操作。

LCI-03：范围由版本化`config/local-ci.json`及入口的改动映射决定。纯Markdown变化执行文档检查；软件变化执行当前登记的软件回归；执行相关源码、协议、构建或测试变化追加原生构建与共享内存E2E。缺少依赖或测试入口执行失败时保存失败结果，master保持原样。完整测试覆盖以实际登记的选择为准。

LCI-04：结果绑定Git索引与实际修改内容的blob身份，并对整个映射计算SHA256。检查过程中源码发生变化时，结果失败；合入前源码、改动范围、必需阶段和master基线再次核对。检查成功后的同内容提交可复用结果。master推进时先将其合入候选，再重验新组合。

LCI-05：合入由正常Git快进完成，保留master工作区的无关改动及Git冲突保护。候选需已提交；CI不代替用户选择提交范围。直接执行普通Git命令仍遵循原Git行为，本入口尚未安装仓库钩子，自动检查由统一本地合入命令触发。

LCI-06：执行E2E从当前永久源码和已批准的WT快照重新构建Host、标准插件及执行器，复用固定工具链与依赖源码缓存。使用独立的SYNTHETIC账户、共享内存、端口和结果目录，实际券商SDK调用0次。当前四场景定义沿[测试模块](../../tests/integration/qmt_broker_context/README.md)；当前列表缺失只授身份保留检查，历史恢复及完整策略验收分别登记。

## 边界与验收

源码可复用工具及缺口见[WT能力目录](../development/wondertrader-capabilities.md)及[测试手册](../runbooks/testing.md)。WT负责原执行算法，CI负责编排检查。现有构建和进程工具继续复用；Git托管工作流文件保持原样。

验收覆盖：真实本地Git候选快进成功、测试子进程失败不合入、源码变更拒绝旧结果、master变化拒绝旧组合；实际C++重新构建及四项SDK替身E2E。完整策略、真实QMT跨日、前端浏览器以及未登记模块测试尚不由此套入口覆盖。

操作见[本地CI手册](../runbooks/local-ci.md)。
