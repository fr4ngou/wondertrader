# Windows 原生数据库部署

类型：条件部署规格。状态：proposed（数据库保留范围复核中；若确需数据库，其Windows非Docker部署约束已确认）。依据：用户要求优先复用WonderTrader已有行情存储及订单成交记录，并质疑继续保存重复数据库事实的必要性。范围：经业务职责复核后仍需保留的观衡持久化；原生WonderTrader的数据文件保持原职责。

## WDB-R1 职责

前置条件：先完成WonderTrader原生能力与观衡剩余业务逐项映射，旧系统使用PostgreSQL不构成新系统必须保留它的依据。行情主存储使用WT原生DSB/DMB及读取接口；基础订单成交记录复用TraderAdapter的savedata输出及原插件查询/回报。观衡展示通过适配读取，新增全量行情副本和另一套基础订单账本须有独立必要性。当前新增PG分钟接纳方案暂停作为默认交付路径，保留未发布代码供复核；现有生产数据及命令恢复事实保持。

WonderTrader 的行情文件、回测读取和内部状态沿原生存储接口运行。旧观衡PostgreSQL当前保存业务配置、审批/命令/审计事实、行情事实与投影及持久消息确认；此句描述旧系统现状，不规定迁移后的保留范围。TimescaleDB是该PostgreSQL实例中的扩展。观衡剩余业务需要哪些持久状态、能否复用现成能力及具体存储方式须逐项证明。

## WDB-R2 部署目标

Windows 主机上的业务数据库以原生 PostgreSQL 进程及受管服务运行，版本化程序与稳定数据目录分离，数据、WAL、日志及备份放在明确规划的 E 盘目录。数据库运行不依赖 Docker Desktop 或 WSL。锁定 PostgreSQL、TimescaleDB、运行库与工具版本；服务身份、ACL、端口、连接池和内存预算由一份受管配置拥有。

其他业务组件是否仍依赖 Docker 单独盘点。数据库迁出本身不能证明整套系统已解除 Docker/WSL 依赖；测量迁移前后进程与整体资源占用，报告其他常驻组件。

## WDB-R3 兼容与数据迁移

先核实已安装版本、扩展、全部迁移、hypertable 和压缩依赖，再选择可验证的 Windows 组合。当前旧库迁移显式创建 timescaledb、行情 hypertable 和资金投影 hypertable，并配置压缩。普通 PostgreSQL 裸安装不视作可直接恢复的兼容环境。若扩展缺少合格原生版本，提交明确替代设计及数据转换范围；禁止跳过迁移或删去压缩条款冒充验收通过。

Linux 容器与 Windows 原生实例之间采用经版本验证的逻辑导出/恢复或官方支持的迁移方式，禁止直接搬用跨操作系统物理 PGDATA。隔离演练比较模式、行数、关键事实摘要、时区、数值精度、唯一约束、事务与恢复结果，验证完整业务入口后才准备生产切换。

## WDB-R4 测试设施

新增原生 PostgreSQL 测试 provider，复用原 fixture 对外契约，使用独立端口/数据目录/数据库，不接生产 DSN。保留创建、迁移、失败留存、真实事务/并发、重启、备份恢复、所有权核验和有界关闭语义。验证不依赖 Docker 的 PostgreSQL 链；NATS 等额外测试依赖另行盘点。

现有 Docker 隔离测试设施可继续用于收尾和既有回归，它是过渡证据。完成原生 provider 后切换默认开发流程并登记支持矩阵，原生产实例持续保持至受控迁移。

## WDB-R5 发布与回退

开发阶段完成原生安装包校验、隔离实例和完整调用链。生产迁移前提供准确备份、短暂停写/在途排空、连接切换、验真与回退命令，按生产授权执行。旧库保留到验收及保留期满足；避免双写和同时运行两个业务事实所有者。归档清理保持逐项授权范围。

## 依据

2026-10-21 代码核对：原观衡 ADR-0004 定义 PostgreSQL/NATS/MinIO 职责；迁移0001、0002、0070、0083定义现有扩展、hypertable与压缩依赖。本机服务枚举当时未发现 PostgreSQL Windows 服务，此观察不证明所有目录均未安装二进制。

PostgreSQL 官方提供 [Windows 安装程序及二进制 ZIP](https://www.postgresql.org/download/windows/)。具体 PostgreSQL/扩展组合的安装、恢复和资源占用资格仍须实测。
