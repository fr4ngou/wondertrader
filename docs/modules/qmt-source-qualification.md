## 可以交付什么

原111快照的510300.SH曾缺2026-10-21和22；117通过原策略显式补齐后，119回读已取得这两条，121原生逐值验证和123安装SDK主链通过。最新9ETF覆盖全部401个已核正常交易日，较早512100.SH的2022-09-02差额仍待核实。589680.SH和589000.SH在2025-03-05上市，上市前的空白不应补成价格或代理证券。

## 接口关系与证据强度

已安装 `qmt_api/api.py` SHA-256：`cc695081bf5e018e98e6ad2a0d56526c48c1fe91869f3329482346adf874ab34`。源码293–319行给出准确调用链：

```python
# 安装包公开包装，示例；本轮111使用同一request取得未经DataFrame整形的回复。
api.get_market_data(fields, [symbol], start, end, '1d', 'none', count)
# -> api.getMarketData(...)
# -> api.request('getMarketData', {
#      'fields': fields, 'stockCodes': [symbol], 'startTime': start,
#      'endTime': end, 'period': '1d', 'dividendType': 'none', 'count': count})
```

这个snake_case函数与camelCase函数的关系已经由源码证明：前者直接转调后者，后者整形同一RPC返回。源码71–75行请求超时为10秒。源码310–385行未增加金额/成交量单位换算；其中多证券历史包装仍使用旧 `pandas.Panel`，单证券或原RPC解码可避开该包装兼容问题。

内置 `ContextInfo.get_market_data` 和 `ContextInfo.get_market_data_ex` 属于文档记载的行情函数系列；本机213页手册第50–53页与当前官网分别说明旧式多形返回和ex返回。**安装的外部包装没有 `skip_paused`、`fill_data`、`subscribe` 参数，也没有ex包装。** 外部RPC服务端实现未在上述Python源码中出现，因此不能从名字或共同尾部推定它等价于内置ex的 `fill_data=False, subscribe=False`。已留存内置589680读回401行的诊断仅记录数量和首尾，不能证明六字段逐值等价。可在以后授权的原策略线程通过既有SHM只读路径，取得同窗口六字段+日期摘要并与外部原回复逐项比较；无需更换SDK或引入HTTP。

当前官网的[内置行情函数](https://dict.thinktrader.net/innerApi/data_function.html)与[数据结构](https://dict.thinktrader.net/innerApi/data_structure.html)用于解释函数族；它们不是本机安装版本的替代证明。原安装手册、API身份和运行观察见[国信Python手册](../runbooks/guosen-qmt-python.md)、[安装证据](../evidence/2026-10-28-qmt-installed-runtime.md)及[单位与补齐证据](../evidence/2026-10-28-qmt-daily-units-backfill.md)。

## 金额的可复算推导

本机手册第51、208页和当前官方字段表均将amount称为成交额，未给出日线金额缩放。本机手册第212页“大单100万元”等阈值描述另一个分类规则，不能充当本日线字段的单位声明。[官方云行情字段表](https://knowledge.thinktrader.net/docs/cloud/data_function.html)明确日线volume为手，但amount仍只有成交额说明。

最新119批次9ETF共9271条，全部volume、amount为正。设 `q=amount/(volume×100)`，逐条用JSON数值的十进制表示重算，9271条均满足 `low≤q≤high`，零容差、零例外。若真实金额为 `k×raw_amount`，所有行的约束交集为：

```text
0.9986742209061336437560247165 ≤ k ≤ 1.001514925334205745403675166
```

在10的整数次幂缩放候选 `10^-6..10^6` 中，仅k=1成立。这为“raw amount是人民币元”提供强数值支持。推导前提是：OHLC未复权且以元/份计，volume已确认为100份一手，量额与OHLC覆盖同一批成交、同一交易时段，成交均价处于该日高低价之间。推导不能排除任意接近1的系数、源舍入或场所/盘后范围差异，也不能证明历史数据未修订。完整条件、公式与结果保存在 `ANALYSIS.json`。

B当前 [kernel.py](../../apps/guanheng/strategy_core/guanheng_strategy_core/kernel.py) 的amount仅参与有限数值、非负校验；当前核心未用它计算特征。可以继续完成真实OHLCV主链和显式假设的回放；amount未知应展示为来源限制。需要把amount用于资金、成交额筛选或其他有量纲判断时，补齐本接口供应商单位说明，或与有明确元单位的交易所逐日金额校准并由来源profile明确接受推导。两者的证据等级分别记录。

## 日期与真正可知时间

111的请求截止20261028235959，回复日线标签YYYYMMDD；整批完成时刻是2026-10-29 01:13:24.380+08:00。当前证据只证明这批值最迟在本次成功读取完成时已被本次采集器收到。原脚本没有逐行接收时刻，也没有历史首次发布、当时最终版本或修订序列。请求开始时间不能充当成功接收时间；日历15:00不能充当供应商发布证明。

准确区分三个时间：`trade_date`表示交易日；`bar_end/model_close_at`表示模型认为观察区间结束；`observed_at/received_at`表示本次采集器实际收到某版本。若业务使用 `available_at`，应声明它指供应商首次发布、系统首次实收，还是回测假设；每条事实的来源与修订身份随之保留。

B现状是 [models.py](../../apps/guanheng/strategy_core/guanheng_strategy_core/models.py) 19–20行把观察截止固定15:00；kernel169–172行要求每行market_available_at带时区且≤该行当日15:00。给111诚实填写本次实收时间会被拒绝。这是现有策略时间契约与事后快照证据的差距。把时间改成当日15:00能绕过检查，却制造了源未提供的事实。

可实际采用的两个方案应分别验收：

1. **M1历史回放**：使用固定119源值、明确单位假设、交易所日历和完整401日区间；报告声明“事后取得的最终日线、日末模型回放，历史首次可知和修订未知”。由B明确区分模型截止与真实实收字段，规格允许这种研究输入后运行；报告不宣称严格逐时点无前视证明。保留原严格模式，不把假设写进真实available_at。改变成交时机到下一交易日也必须按策略时机规格重新验证；仅平移时间不能证明旧数据当时已经发布。
2. **后续实时运行**：原策略线程在收盘后通过受限只读入口取得闭合日线，Host在接收完整回复时记录真实received_at、源会话、摘要和版本。全标的同日完整、日历有效、单位已接受后，决策时刻必须不早于所需事实实收。收盘事件、SDK可读、数据最终不再修订须分别确认。要用同日15:00成交模型，需另有可执行时序论证；一般收盘后收到的数据只能服务之后的决策。真实盘中/收盘观察和系统延迟本轮没有验证。

这些是消费契约建议，未修改B生产代码、运行配置或交易权限。来源研究、缺口核验、回放候选准备可独立推进；研究结论不会给账户或策略增加执行权限。

- 固定API、原文档、111原回复/rows/采集脚本及B源码SHA；新数据重新计算，不复用旧批金额推导。
