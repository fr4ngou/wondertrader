# 完成回测报告的只读准入

类型：模块说明。行为要求以[BRP](../specs/backtest-report-read-performance.md)和[NBW](../specs/native-backtest-workspace.md)为准。

## 职责与调用链

观衡归档HTTP先核完成证明、原请求、安装和所有原生输出，再调用WT自有 `backtest_reports.normalize_session`、`validate_report_dict` 及 `project_session_record`。报告准入复用 `retained_report` 的原领域校验、持仓/资金/数量核对及纯核重演。读取层只消费完成结果，不拥有执行、QMT通信或模型运行。

纯值包的 `guanheng_strategy_native._numbers.text` 承担有界文本准入。控制字符扫描可使用与原逐字符判断等价的编译搜索，类型、长度、空白和控制字符的检查顺序及QuantityError语义保持；金融数值、数量和策略数学函数保持原实现。该优化作为独立纯值发行固定到只读组合锁，运行侧依赖独立保留。全Unicode/错误顺序等价、完整报告同值及实际HTTP证据分别登记。

`normalize_session` 的固定基准输入族沿原实现。逐日输入先通过原 `RetainedReplayInput.from_dict` 和 `normalize_source_binding`，由原 core `json_value` 处理时间、枚举和数据类。适配层将该私有树一次转为有序独立纯值，逐节点计入与紧凑 `ensure_ascii=True` JSON相同的字节数；原8MiB内层及16MiB外层额度保持。此纯值与 `loads(canonical_bytes(...))` 等值且同键序，省去编码后解析同一数据的往返。

`report_values._snapshot_json` 在领域验证前拥有独立JSON树。每个出现位置分别计费并执行原节点、深度、类型、非有限数、大整数及检查回调规则。调用内最多复用4096项短字符串的编码长度，缓存满后继续计算；这只复用不可变标量的编码成本。报告和不同文件的身份及完整领域准入分别保留。快照完成后继续原深冻结，投影返回副本；调用方修改输入或投影不会修改已准入报告。

Core `contracts.json_value` 的纯值分派可在原检查回调执行后，直接返回类型恰为内置字符串、整数、浮点、布尔或None的原对象。其余类型继续原分派，标量子类、枚举、日期和容器语义保持。读取性能验收分别核对完整报告、回调时机和实际HTTP结果。

## 生命周期、错误与资源

此模块不创建线程、进程或持久缓存。调用方拥有HTTP操作的原绝对截止、累计读取预算及原控制异常；报告边界保留原异常对象。归档持有原文件和摘要证明，损坏或身份变化由原归档准入拒绝，恢复原字节后可沿同身份重新读取。每次请求重新核当前原件，不凭前次成功延长数据资格。

短字符串长度缓存仅在单次规范化或快照调用内存活，键最长256字符、最多4096项，超出后继续逐值编码。输出容量仍按每个出现位置累计。此额度控制优化内存，不限制可读取的证券、报告或字符串数量。

## 安装与维护

观衡使用独立的完整WT纯读取发行，保留原报告族和依赖。选择候选时核固定wheel、普通安装收据及全部35模块，WT运行角色与此读取发行分别记录。局部读取发行版本不授WT执行或真实来源资格。

验证入口位于模块证据中，覆盖原实际HTTP双报告比较、同身份恢复、原输出损坏拒绝、容量、字段/键序、回调和深不可变。纯函数性能测量用于定位，普通安装的原5秒HTTP主路径单独验收。
