# 原生超时撤单与已知挂单恢复

状态：开发及隔离验证通过；实际采用沿后继发布记录。范围为自有执行宿主、QMT标准插件、Python观察接线及执行配置，新增WT框架修改为0。

## 根因与实现

实际原配置expire=0，Native初始化日志亦为order expired: 0 secs，关闭了WT原生超时撤单。两笔模拟买单于14:52/14:54报出，首次撤单在17:08停止期间。SDK请求已发送与券商终态分开确认，未确定模拟柜台迟迟不回终态的原因。

自有恢复另要求活动单先撤清，并在恢复后放弃NSQ冻结阶段。现改为沿原完整O、后继P/A保留原WT订单表和Host journal身份。原插件只读区分已核活动子单与未知调用，正常关闭允许已知挂单接续；未知、缺身份及终态后未同步P继续原核查。恢复保留冻结阶段，原活动单值进入NSQ pending与观察身份；原执行器继续拆单、余量及撤单，不新增订单表。

显式发行允许调整原股票执行器expire/is_cancel_unmanaged_order参数，原资金及策略模型保持严格。部署采用60秒超时及WT原重连自有挂单撤单入口；原Adapter只提供已核本通道订单。原生算法、文件格式、资金/持仓账保持。
