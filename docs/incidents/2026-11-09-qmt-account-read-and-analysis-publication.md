# 2026-11-09 WT 账户读取拒绝与行情发布接线故障

主要故障。原模拟账户及交易实例已恢复。凌晨 HTTP 拒绝的具体来源仍缺原始回包，收盘后未验自然策略调度。时间均为北京时间。

## 故障证据

- 01:52 正式原生实例就绪。02:24:05.876 资金查询成功，02:24:06.235 持仓查询成功。02:24:36.382 原生交易插件记录 `qmt_http_remote_invalid_input` 和通道断开，Runtime 随后停止。原回执只保留通用类别和摘要。
- 下一轮 30 秒资金刷新是与时序最吻合的请求，按最早调度时刻至报错约 147 毫秒。原账户任务预算 30 秒，显式票据上限 5 秒。现有时序与该轮新票正常超时不符。
- 原部署插件在隔离资金准入和交易事件页分别收到 HTTP 400 时，都复现相同的硬故障和凌晨摘要。原回执无法反推唯一入口。故障窗口前后交易事件水位、165 条事件及原 56 条交易命令一致。QMT 行情日志的周期性连接维护前后均出现，缺证据将其与交易 HTTP 拒绝关联。
- 已确认的退出根因是旧插件把这类 HTTP 参数拒绝升格为交易通道硬故障，隔离试验复现了未准入只读请求的同一传播链。另有独立行情接线问题，端口迁移后原生 Reader 继续读取旧发布器状态，摘要与公开行情窗口不一致。
