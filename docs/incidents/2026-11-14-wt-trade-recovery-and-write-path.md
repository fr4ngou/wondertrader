# 2026-11-14 WT 交易通道超时与重启接账失败

状态：修复候选开发及验证。北京时间 09:53 原交易 Host 退出，WT 停止两套策略。12:20 正式重启时 QMT 读回账户和持仓，执行器在恢复准入失败，未开放新委托队列。

## 根因与复现

- 09:53:09 原账户查询已返回，Host 持久结果超过原 2 秒预算；同请求续查没有记录结论。09:53:17 Host 退出并报告清理未确认。上游 WT 将新增委托挡住，执行器停止超时而被强制退出。线上代码在核查 Future 再次超时时将异常抛出。用线上同版代码注入连续两次超时已复现。现场记录未量出队列、锁、批处理、提交分别耗时，故首次超时的具体慢点仍待分段证据。
- 12:20 普通启动遇到已有 WT 故障收据，跳过核查旧执行进程实际退出，缺少旧原生进程退出证明。原生初始化因此读取不存在的关闭预备收据，错误被压成通用初始化失败。按原配置、账本摘要及前代目录重放条件，配置兼容、文件摘要一致、原进程已退出，读取关闭预备收据返回 Win32 错误 2。12:20 失败代没有接账认领、未进入执行循环，恢复队列计数为零。
- 修复在 Host 原控制节拍持续核同一只读请求，保留首次保存期限。复现 SQLite 写锁竞争时，100 ms 测试预算在 BEGIN 阶段实际等待 172 ms 并返回 SQLITE_BUSY；该错误也进入同一只读续查。普通启动在生成接续材料前核旧执行进程实际退出并登记证明。失败代满足原执行未启动、接续未认领、原状态未变的证据后，使用最后有效执行代。日志记录首次故障阶段、原生初始化细步与文件错误、查询摘要、各阶段毫秒数和清理结果。见[恢复规格](../specs/execution-fault-recovery.md)及[交易 Host 验收](../specs/qmt-trade-host-product.md#验收)。

## 存储改造与验收

先在同一份通信库副本和同批回放下测 E、D 两盘，记录每类写盘次数、逻辑字节、写入和同步耗时、锁等待、事务提交和 checkpoint。用资金/持仓周期刷新、启动四类账户查询、交易回报与查询并发、策略实际变更和无变化各组对照。写盘计数与策略线程阻塞时间分别记录。

共用规则采用按业务责任分级。可重建状态由内存保存最新值，后台合并成快照。恢复所需状态以单写入者处理，已持久的变更记录用于重启重放，事务回滚处理未提交更改，后台 checkpoint 合并。影响外部交易的命令身份、已接收成交、分账和去重记录在确认前持久提交。复用现有 SQLite WAL 及事务边界。通信库迁往 D 盘前，用停止后的完整副本做原身份续接，覆盖提交前后强退、待确认命令、回报去重、账本对平和唯一写入者。
