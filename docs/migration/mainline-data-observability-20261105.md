# 自动交易主线的数据、诊断与日志收敛

类型：实施方案。状态：implemented / online。依据用户2026-11-05批准，最终合同为[SDO](../specs/strategy-data-and-observability.md)，目标沿[完整TARGET](../roadmap/TARGET.md)，承接[整体方案](guanheng-qmt-tdx.md)。当前完成范围、真实挂单与来源边界见[正式在线核验](../evidence/2026-11-06-mainline-online-acceptance.md)。

## 目标、根因和决策

本轮起点：价格链已提供当日窗口，四类辅助字段全空，三个角色无模型买卖、部分份额退出不可触发。原报告未明确此缺口，回测可结束及其他标的成交掩盖业务缺失。部分子进程stderr仅存内存，发布检查缺逐组件日志/输入覆盖。

复用WT原生行情、调度、执行、状态及日志。自有适配取得辅助事实，唯一业务模块派生并由WT持续发布；观衡独立只读。保留100万元含持仓基准、实际周期及模拟账户；旧QMT仓库只读参考。不填零、不改公式、不伪造历史知晓时间、不新增人工上线审批。新增WT框架改动仍先说明并获批准。

来源选择补充：按用户要求，优先核对国信QMT内置读取能力和已有缓存，复用现有共享内存通信；旧QMT项目只读追溯原来源和算法。来源优先级、字段核验和受限运行要求由[SDO-R1](../specs/strategy-data-and-observability.md#sdo-r1-目标与复用)统一维护。开发者1负责标准化接口和持续更新，杂役核历史可得性，Root核官方接口并统一现场验证；已核交易所来源继续用于补充，避免等待一项接口结论阻塞整个模块。

## 实施顺序

1. 冻结SDO数据/时钟/诊断合同、文件所有权和完成标准。
2. 各模块独立跑通实际主链，Root并行处理日志与自动运行阻断；长历史补齐不阻塞其余功能。
3. 逐层核原文、派生、合并生效、策略消费；历史首次未知或源限制明确交付，研究假设单列。
4. 主链完成后补根因回归、恢复/异常及独立审查，一次交付提交/SHA、命令/结果及剩余。
5. Root统一采用WT，观衡读取独立采用；核发布日志、逐角色输入/信号、自然调度和真实模拟业务。旧有效下撤单证据复用，不代替最新策略自动结果。
6. 完整在线验收后清理无引用工作树、进程及可重建产物；保留业务数据、原件、金融状态、回退和未合入成果。
