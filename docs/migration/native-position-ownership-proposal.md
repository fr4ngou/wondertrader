# 原生组合仓位对象的内存所有权候选

类型：核心修复提案。状态：superseded，用户于2026-10-29决定停止WT框架多线程相关调查及本提案推进，核心保持只读。前缀：NPO。关联模块B的B-04/B-07及[既有实验记录](../evidence/2026-10-29-native-position-lifetime.md)。

当前决定：专注主线开发，继续复用WT原生框架。以下内容保留为历史候选，不作为待审批或当前实施任务；后续遇到实际故障时再结合现场处理。

## 用户可观察结果与必要性

目标是正式策略运行时，原组合浮盈后台任务能够安全读取原仓位对象，进程持续运行并完成原有计算和停止。继续复用WT持仓、盈亏、文件、目标汇总及执行器。

当前固定运行库中已经复现内存访问冲突：主线程增加仓位条目，仓位表扩容搬动条目；后台任务仍持有旧条目中智能指针的引用，随后在取得仓位锁或读取数量时访问无效地址。只创建8个零仓位条目、沿原`WtEngine::on_tick`投递原任务即可触发，无策略算法、交易或行情来源参与。64个独立诊断进程中14个捕获该故障，50个完成18个原任务并正常停止。该频次只描述本次实验。

历史App与独立运行的两处崩溃，均位于同一原函数的对应指令；历史同次寄存器和原生栈仍缺失。因此组件故障已证实，历史两次崩溃的同次根因归属保持待核。固定运行库包含已批准的NCS生命周期差异；固定上游源码已有同样引用方式，纯上游运行复现尚未执行。

本项只补齐容器条目和仓位对象的内存生命期。行情、策略回调和组合汇总继续按原WT方式运行，策略仍能使用更新后的行情。此前[事件串行提案](native-cta-event-serialization-proposal.md)保持撤回，[额外保存接口](native-clean-state-flush-proposal.md)保持未实施。

## 原生能力和实际接缝

对应能力为[WT-S01/S02/S06](../development/wondertrader-capabilities.md)：原CTA/SEL、原组合持仓及汇总。基础引擎拥有`_pos_map`，`wt_hashmap`采用vector承载条目的`ankerl::unordered_dense::map`，条目内保存`shared_ptr<PosInfo>`。后台任务与主线程直接访问同一个容器；原`PosInfo::_mtx`保护取得对象之后的仓位内容。

当前任务先在容器中`find`，再持有`PosInfoPtr&`，随后取得对象锁。查找、智能指针slot和对象锁之间缺少统一容器所有权。仅把引用改为局部`shared_ptr`仍会留下与容器变更并发的查找/复制。创建时先用`operator[]`发布空slot、再reset对象也须在同一所有权范围内收敛。

原Parser、Reader、策略Factory、公开上下文和`poolsize`配置都没有接管该基类后台任务的容器访问。`poolsize=0`仍保留基类worker。现有公开扩展机制没有覆盖这项容器所有权，因而提出核心所有者层的最小候选。

## 拟议统一逻辑

1. 在`WtEngine`集中拥有一把短期容器结构锁及查找/创建/遍历接缝。适配路径中，持锁查找或创建完整非空`PosInfo`，复制其`shared_ptr`值，随后释放结构锁。调用者以局部持有值保证对象生命期。
2. 后台任务沿原`PosInfo::_mtx`更新原数量明细和浮盈。所有创建/查找/size/遍历均经同一结构接缝；遍历仅在结构锁内复制原key与`shared_ptr`的临时持有列表，随后逐对象处理。临时列表不持久化，也不形成新的账户事实或跨字段事务快照。
3. 原`do_set_position`和加载路径经同一创建接缝。运行期仓位内容沿原对象锁；加载仍位于启动静默期，完整初始化后才向可并发访问者发布对象。
4. 原组合浮盈汇总、保存及CTA尾部遍历使用同一遍历接缝。读取原对象字段/明细时按需取得原对象锁；JSON构造后沿原序列化和写入位置保存。结构锁内只处理容器及智能指针所有权。
5. CTA/SEL的目标增量处理经同一接缝取得对象；读取`_volume`后释放对象锁，再调用`append_signal`，避免后者立即进入`do_set_position`时重入同一SpinMutex。原目标公式和执行路由继续使用原实现。
6. 行情处理、策略整轮计算、执行器调用、文件写入、外部回调、线程等待与join全部位于容器结构锁外。每次至多持有一个仓位对象锁，容器锁与对象锁分阶段取得。

配置只在访问接缝选择原生借用方式或受保护的持有方式，原金融计算正文保持单一实现。默认路径继续保留原容器访问语义；适配路径覆盖同一容器的所有访问点。类外自行访问protected容器的第三方派生类须另核，不能从本候选获得资格。

## 文件、配置与消费者

| 文件 | 拟议范围 |
|---|---|
| `src/WtCore/WtEngine.h` | 集中访问接缝、显式模式及结构锁；中文所有权/锁顺序说明 |
| `src/WtCore/WtEngine.cpp` | init读取模式；on_tick任务、原浮盈汇总、原保存/加载及do_set_position统一使用上述接缝 |
| `src/WtCore/WtCtaEngine.cpp` | 尾部遍历及handle_pos_change使用同一基类接缝 |
| `src/WtCore/WtSelEngine.cpp` | handle_pos_change直接访问同一个基类容器，纳入同一接缝 |

拟议键为`env.managed_position_ownership`（产品JSON中为`environment.managed_position_ownership`）。缺省或布尔false选择原生路径；布尔true选择上述持有路径。产品先在原JSON中检查字段存在性及Boolean类型，null、字符串、数字、数组、对象均在创建生产者之前拒绝。原JSON转WTSVariant加载器会省略null，因而该检查必须先于转换；直接传入核心的WTSVariant对其保留字段继续用`type()/has()`校验，无法追溯已被加载器省略的字段。模式在init固定，停止并重启后才能改变。

基类接缝适用于继承此容器的CTA/SEL/HFT；HFT当前仅调用基类on_tick，没有额外直接访问此容器。首个产品资格仍限定既有CTA/pool0；SEL/HFT与pool>0的资格分别通过相应原路径和适配路径回归取得。

自有修改范围为`src/GuanhengExecution/CtaProcess.cpp`中的原JSON前置校验、`CtaExecutionSession.cpp`中的带类型配置校验、相应独占测试、规格/构建候选材料。公开交易接口、策略虚接口、持久文件结构及费用算法保持。新增成员改变C++类布局，全部相关消费者必须同批重编，包含WtCore、Runner/Porter/ExecMon、派生引擎、Guanheng运行库/宿主及直接使用相应类的测试；插件标准C工厂及IParser/ITrader协议仍沿原定义，禁止混用新旧头库。

## 替代方案与代价

| 选择 | 核对结果 |
|---|---|
| 保持现有配置/只关闭策略线程池 | 8条目复现已使用pool0，原worker继续工作 |
| 只检查空指针或捕获异常后重试 | 旧slot也可读出非零非法地址；容器查找本身仍与变更竞争，任务可已部分更新 |
| 单独复制shared_ptr | 查找/复制仍须与容器变更同步；缺少同一结构锁时所有权缺口保留 |
| 预留巨大容量、更换稳定地址容器 | 预留容量只延后搬移；容器变更与查找仍须同步。更换容器还引入更大兼容及布局范围 |
| 启动前伪造仓位文件或使用零成交量tick | 改变输入业务事实或跳过原PnL任务，无法修复现有所有者层 |
| 冻结整轮行情与策略计算 | 扩大业务调度语义，已被用户撤回；本项保持短期内存所有权范围 |

主要代价是容器短期互斥、遍历时复制key/智能指针，以及同批重编和上游维护。列表分配失败沿原失败/停止机制处理，已持有对象通过RAII释放。本项不授予并行目标增量的read-modify-write事务性，也不授予历史来源、真实券商费用、断电恢复等未验能力。
