# 共振1.1.2当前持仓作为初始库存

类型：模块B主线初始库存设计。状态：accepted / implementation-in-progress。适用范围：用户确认的唯一策略resonance-regime-v1@1.1.2及全部当前券商持仓。用户2026-10-30明确决定：当前持仓保留，旧开仓记录、旧交易流水和旧周期状态全部不迁入，新交易记录从新系统启用时开始。规则与六参数、预算来源沿[唯一策略确认](../evidence/2026-10-29-retained-resonance-latest.md)；本文更新初始库存与策略周期的运行起点，不研究WT框架多线程问题。

## 目标与现有能力

启动时以券商当次持仓、可卖、资金和活动委托为准，把现有股票作为初始库存交给唯一策略。历史买卖流水、实际旧开仓日期、旧持有天数、旧参考峰值、旧退出记忆和历史费用全部退出初始输入要求。新系统在明确的启用时点建立新的运行与绩效基准；持仓数量保留，新增交易和费用从此记录。行情K线继续用于信号预热与模型计算。

原生能力沿[WT-S01/S05/S06、WT-T01/T02/T10及WT-B01/B02](../development/wondertrader-capabilities.md)：`CtaStraBaseCtx::load_data`读取策略持仓和明细、开仓时间及冻结量，`WtEngine::load_datas`读取组合仓位，用户变量沿原接口保存。相关源码为`src/WtCore/CtaStraBaseCtx.cpp`、`src/WtCore/WtEngine.cpp`。本候选复用该格式和加载流程；迁移输入转换由自有宿主承担。

原自有入口只支持初始空仓和原干净状态恢复：`CtaExecutionSession::initialize`拒绝fresh模式下已有金融目录，`ConfiguredStrategy.callback`要求fresh原仓位为零，resume_clean要求原关闭证明及数量阶段身份。[P23后继](../evidence/2026-10-29-native-holding-takeover.md)已在自有宿主增加空根租约内的首次prepare，完成合成存量加载、差额执行及同根两代；正式Configured/唯一1.1.2薄桥仍需接入。接管材料不生成虚构的干净关闭证明，不用策略setter模拟历史买入。

账户mapper的具体边界已定位：`src/GuanhengQmtBootstrap/AccountMapping.cpp`将券商总量/可卖量映射到原WTSPosition，平均价缺失时ABI为0，positionCost亦为unknown的中性0，原值及已知性保存在观察投影。新初始库存按有来源的当前标价建立原WT运行基准；这些中性0不作为标价。旧开仓日期和旧成本口径已经退出首次运行的必需材料。

## 初始库存与启用后的周期语义

初始库存采用C的guanheng-strategy-v1==0.1.0a8公开合同：PositionCycle.status=initial_inventory、opened_at为空、baseline_at为本次启用时点，cycle_id和source_sha256固定本批身份。规则年龄从0开始，参考峰值从严格晚于新起点的首个合格分析收盘价开始形成，初始退出记忆为空。B将该显式类型沿Configured和原KV保存，原纯核继续拥有规则数学及信号机。原P23明细时间承载新WT账本载入基准。准备收据绑定基准、事实身份及原输入；初始库存与实际新买入的held/opened_at分别保存。早期a7上以held/opened_at承载管理起点的开发候选已封存，其历史证据及限定身份保留。

启用后的新买入、清仓和部分增减仓继续沿真实当前回报及券商数量推进，保留1.1.2原角色信号机和数量/T+1/费用规则。新运行建立后，正常停止恢复继续沿原WT状态、KV和clean证明，运行起点及已生成状态不因重启再次归零。当前活动委托和未知提交属于未完责任，启动时按原身份核查。

历史K线继续满足模型预热和当前信号计算；首次运行不再请求旧周期的开仓历史补齐，也不导入迁移前成交流水。

初始账本的交易日沿原生会话日历取得。自动准备以`initial-inventory-facts.v2`保存当前观察及有效期，`cta-takeover.v2`在原生加载owner内取得会话日并写入原载入收据；Python装配层保留真实启用时点，券商交易日的known/unknown仍归原观察。旧v1显式日期合同继续严格核同一原生会话日。周末启动不把自然日期推定成原生会话日；有效标价和当前事实准入继续按原合同校验，真实休市来源另验。

## 首次接管主流程

自动启动由B执行owner完成：复用原ManagedAccountScan的四查询及原行情SDK标价，自动调用已实现的准备API，生成原策略/P23配置后启动原执行owner。运行配置提供来源连接、唯一策略模板和工作目录，操作员不手写库存事实JSON，启动不依赖观衡。首次生成的基准与原输入作为本系统状态保存，后继resume_clean使用同一份输入并由原生重新核当次账户事实。当前准备入口/库存模型已封存，自动装配主路径单列实施及验收。

### 已取消的旧开仓历史工作

此前[旧开仓历史边界核证](../evidence/2026-10-30-holding-history-boundary.md)保留其实际观察。用户本次决定取消旧周期迁入，`build/ms-takeover-opening-source-001/C-INTERFACE-REQUEST-001.json`的逐证券旧周期补齐请求已由新初始库存要求取代，不再作为本模块交付缺口或继续开发事项。

用户决定与取消收据位于`build/ms-initial-inventory-baseline-001/DECISION-001.json`，其中原“等待C新增合同”的实施假设已由上述公开入口核实更新。实现与限定两代证据见[初始库存入口](../evidence/2026-10-30-initial-inventory-baseline.md)。原封存证据、现存运行目录和真实持仓保持原件。

1. 消费唯一1.1.2及原参数材料，复用C现有公开纯核/状态合同；保留原交易关闭状态，生成候选期间SDK提交为0。
2. 沿原查询获取当次数量、可卖、资金及未决委托，取得本次有效标价。输出可核对的初始库存表：券商事实、新运行起点、标价、原生初始持仓和预算；旧开仓时间和旧流水不在输入清单内。
3. 在全新隔离目录形成原WT策略/组合初始文件及新运行基准元数据。持仓数量与券商一致，冻结量按当次总量减可卖确定；历史收益/费用为0，当前库存按本次有效标价计入原生初始状态。原WT继续拥有后续账本和绩效，不另建金融账。
4. 自有宿主在原输出根租约内消费一次初始库存材料，再调用原加载流程；初始化回读核对数量、可卖、新运行基准及预算，开始业务计算后才允许产生当前目标。首次初始化与resume_clean分别校验，后续正常停止恢复仍走现有原关闭证明。
5. 先在隔离SDK替身完成主链：初始持仓保持不产生重复买入；真实规则给出下一目标后原执行器仅提交差额；停机重启后原数量阶段和策略记忆接续。完整候选交主会话审核，真实切换沿既有明确授权。

## 验收与交付边界

验收包含：唯一版本/六参数一致；完全不提供旧开仓日期和旧流水也能加载非空初始库存；持仓/可卖原值保持及零重复买入；新运行收益/费用和初始周期状态从0开始；新基准在日内/收盘后的首分析价差异；因子修订和模型预热；缺当前标价/当前事实明确报告；库存市值与预算不重复计量；未决委托责任保持；原同根停止恢复不再次归零；普通独立安装及页面。

当前自有initial_inventory准备入口已复用原Configured/P23协议及C原公开核，源与普通安装均通过原旧历史失败输入的新基准计算、数量/可卖、清旧退出和公开CLI验证；限定原生两代模型已通过。实际事实生产者自动装配、统一候选、完整边界/审查及当前真实只读来源继续按[证据](../evidence/2026-10-30-initial-inventory-baseline.md)登记。旧实际开仓时间退出启动缺项，真实账户及生产配置保持原状，真实下撤单和生产切换另行授权。
