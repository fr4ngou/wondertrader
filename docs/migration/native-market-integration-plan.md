# 原生行情接入方案收敛

类型：方案。状态：proposed；m1历史查询已按独立[NHQ规格](../specs/native-history-query.md)实施并取得[限定开发证据](../evidence/2026-10-22-native-history-query.md)，整体实时/周期/业务与生产接线继续验收。本文承接[业务适配地图](business-adaptation-map.md)，替换其前序“沿已有自有链直接接入”的假设。用户功能、QMT主来源、HTTP优先、通达信可选及观衡独立发布继续适用。

## 目标与依据

策略按需读取历史1分钟、补齐真实缺失、获取实时快照、接收闭合分钟并正确恢复；图表、研究和回测消费同一原生行情。原生查询、存储、重采样、分钟调度、策略上下文和执行通道全部复用WT。原QMT的重复行情库、周期引擎、策略调度与撮合退出目标架构。

固定上游 `08b230dd05facf6d650d949bfe51054115a2ecb1`。能力依据WT-D01–D11、WT-S01/S05/S06、WT-B01，详见[能力目录](../development/wondertrader-capabilities.md)。行为证据见[Servo实验](../evidence/2026-10-21-native-servo-behavior.md)和[公开Reader所有权实验](../evidence/2026-10-21-native-reader-ownership.md)。源码、运行资格及本项目接入完成状态分别登记。

## 查询宿主选择

采用公开IRdmDtReader组合的理由是所有权明确：宿主创建Reader，以同步借用切片读取，复制结果并释放切片，最后通过原delete工厂销毁。原生DataFactory负责派生周期；与Reader代际一致地重建派生结果。该组合复用WT实现，无需为历史查询新增第二行情数据库或修改Servo释放接口。

Servo继续作为官方能力参考及可选运行入口。固定上游版本的空历史count虚报、已有派生缓存不随clear_cache刷新、C ABI无完整关闭入口，都有精确依据。底层空计数已按用户批准完成[CORE-008限定修正](../evidence/2026-10-21-native-reader-empty-count.md)，带中文原因注释；接入继续校验实际数据块、条数和范围，异常不冒充空成功。其他核心变动按单独必要性和批准处理。

线程所有权：请求接纳、Reader调用、修订切换及销毁由明确所有者串行协调，用户HTTP线程不直接并发触碰Reader。默认Reader仍有后台检查线程；外部串行不等于内部线程安全。历史-only实验不授予DMB实时混读资格。停止顺序是停止新请求→结束在途查询→释放借用切片→原delete/join→销毁基础资料和sink；当前原检查间隔约5秒，关闭预算与页面请求预算分别设置。

此前历史实验确认clearCache后基础历史可重新读取；正式适配同时考虑原检查线程遍历RT map，采用Reader代际替换与有界后台释放，详见[历史查询规格](../specs/native-history-query.md)。长期派生缓存的键必须包含实际输入代际，或在同一所有者边界重建。完整多文件发布、映射扩容、在途旧切片及DMB并发仍需分别验证；历史实验不提供跨进程事务保证。

来源后续核准见[QMT分钟契约与现场观察](../evidence/2026-10-21-qmt-minute-source-contract.md)：公开1m可读已有缓存，主动下载Adapter当前限1d；0条/120条与快照并存，不以接口成功证明完整。新适配须核Bridge实际1m预算路径及同request_id结果恢复。

后继[分钟量额复核](../evidence/2026-10-22-qmt-cache-volume-precision.md)以直接Agent HTTP正文重现旧428行数值；100倍量尺度仍有129根正量偏离及3根零量非零额。历史存储/读取按原字段及既有profile的开发资格继续验证；精确成交股数、量额均价和依赖这些事实的策略资格，等待供应商分钟契约或原生高精度证据。当前不改变原样本/DSB，不按金额反算补量。

## 策略与真实分钟的两条原生接缝

完整tick来源可以使用原Writer生成DMB，再按写后广播拓扑驱动策略Parser/Ticker和原Reader。稀疏HTTP快照只代表其采样事实，不能保证聚合后的分钟高低价与真实源一致。

若QMT提供已形成的权威分钟bar，来源准备与原生历史发布在策略回调之外完成。优先核实IDataReader插件接缝，在原onMinuteEnd通知和DtMgr聚合/调度下交接已准备数据。IDataWriter没有通用writeBar，IHisDataLoader仅为历史加载入口；不为适配默认Writer伪造tick，不另建分钟调度器。

现有ReaderGuanheng是可替换开发候选。其readKlineSlice/onMinuteEnd会调用provider.read，其中HTTP provider可沿策略/ticker线程执行请求。最终接线需要核预算、来源延迟及预备数据交接；不能因旧候选通过功能测试而默认保留该同步网络链。

策略m1、times=1、force_cache=false可沿公开Reader接缝读取；上层WtDtMgr的force_cache和派生周期缓存是独立边界。历史修订需要同时覆盖实际运行的每一层缓存。当前历史查询宿主实验不能替代策略多周期同实例修订资格；若公开生命周期无法满足，再提出精确核心修改。

## 分钟与恢复契约

原生Reader按闭合时间扫描各证券未读DMB bar，收集后统一通知，Ticker再调策略；线程池on_bar和on_schedule各有等待屏障。它没有自动提供全市场所有证券同一分钟到齐的强一致快照。组合策略按自身输入要求检查证券、时间和覆盖，缺少输入时采用明确业务规则。

本地定时器可闭合当前已观察分钟；没有来源数据时不会凭时钟制造整段行情。补回多条bar与策略计算次数分别登记。研究需要逐分钟重算时使用原回测/回放路径；实盘恢复避免把旧分钟误当当前交易信号。原生游标和业务持久确认按各自事实处理。

## 实施与验收顺序

1. 补齐公开Reader/Factory的异常清理、全字段重采样、真实时段与复权实验；将已经取得的限定事实留在原生能力文档。
2. 核QMT真实分钟及采样快照契约，选择上述原生接缝；先冻结公开接口、线程/停止与代际语义，再修改自有适配。
3. 单一原生行情查询→原MarketData/Console图表与研究；真实、空、异常、修订、预算和关闭均验，退出PG分钟副本。
4. 原CTA策略读取、预热、多证券闭合/午休/断流/补发与pool=0/>0，分别记录数据更新、bar通知和计算次数；验证同实例补齐与修订。
5. 再推进策略状态、交易适配及独立业务发布；原账户/命令/幂等事实按既有授权和切换方案交接。真实交易和生产发布分别取得具体授权。

研究结果不足的部分继续调查；现阶段没有新增必须由用户决定的核心修改。旧候选及数据保留，退出和切换在取得相应验收后执行。m1查询沿已收敛NHQ接口开发；周期、策略实时及业务默认接线在各自契约与资格核实后推进。
