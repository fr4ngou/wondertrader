## 合入与发行

### 独立发行的最终组合

WT运行侧和观衡分别交付可安装制品及各自依赖锁。当前C的App61使用只读 `guanheng-wt-runtime==0.1.0a11+read4`；SRI004运行侧使用 `0.1.0a12+initialinventoryauto.2`，B最终执行候选继续开发。两个发行使用各自环境，保留各自已验模块和版本；只读读取库的分发名不赋予观衡交易进程管理职责。

最终集成先接收B的WT/Host运行包与C的独立观衡包，各自离线安装到新目录，再用显式只读连接配置完成组合验收。已有SRI v2支持不携带App/SPA的WT发行，C继续使用其普通离线安装入口。整套交付记录同时绑定两包身份、来源配置和兼容结果；运行时各自启动、停止、升级和回退，观衡停止期间WT继续管理Host及策略。后续若制作便捷组合包，继续保留上述角色环境和原字节。

源码构建安装器当前按单个输入树约束同名本地分发来源；它适用于同源角色构建。独立发行组合直接消费两方已有制品，保留各自来源收据及依赖，不为凑单一源码构建而替换已验模块。验收从同一对固定制品进入：WT启动/账户发布→观衡读取→观衡停止而WT继续→WT正常停止→同根恢复→观衡重连读取。业务结果和恢复全部通过后，才授相应整套开发资格；真实来源及生产资格另列。

当前三个会话共用E:/workspace/wondertrader的codex/qmt-migration-plan工作树，存在大量尚未提交的新增代码及冻结框架差异。开发者只修改独占文件并交付，不切换共享分支，不批量暂存或提交整个目录。模块不能因留在同一目录就视为已合入。

1. 开始模块先保存基础身份与精确文件归属。交付时提供：最终规格/验收ID、全部变更文件与SHA256（含新增文件）、当前公共依赖版本、具体运行命令/退出与清理结果、发行制品及哈希、独立审查与剩余缺口。资料放各自模块证据，运行原件放各自独占build根。
2. A核对A/B/C文件交集、最新内容及接口版本。公共文件按最新基线合并明确片段；存在他方新改动时保留并重新核调用链。未批准框架差异持续冻结，不混入构建或提交。
3. 按来源清单组成固定候选：锁定上游+已批准覆盖+明确自有模块；必要时在独立集成目录装配，避免当前脏树成为隐式构建输入。复用输入未变的有效验证，组合变更重跑M1及受影响异常/恢复链。
4. A完成集成审查后，使用精确文件清单提交，记录实际commit和制品对应。模块提交/合入、候选打包、生产发布分别登记；正式发行按[发布规范](../runbooks/release.md)从干净集成候选/标签构建。发布和真实交易取得相应授权后进行。
