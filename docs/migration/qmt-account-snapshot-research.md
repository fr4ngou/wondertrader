## WT原生职责及适配边界

| 入口 | 已核实行为 | 接入必须处理的影响 |
|---|---|---|
| TraderAdapter.onRspPosition | 绝对更新返回证券；空数组与缺行保留旧证券 | 整账户缓存替换需要明确空值及缺行语义 |
| onPushTrade | 加减持仓、更新统计和未成交量，并通知策略和日志 | 持仓写入与其余真实成交副作用分别处理 |
| onPushOrder | 冻结／解冻可卖量，更新订单和未成交量 | 采用查询可卖量时须处理重复冻结／解冻 |
| onRspTrades | 累加历史成交统计 | 与live同成交的统计幂等及首次通知分别验证 |
| 初始化状态机 | 持仓查询后依次查订单、成交、资金；就绪后普通持仓刷新不重跑四查询 | 合并持仓刷新复用原入口，保持首次／重连职责清晰 |
| StockMinImpact | 分别读取持仓、可卖与未成交量，完成标记影响重算 | 旧持仓、新订单和后续刷新可能影响目标执行 |

TraderAdapter私有持仓及非虚读取限制了普通插件直接替换归约规则。原SPI、执行单元工厂、Standard的单owner／有界队列仍有复用空间。原生能力和约束见[能力目录](../development/wondertrader-capabilities.md)及[复用规则](../development/wondertrader-reuse.md)。

## 来源范围与缓存新鲜度

[官方交易查询说明](https://dict.thinktrader.net/innerApi/trading_function.html)提供按账户／类型的三参数列表查询；第四参数仅筛选委托和成交的策略子集。本仓SHM account_query固定account范围并使用三参数调用，对原列表全部遍历，超限、长度变化、来源结构或标量非法、SDK返回值／行对象为None或异常整批失败；可选字段的缺失／None沿原契约保留，金融映射另行校验；已有complete/truncated字段描述这次列表转换，coverage=sdk_returned_list。没有额外full字段本身不能否定其账户查询范围。

[官方完整示例7](https://dict.thinktrader.net/innerApi/code_examples.html)在账号查询非空后读取持仓列表，并把目标中缺失的证券作为0处理。这为账户缓存列表的使用提供依据；当前国信未登录、断线或SDK静默失败时空列表的具体行为仍需核实，完整性与登录／错误语义分别登记。

[官方FAQ](https://knowledge.thinktrader.net/docs/python/question_answer.html)明确账户查询和四类交易回调读取客户端缓存，后台接收柜台更新；查询可能滞后。文档给出的刷新时长不构成本机最大延迟承诺。返回列表完整、调用完成时间、运输ACK和事件序号均不自动证明持仓已包含某笔最新成交。账户观察修复与自动执行的新鲜度保证分别验收。

## 最小提案的收敛方向

初稿同时包含统一订单条目、资金复合视图、C ABI注册、新通知队列和执行器改造。独立最小范围审查（外部历史/待归仓路径：`../../build/qmt-r8-framework-minimal-review-001/REPORT.md`）发现三项必要性／范围问题；这些内容按各自反例分别论证。持仓观察修复不增加第二账本、对账服务或人工实盘资格，也不要求所有来源提供新造的成交包含标记。
