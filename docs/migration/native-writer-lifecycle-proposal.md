## 用大白话说明

这是让行情采集程序能够正常停止和重启的修正。原版程序处理完行情、返回“关闭完成”后，还有后台线程继续访问已释放的内存，随后程序崩溃；这一步已真实复现。另有写行情与后台清理共用内存的同步缺口，源码已确认，独立故障尚未复现。

申请只改两件事：停止时先等后台线程退出，再释放资源；运行时协调写入与清理对同一块内存的使用。分钟线计算和文件格式沿用原实现。默认使用原版DLL，显式配置才使用适配版。本方案已获明确批准，范围为开发和隔离验收；生产切换另行处理。

## 要解决什么

原版 Writer 已真实重现关闭后崩溃：6982 条行情走完处理，约 45.5 秒时关闭函数返回；随后后台检查线程访问已经释放的 Writer 内存，发生 `0xC0000005`。原 DLL 堆栈与指定函数机器码核对已将故障定位到 `check_loop`。这会影响采集停止、重启和正常资源回收。

原收盘接口仍用于生成历史文件，但它没有提供“全部线程已经退出”的确认。两证券实验中，原生归档已生成 2 个 DSB 和 marker，约 0.25 秒关闭返回时，检查线程的真实 Windows 句柄仍显示运行中，约 10.1 秒才退出。等待 marker 或固定睡眠都不能作为安全关闭依据。

官方另一模块 `WtDataStorageAD` 已核实：它写 LMDB 和专用实时缓存，收盘接口继承空实现，没有标准 DSB/marker 输出，既有 DSB 历史与 Reader 无法直接接续；其源码另有未初始化的异步选择、数据库引用被移空及析构/停止缺口。因此它当前无法通过更换 `writer.module` 完整替代本次采集链路。

## 申请的两个修改切片

| 切片 | 修改及必要性 | 证据强度 |
|---|---|---|
| **L：正常关闭与具体析构** | Writer 停止新工作准入，排空已受理工作，唤醒并等待所有实际创建的线程退出，最后释放映射与对象；工厂按具体 Writer 类型析构。同步接收、异步工作、收盘线程和初始化失败共用同一生命周期逻辑。 | **原 DLL 已重现关闭后崩溃**；源码确认漏等检查线程、普通停止标志及基类删除缺口。 |
| **M：映射使用权与并发** | 短锁保护映射表的查找/新增/遍历；复用原块锁，从建立映射一直保护到最后使用。检查线程逐块判断过期；归档与行情按受理顺序处理；外部回调使用自有快照并离开物理锁执行。 | **源码确认存在未同步访问**：接收线程插入映射表，检查线程同时遍历和关闭映射。该运行期竞争尚无独立故障复现，不能把 L 的崩溃证据算成 M 的实测。 |

**当前同步、单接收线程的全天采集需要 L 和 M。** 原 Writer 仍会自行启动后台检查线程，每 10 秒扫描一次；因此当前架构实际存在内部并发。仅完成 L 能补齐关闭链路，全天运行的映射竞争仍保留，不能据此授予完整运行资格。

## 怎么启用，修改到哪里

- 缺省及显式 `writer.module=WtDataStorage` 继续加载保留的原 DLL；只有显式 `writer.module=WtDataStorageLifecycle` 加载适配库。非法值在启动准入时失败；模式在初始化时固定，通过正常停止、重启切换。
- 核心源码范围限定为 **`WtDataWriter.h`、`WtDataWriter.cpp`**，另含自有集中构建、薄 Session 接线、测试和文档。适配库由同一受控源码集中构建，沿用原聚合算法；原 `IDataWriter` 公共虚函数布局和工厂签名保持。
- 固定基线为上游 `08b230dd05facf6d650d949bfe51054115a2ecb1`。本次审批范围排除旧 CORE-005 冻结差异、分钟量额算法、DMB/DSB 格式、600 秒过期阈值、常态扫描周期和测试预算调整。源码中文注释须解释状态所有者、锁范围、回调限制及关闭顺序。

关闭主路径为：**停止接收并等待接收线程退出 → 提交原生收盘任务 → Writer 排空并等待内部线程退出 → 原 Helper 回读本次 DSB**。成功关闭证明资源已安全回收；数据是否完整另按回读结果确认。磁盘、dumper 和原清理重试会影响耗时，本方案没有固定秒数的关闭上界。回调可以查询或提交工作；它同步等待自身所在工作线程的后续任务或关闭，会形成循环依赖，须在接口契约中明确约束。

## 怎么验收与回退

先完成合成数据的完整主路径，再核对原 6982 条关闭条件、两证券归档、检查线程扫描/过期与新增映射重叠、异步积压、回调查询、初始化失败、重复释放和存储异常。关闭返回时检查所有实际线程句柄已经退出，并核对数据、映射和句柄回收。缺省、显式原生、显式适配、非法配置分别验收，原路径绑定原 DLL 身份。

随后在已授权范围内做真实来源回归，覆盖行情进入、分钟量额、收盘文件、既有历史 Reader 接续及正常停止；源码、DLL、配置和结果共同存证，再按最终差异进行独立审查。合成测试或构建成功只证明对应层级。

回退先让适配实例正常停止并确认线程退出，保留数据和未决事实，再选择原 DLL 重启。原数据格式保持兼容；回退版本同时恢复其已知关闭缺陷，需要在操作记录中说明。开发批准与真实运行、生产切换授权分别管理。
