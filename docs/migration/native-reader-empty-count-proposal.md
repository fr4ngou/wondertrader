# 原生 Reader 空数据计数修正提案

类型：核心变更提案。状态：用户已批准，仅此分支修正，并要求中文代码注释；开发隔离验证通过，生产未发布；结果见[验证记录](../evidence/2026-10-21-native-reader-empty-count.md)。范围仅 `src/WtDataStorage/WtRdmDtReader.cpp` 的 `indexBarFromCacheByCount` 空数组返回分支。

## 大白话说明

向原生接口请求“最多100根分钟线”，某只证券实际一根也没有时，固定版本会报告100根，却不给任何数据。换用公开Reader工厂后问题仍存在。现在只能检测为接口结果异常；若要让原生接口正确表达正常空数据，需要修正原函数的输出数量。

原样复现和独立源码归因见[Servo实验](../evidence/2026-10-21-native-servo-behavior.md)及[公开Reader实验](../evidence/2026-10-21-native-reader-ownership.md)。有数据但少于请求数时，原有最多N根逻辑已正常。真实QMT同日查询也出现过某证券0根，空数据是实际接入必须支持的状态；该真实空结果并不单独证明停牌或无成交。

## 根因与拟修改内容

固定上游：`08b230dd05facf6d650d949bfe51054115a2ecb1`。函数的count为引用输出；当前空数组分支返回NULL时保留了调用方传入数量。上层据此创建“数量100、数据块0”的切片。

拟议差异：

```diff
 if (barsList._bars.empty())
+{
+    count = 0;
     return NULL;
+}
```

新增一条赋值和分支括号，保持函数签名、正常非空索引算法和文件格式。该函数用于随机Reader查询；不更改策略Ticker、Writer、交易、账户、线程或锁，也不动其余冻结差异。

## 必要性与替代办法

- 建议：在数量的原所有者处归零，所有使用该公开Reader的宿主得到一致结果。
- 暂时保持冻结：适配层核对size和实际block，异常明确报错；缺点是正常空历史仍无法通过原count接口表示。
- 改用range后截取尾部：已验部分范围空路径，但还需维护额外尾部选择和范围边界；不能据此证明原count语义已经正确。优先复用正确的原count实现。

这项修正与Servo派生缓存及关闭接线分开；后两项已有公开组合可继续评估，本提案不扩大修改范围。

## 风险、验证与回滚

风险是空历史但存在实时记录的混合路径：剩余历史数量归零后，应只返回真实实时条数。因此验收包含空历史/空实时、空历史/部分实时、非空历史不足N/等于N/超过N、截止时间与正常范围/日期回归，核对声明数量和每个block累计。

按批准范围先保留原样红例，再在隔离原样快照应用同一最小差异验证，独立审查后才修改正式文件并跑受影响原生回归。追加数据与缓存刷新、线程退出的已有范围按输入匹配复用；不以此授予实时并发、热卸载或生产资格。

回滚仅撤销本分支新增赋值和括号，保留适配层一致性校验并将旧异常显式返回。无数据格式、配置、账户或持久事实变更。任何扩大修改范围重新说明并取得批准。
